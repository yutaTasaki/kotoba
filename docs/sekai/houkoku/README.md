# 実行結果の報告書

**指示書を1本実行したら、ここに1本残す。** チャットの返事だけで終わらせない。

## 名前の付け方

`YYYY-MM-DD_<指示書の名前から _shiji を取ったもの>.md`

例：`chuu_200ji_shiji.md` を実行した → `2026-09-12_chuu_200ji.md`

指示書の名前をそのまま使うので、「あの指示、どうなった？」から一発で引ける。

## 中身の順番（この順で書く）

1. **何をしたか** — 1〜3行。使う側から見た言い方で
2. **結果** — どうなったか。数字で（件数・字数・金額）
3. **意味** — なぜそれが効くのか。何が原因だったのか
4. **残り** — まだ確かめていないこと、次にやること
5. （必要なら）**測った値** — 詳しい数字の表

**書かないこと**：どの関数を直したか、ファイルの何行目か、変数名の列挙。
実装の詳細が要るときは仕様書（`../spec/`）に置き、報告書からは名前で参照する。

## 調査との違い

測った事実そのもの（どのサイトが開けるか、いくらかかるか）は `../chousa/` に置く。
報告書は「その回に何をして何が変わったか」、調査は「何度も引きたい事実」。
