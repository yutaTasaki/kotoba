## 見込み

- 7日間の実測では、kotoba-data の全コミットの61%（3,181回）、散歩の97%がこの「変わらない書き込み」だった。両端末が v20.41 になれば、この分が無くなる見込み

## 気づいたこと（直していない。前からある）

**散歩のデータは、2台で同じ日に別々の値を入れると、片方の値が GitHub 上で一時的に消えることがある。**

- 散歩の合わせ方は「歩いた日数が多い方を採る。同じなら自分の分を書く」（元の walk10000 アプリと同じ決まり）。歩いた日数が同じ2台では、あとから同期した端末の分で上書きされる
- 偽の GitHub で再現した：端末Aで「今朝の体調」を押す → 端末B（押していない）が同期 → GitHub から体調が消えた → 端末Aが次に同期すると戻った
- **本物の散歩の履歴（中身が変わった69版）を読んだ。消えたまま残った値は無かった。** 9/12 に今朝の体調が約6秒だけ消えて、すぐ戻った跡が1つあった
- 消えたままになるのは、値を入れた端末が戻す前に、もう1台の歩いた日数が増えて、そちらを取り込んだ時。今まで起きていないのは、散歩の記録を付けるのが1台だけだからだと考えられる（**確かめてはいない**）
- v20.41 でこの動きは変わっていない（前も後も、違う中身なら書く）
- 直すなら、日ごと・欄ごとに新しい方を採る合わせ方にする。ただし元の walk10000 アプリが同じ置き場所を今も使っているなら、決まりを変えると食い違う。**直すかどうか、walk10000 アプリをまだ使っているか、を教えてください**
