## 結果（先に）

1. **回答書の案2に賛成。そのまま仕様にした。**
2. **「同期でぶつかったら出す」に賛成。** 反対する理由（遅くなる・毎回出て邪魔）は、測ったら当たらなかった
   - 見分け方：同じ番号が両方にあって、**作った日時が違う**もの。同じものを2台で直しただけなら作った日時は同じ
   - 今の kotoba-data で、作った日時が無いものは **0件**（言葉165・日誌38・札120・概念44・用語118・主体90・聞いたこと2）
   - 重さ：言葉165件を合わせる1回が 0.164ミリ秒 → 0.174ミリ秒
   - 出るのは、ぶつかりがあって、まだ設定の記録を開いていないときだけ
3. **消えた方の中身は控えられる。** 合わせる瞬間には両方が手元にあるので、そのまま写せる。控えるのは**その端末の中だけ**（最大50件）。kotoba-data に送らない理由は仕様書 2.4
4. **ぶつかったときに自動で両方残す（消える方に新しい番号を付ける）のは反対。** その番号を指している日誌・概念・予告・続きの札が、どちらの中身を指していたのか分からず、正しく付け替えられないため
5. **回答書に無い小さい足しが3つ**（どれも賛成なのでそのまま仕様に入れた）
   - 空きを決めるときに、消した印の番号も使用中とみなす（今は消した番号を使い直している）
   - 見張りに予告も入れる（v20.36 までの端末が残っている間は起こり得る）
   - 見張るのは「種類_8桁の日付_数」の形の番号だけ。主体の最初から入っている22件（`ac_boj` など）は端末ごとに入れた日時が違うので、見張ると誤って出る

## 追加で考えてほしいこと（ぶつかったら出す）への答え

**賛成。入れる。**

| 聞かれたこと | 答え |
|---|---|
| 片方を消す前に画面に1行出せるか | 出せる。同期の1行に「※ 同じ番号が2つありました。N件（新しい方を残しました）」。設定の記録を開くまで出し続け、開いたら消す |
| 出す場所 | 同期の1行（画面の一番上）と、設定の「切り詰めた文」の下に「同じ番号でぶつかったもの N件」。取り込みの結果の1行には出さない（ぶつかるのは取り込みのときではなく、同期のとき） |
| 消した方の中身を控えに残せるか | 残せる。その端末に最大50件。設定の記録で、残した方・消えた方の冒頭と作った日時を出し、［消えた方をコピー］で本文をクリップボードに入れる。戻すのは人の手 |
| 手間・同期が遅くなるか | 合わせる所7か所に同じ呼び出しを1行ずつ。比べの重さは 0.01ミリ秒ほど（実測） |
| 毎回出て邪魔にならないか | ぶつかりが無ければ何も出ない。同じぶつかりは1回だけ数える |

**入れて失うもの：**
- 控えはその端末にしか無い（別の端末からは見られない。その端末のデータを消すと控えも消える）
- 戻すのは手作業
- 見張りは v20.38 の端末でだけ動く。古い端末で合わさったぶつかりは出ない
- 端末の保存場所を、控え50件ぶん（多くて約12万5千字）使う

## やった場合に失うもの（番号の作り直し）

- 生成とのやり取りで番号が長くなる：全部が新しい形になったときに、読む回 +372字・朝の言葉と関連づけのキャッシュする部分 +495字。今ある番号は変えないので、しばらくはもっと小さい
- 同じ日の中で、番号から作った順が分からなくなる（今、番号で順を見ている所は無い）
- 番号が長くなって生成が写し間違える危険（**測れません**）

## 仕様書で決めた確かめ方（回答書の分を含む）

- 6種類それぞれ、同じ状態の2台で同じ日に1件ずつ作って合わせ、12件とも残ること（v20.37 では6件に減ることも示す）
- v20.37 のコードで、新しい番号を指す札の「お金の流れの続き」が消えないこと、新しい番号が正しい月のファイルに入ること
- 見張りが、ぶつかりで出る・ふつうの直しで出ない・固定の番号で出ない・二重に数えない・51件目で古い控えを消したことを出す
- 決まった8項目と、言葉の保存・相談・一括入力・取り込む回・聞く回・設定の記録を本当に押す・打つ
