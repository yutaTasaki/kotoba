## 先に結論

1. **重複はある。** 朝の取り込みで作られた札69枚（最初の1回と初期投入・問いを除く）のうち、**同じ出来事の言い換えが17枚（25%）**、同じ発表の別の数字まで入れると **21枚（30%）**。続報まで入れると28枚（41%）
2. **いちばん大きい原因は「チャットに前の札が見えていない」。** 重複21枚のうち15枚は、先の札がプロンプトに出ていなかった（flow が無い7・日付が30日より前4・30件の枠から外れた4）。ただし**見えていたのに重複した札も6枚ある**ので、渡すだけで止まるとは言い切れない
3. **重複21枚のうち15枚は、先の札を作ってから25時間以内**にもう一度作られていた。9/12 は朝の取り込みを **9回**（0:40〜16:02）流していて、同じ日のニュースを毎回拾った
4. **「つながる札 ほか42件」の重さの主な原因は重複ではない。** 重複を全部畳んでも、つながる札は **18%しか減らない**（2,754→2,250）。重いのは「チョークポイント」（30枚）「余剰生産能力」（20枚）のような広い概念で、これは別の相談
5. 見立ての2（四半期のソース）は**半分当たり**。朝のボタンは期限の来たものだけ入れるが、取り込む画面の［プロンプトをコピー］は7件全部を入れる。履歴を見ると 9/12 と 9/14 は7件全部が入っていた。**「どの回を読んだか」はアプリのどこにも無い**
6. 見立ての3（同じ主体に寄る）は**重複の原因としては弱い**。米財務省は朝の札79枚のうち11枚で一番多いが、重複の組に入っているのは2組だけ

**推奨：入口（A）を先に。1つだけなら A-3（すでにある札の一覧を渡す＋「同じだったので札にしなかった」を JSON で報告させる）。** 束ねる（B）は、札を消さず・書き換えず、「同じ出来事の組」を別ファイルに記録して表示で畳む形（案2に表示を足す）を勧める。

### A-3 既存の札を渡す案

**賛成。1つだけやるならこれ**（A-6）。ただし「fact だけ」でなく、**札の番号（id）をつけて、「同じだったので札にしなかった」を JSON で返させる**ことを足したい（黙って捨てさせないため）。

実データでの字数（今の20,284字に対して）：

| 渡し方 | 件数 | 増える字数 |
|---|---|---|
| 全132枚、番号・日付・fact | 132 | +5,721（+28%） |
| 同じく、番号なし | 132 | +3,967 |
| **「最近のお金の動き」に出ている30件を除く** | 102 | **+4,453（+22%）** |
| 出来事の日付が14日以内（端末で試した分） | 77 | +3,354 |

1件あたり平均43字（fact だけなら24字）。

**14日で足りるか**

- 札が全部 9/11〜9/14 の4日間で作られているので、**14日と30日の違いはまだ測れません**
- 測れたこと：重複21枚は、**先の札との間がすべて74時間（3.1日）以内**。25時間以内が15枚
- **「出来事の日付」で切るのは勧めない。** 出来事の日付が14日以内だと、先の札が入るのは21枚中14枚だけ（トヨタ 8/4・TSMC 7/16・資金循環 6/25・EU 8/24 が外れる。古い決算を何度も読み直して重複しているため）
- **「取り込んだ日」で切れば21枚すべてが入る**
- 「直近に作った順に40件」だと8枚、60件でも11枚しか入らない（間に初期投入の45枚が挟まるため）

**推奨：取り込んだ日が14日以内の札（初期投入の札も含む）、上限100件、新しい順。** 100件を超えて切ったら、コピーしたときに「外れた札 N件」と出す。
- 理由：9/11〜9/14 の朝の札は1日約22枚。14日分をそのまま渡すと約300件・約13,000字になり、規則を押しのける。100件（約4,400字）なら、測れた最大の間（3.1日）の分は入る
- 失うもの：プロンプトが約4,400字（約22%）長くなる。100件より前の札は見えない。**見えていても重複した6枚の分は、これだけでは止まらないかもしれない**

JSON に足す形（案）：

```
"same":[{"id":"w_20260910_1","why":"同じ ECB の利上げ。別の媒体"}]
```

- 取り込みの結果に「同じ出来事として札にしなかった 3件」を出す。番号が一覧に無ければ「番号が無い」と出す
- 札は作らないので、何も書き換えない

世界の索引の変更の履歴（9/10〜9/14 の192回）で、この日付が動いた時を見た：

札の側にも「どのソースの何回目か」は無い（url で引き当てようとしたが、トヨタの5枚は url が日経・トヨタ・トヨタイムズ・stockanalysis とばらばらで、ソースの url と合うのは1枚だけ）。

**持つために足すもの（案）**

- 返す JSON の checked に「回」を書かせる：`{"source":"トヨタ","opened":true,"picked":0,"edition":"2026年4〜6月期","editionDate":"2026-08-04","note":"同じ回"}`
- アプリはソースごとに「最後に読んだ回・その発表日」を控える。**置き場所は世界の索引ではなく別ファイル**（古い版の端末が世界の索引の知らない欄を落とすため。9/14 に予告の日時で起きた）
- プロンプトの7件の行に「前に読んだ回：2026年4〜6月期（8/4発表）。これより新しい回が無ければ札にせず picked 0、note に『同じ回』」と書く
- `picked:0` `note:"同じ回"` の形：**賛成**（今の checked の形のまま使え、結果の1行にそのまま出る）

**毎日開かせる必要があるか**

- **無い。** 四半期・年1回のものは、次の回が出るはずの頃（前の回の発表日＋周期の少し前）から開けばよい
- 今の朝のボタンは「最後に取り込んだ日＋90日」で数えているので、取り込んだ日が発表日より遅いと次の回を数週間取りこぼす（例：8/4 発表の回を 9/12 に読むと、次に入るのは 12/11。11月初めの次の回に1か月以上気づかない）。**「前の回の発表日」から数え直すのを勧める**
- 取り込む画面の［プロンプトをコピー］も、期限前のソースは「前の回だけ確かめる短い1行」にすれば、4,058字の多くが減る（何字減るかは、作ってから測る）
- 効きの見込み：重複21枚のうち、この回の印で止まるのは **7枚（33%）**（トヨタ3・TSMC 1・資金循環と家計2・H.4.1 1）
- 失うもの：チャットが「回」を書き間違えると、新しい回を「同じ回」として読み飛ばす（note に出るので気づける）。控える欄と別ファイルが1つ増える

### A-5 続報の受け皿

- 「続きだから新しい札にしない」と書くと、**本当の続報も捨てる恐れがある。** フーシ派の6枚は、3枚が同じ制圧の言い換え、残りは翌日のペリム島到達や「イランが追加支援を約束」という新しい事実を持っていた
- **`updates`（既存の札に追記する欄）には反対。**
  - 既存の札を書き換えることになる（追記のみの原則に反する。読んだ推定・予告の元になっている札の中身が後から変わる）
  - 追記した続報には、自分の url・日付・お金の動きが要る。札でないと、地図・主体の盤面・予告の元・読む枠に載らない
  - 2台で同じ札に別々に追記すると、合わせ方がもう1つ要る
- **勧める形：続報は今までどおり新しい札にして、`follows`（どの札の続きか）を付ける。** 言い換えだけのものは A-3 の `same` で札にしない。お金の動きの `after` と同じ指し方にする
- 失うもの：続報の札は減らない（フーシ派なら6枚が4枚になる程度）。「続き」の線を見せる場所を作らないと、付けても見えない

### A-6 優先順位

| 案 | 止まる見込み（重複21枚に対して） | 確かさ |
|---|---|---|
| A-3 すでにある札を渡す＋same | 先の札が見えるのは21枚すべて。ただし今でも見えていた6枚は重複したので、**何枚止まるかは測れません**。見えていなかった15枚（71%）が上限の見込み | 流して数えるまで分からない |
| A-4 前に読んだ回 | 7枚（33%） | 回の印が合えばほぼ止まる |
| A-5 follows | 重複は減らない（続報をつなぐだけ） | — |

**1つだけなら A-3。** 重複の多くは同じ日に何度も流したことで起きていて、A-4 はその分（ECB・フーシ派・サウジの管など）に効かない。A-3 を入れたあと、JSON の `same` の数と重複の数を1週間数えて、効きを測る。

### B-4 誰が押すか

- v20.45 の［札にする］が0枚だった件から、**1組ずつ押す形は続かない**と思う
- **アプリが字の近さで勝手に束ねる形には反対**（B-5 のとおり半分が間違う）
- **勧める形：チャットが組を提案し、アプリは1回押しでまとめて受け、違う組だけ人が外す**
  - 入口（これから）：朝の取り込みの `same` で、チャットが「この札と同じ」と書いたものは札にしない。結果の1行に件数と相手の札を出し、押すとその札が開く。違っていたら［別の出来事だった］で、次に同じ JSON を貼ったとき札にできるようにする
  - 溜まった分（今の15組）：「同じ出来事を探す」依頼文をコピー → チャット → 組の JSON を貼る → 画面に組の一覧（理由つき）→ **［この組をまとめて束ねる］1回** → 違う組だけ［外す］
  - 「判定するのは機械ではなくチャットで、理由を必ず出し、人が1回押して受け、外せる」形。今日見るべき3件と同じ考え方
- 失うもの：チャットの間違いは、人が一覧を見ないと残る（外した記録は残す）

## 質問（回答書で決めてほしいこと）

1. **A-3 の切り方**：取り込んだ日14日・上限100件（約4,400字増）でよいか。7日にするか、上限を変えるか
2. **`same` の札は作らない**でよいか（札にしなかったことは結果の1行と記録に残し、［別の出来事だった］で戻せる）
3. **`updates` は作らず `follows` にする**でよいか（反対の理由は A-5）
4. **A-4 の「回」**：checked に回と発表日を書かせ、別ファイルに控える形でよいか。期限を「前の回の発表日」から数え直してよいか
5. **取り込む画面の［プロンプトをコピー］**：今は7件全部を入れる。期限前のソースを短い1行にしてよいか（朝を逃した日の入口としては残す）
6. **B のまとめ方**：案2＋表示で畳む（案1・案3は反対）でよいか。代表の札は「一次資料の札、無ければ先の札」でよいか
7. **B-4**：チャットが組を提案し、人が1回押して受け、違う組だけ外す形でよいか
8. **段の順**：段1（入口の一覧と same）→段2（回）→段3（畳む表示）→段4（溜まった分）でよいか
9. **別の相談にしてよいか**：「つながる札 ほか42件」の重さは広い概念（チョークポイント30枚など）が主な原因で、重複を畳んでも18%しか減らない。つながる札の並べ方・絞り方は別に扱いたい
10. **1日に何回も流すこと**：9/12 は9回流していた。流す回数に決まりは作らない（時刻の決まりは作らない方針と同じ）でよいか。A-3 で重複を止める前提
