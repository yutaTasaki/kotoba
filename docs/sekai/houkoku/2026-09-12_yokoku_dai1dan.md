# 予告 第1段：入れ物を作り、読む回に書かせ、ホームに出す

## 0. 何をして、どうなったか

**したこと**：読む回（思惑を書く回）に、**「その思惑が本当なら、次に起きるはずの行動」**を
最大5本書かせるようにした。入った予告は、ホームの一番上に期限の近い順で並ぶ。

**結果**：予告が溜まる場所ができた。**第1段では押しても何も起きない**（答え合わせは第2段）。

**意味**：これまで思惑は「読んで終わり」だった。予告が入ると、**後で当たり外れを確かめられる形**になる。
外れれば「思惑の読みが違った」という記録が残る。

**残り**：第2段（答え合わせ）、第3段（貼る欄を1つに）、第4段（次にやることを1つだけ）。

## 1. 予告1本の中身

| 項目 | 例 |
|---|---|
| 誰が | 日本銀行 |
| 何を（4つの動詞） | 出す／止める |
| どれくらい | 減額を四半期4000億円で続ける |
| いつまでに | 2026-12-19（**必ず日付**） |
| 当たりの印 | 日本銀行の金融市場調節の公表 |
| 約束どまりか | いいえ |

**動詞は4つ**（買う／売る・出す／止める・貸す／借りる・物や人を動かす）。
「約束する」は動詞にせず**別の印**にした。第4段で入れた「約束の印」と同じ概念が
2か所に分かれると、後で必ず食い違うため。

## 2. 結果欄は最初から4つ（指摘を受けて修正）

仕様書の初版では、第1段の結果欄を「まだ」だけにしていた。
指摘を受け、**入れ物は最初から4つを受け取る**形に直した。

- まだ（期限前）／当たり／外れ／**確かめられない**
- **押した日時も最初から持つ**

第1段が書き込むのは「まだ」だけだが、**後から足すと、すでに溜まった予告に日時が無く、
2台で押したときどちらが新しいか決められなくなる**。第2段は押す経路と画面を足すだけで済む。

確かめた：4つとも受け取り、知らない値は「まだ」に倒れる。保存の往復でも消えない。

## 3. 落としたものは必ず理由を出す

```
予告が5本入りました。
※ 期限が日付でないもの1本を落としました（「9月中」）。
※ 同じ主体・同じ動き・同じ期限の予告1本は既にありました。
※ 6本目以降の1本を落としました（1回5本まで）。
※ 主体の名前が無い予告1本を落としました。
```

### ここで自分の間違いを1つ直した

最初の実装では、**上限（1回5本）を他のどの検査よりも先に当てていた**。
その結果、先頭5本で枠が埋まり、6本目以降は中身を見られないまま
**全部「本数超過」に一括りにされた**（実測で `本数超過4・他は全部0` になった）。

これでは「期限の書き方が悪かった」が利用者に永久に伝わらない。
**先に中身を検査し、通ったものにだけ上限を当てる**順に直した。
直したあと、5つの理由が正しく分かれることを確かめた。

## 4. 確かめたこと（実機）

| 見たもの | 結果 |
|---|---|
| まっさらから1回で取り込み | 入った5・期限が日付でない1・重複1・6本目以降1・主体名なし1 に**分かれた** |
| 「9月中」の扱い | 落とし、文面に「（「9月中」）」と出た |
| 期限 | 入った5本とも YYYY-MM-DD |
| ホームの位置 | **一番上**（`homeForecastRow` が先頭） |
| 表示 | 「待っている予告 5本」＋期限の近い順に5本 |
| **押せないこと** | ボタン0個・クリックの受け口なし・指の形も変わらない |
| 0本のとき | **行ごと消える**（「ありません」の空行を出さない） |
| 幅360・320 | はみ出しなし |
| 保存の往復 | 結果・押した日時・元の思惑が残る |

## 5. データが消えないための作り

- **別ファイル** `world/forecasts.json`（月割りしない）。端末では `worldForecasts`
- **元の思惑を写して持つ**（`fromRead`）。札側の読みが後で書き直されても、予告の根拠は残る
- **2台で押したときは、押した日時の新しい方を採る**（結果だけ。他の項目は更新の新しい方）
- 起動時の読み込みにも登録した。**保存はされるのに起動で読まれない**、という壊れ方を避けるため

## 6. 第2段への申し送り

- 地層は実測済み（系列20本・717点）。**照合に使えるのは厚い3系列だけ**
  （米国の政府債務総額403点・DFA 上位0.1% 147点・下半分147点）。残り17系列は1〜3点か0点
- 米国の政府債務は毎日更新され、**同じ日付の値が後から訂正されうる**。
  判定に使った時点を残さないと、後から再現できない
- **世界のデータを捨てたとき、予告をどうするか決めていない**。
  いまは捨てる処理に手を入れていないので、札を捨てても予告は残る。
  予告は札の思惑から出たものなので、一緒に捨てるのが筋に見えるが、仕様に無いので触っていない
- 外れた予告は、元の札を読む回に戻す（`rewrite: true` の仕組みを流用できるか確かめる）
