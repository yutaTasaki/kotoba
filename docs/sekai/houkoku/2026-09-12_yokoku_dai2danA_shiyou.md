## 1. 仕様に落とすときに決めたこと

回答書で確定していなかった細かい点を、仕様を書きながら決めた。報告しておく。

| 決めたこと | なぜ |
|---|---|
| 朝のプロンプトの差し込み位置は「並べ方」の後・「出力形式」の前 | 既知の概念・アクターの羅列は末尾に置く決まり。羅列より前に置かないと規則が押しのけられる |
| `evidence` の「読み取った日時」は**端末が入れる** | 生成に書かせると、生成が名乗った時刻になる。端末が入れれば、いつ見えていた値かが確かになる |

| 押した後もボタンは**出たまま** | 「取り消し」を別に作らず、押し直しで変える（状態が1つ減る） |
| 根拠1行は**ボタンより上** | 押す前に必ず読ませるため |

## 3. 第2段Bに送ったもの（危険の確認を含む）

回答書で「4か所すべてに足す」と確定した捨てる処理は、**第2段Bに送った**。
仕様書には、いまの状態を表にして残してある。

| 場所 | いまの状態 |
|---|---|
| 捨てるときに空にする器の並び | 予告が**無い** |
| 保存庫へ書き戻す器の一覧 | 予告が**無い** |
| 受け取った側の端末へ書く並び | 予告が**無い** |
| 保存庫のファイルを上書きする並び | 予告が**無い** |

4か所すべてに足さないと、**捨てた端末では消えるのに、もう一方では残り、次の同期で復活する**。
Aが実機で安定してからBに入る、という段分けはこの危険があるからで、順番を守る。
