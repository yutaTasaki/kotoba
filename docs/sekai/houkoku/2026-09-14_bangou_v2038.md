## 何をしたか

1. **番号の後ろを数字6桁の乱数にした**（言葉・日誌・下書き・札・概念／用語／主体・聞いたこと）
   - 頭の「種類_日付_」は今のまま。後ろは 100000〜999999
   - 今ある番号はそのまま。これから作る分だけ新しい形
   - 同じ起動の中で出した番号は覚えておき、一度に何件も作っても重ならない
2. **消した番号を使い直さないようにした**（言葉・日誌・下書き。札は前から）
3. **同期で同じ番号がぶつかったら出すようにした**
   - 見分け方：合わせるとき、同じ番号が両方にあって作った日時が違うもの。「種類_8桁の日付_数」（予告は「_英数字」）の形の番号だけ見る
   - 見る所：言葉・日誌・下書き・札・概念／用語／主体・聞いたこと・予告を合わせる7か所。残す方の決め方（更新日時の新しい方）は変えていない
   - 画面の一番上の同期の1行に「※ 同じ番号が2つありました。N件（新しい方を残しました）」。設定の「統計と使用量」を開くまで出す
   - 設定の「統計と使用量」の見出しにも「同じ番号のぶつかり N件」
   - 設定の「切り詰めた文」の下に「同じ番号でぶつかったもの N件」と、1件ごとに種類・番号・日時・残した方・消えた方と［消えた方をコピー］
   - 消えた方の中身は端末に最大50件控える。超えたら古いものから消し、「古い控え N件を消しました」を出す
   - 同じぶつかりは1回だけ数える

## 意味

- 両方の端末が v20.38 になれば、同期の前に2台で同じ日に作っても、番号はぶつからない（同じ種類・同じ日付の2件の間で、1組あたり90万分の1）
- それでもぶつかったとき（古い版の端末が残っている間など）は、画面に出て、消えた方の中身が端末に残る

## やった場合に失うもの

- 番号が長くなる。生成とのやり取りで、全部が新しい形になったとき読む回 +372字・朝の言葉と関連づけ +495字。今ある番号は短いままなので、しばらくはもっと小さい
- 同じ日の中で、番号から作った順が分からなくなる（番号で順を見ている所は無い）
- ぶつかりの控えはその端末にだけ残る。別の端末からは見られない。戻すのは手作業
- 見張りは v20.38 の端末でだけ動く
- 端末の保存場所を、控え50件ぶん（多くて約12万5千字）使う

## お願い

1. **iPhone と PC の両方を v20.38 にしてください**（設定 → 世界の見出しの右に「版 v20.38」）
2. 両方そろうまでは、2台で同時にものを作らないでください（回答書どおり）
3. 同期の1行に「同じ番号が2つありました」が出たら、設定 → 統計と使用量 を開いて、消えた方を確かめてください

## 測れていないこと

- 本物の2台どうしの同期で、見張りが出ること（本物の GitHub を使った2台の同期は試していない。本物のコードを取り出した試しと、試しのページだけ）
- 生成が長い番号を写し間違える割合
