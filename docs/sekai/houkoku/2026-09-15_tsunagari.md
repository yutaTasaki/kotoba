何をしたか
- v20.53 のコードと、本物のデータの写し（kotoba-data。札145枚・幹11本・幹の記録167件・調べた記録7件）を読んで数えた

## 先に：結論

1. **名前は、画面の言葉だけを木で揃える。** プロンプトとデータの欄名は変えない（反対）。枝か葉か決まる前の「札」は「札」のまま残す
2. **調べたことの「札の候補」が押せないのは仕様どおり。ただし押せるようにする道が見えず消えやすい。押せた後にも不具合1つと作りかけ1つがある。** 調べた記録7件・134項目は、いまも主体にも幹にも枝にも戻っていない
3. **幹どうしの横のつながりは、チャットが1枚ずつ幹を選んだ結果（2本にまたがる枝・3本目を付けたかった枝）から作るのが筋。** 同じ主体・同じ地層・同じ国・同じ概念で結ぶのは反対（米財務省1人で10組、チョークポイント1つで20組つながる）
4. **地図は、幹の画面の中に「幹の地図」として入れる。** 枝1件だけの地図は作らない（反対。1本の線にしかならない）。地図タブはなくさず奥へ下げる
5. **順番**：①名前と候補の穴 → ②幹の地図 → ③隣の幹は、最初の答えが出て段4を作り直すときに一緒に

**ふだんの日に押す回数は、どれを入れても増えない。**

## 1. 名前を木で揃える（問1〜5）

### 問1 どこまで直すか：**画面の言葉だけ**（推奨）

**数えたもの**（index.html を、画面に出る文字列・プロンプトの文字列・コメントに分けて数えた）
- 「札」：画面166・プロンプト116・コメント366
  - このうち幹・枝・出発点と同じ文にあるのは、画面17・プロンプト17だけ
  - 残りの画面149は、**枝か葉か決まる前の札**（「まだ読んでいない札」「札にする」など）
- 地図の「根」：画面34、プロンプトとデータには0
- 「出発点」：画面8・プロンプト5

**決め方**
- 幹に付いた札 →「枝」、幹に入らない札 →「葉」、出発点 →「根」
- 札一般（枝か葉か決まる前、朝の取り込みの結果、読む回の対象など）は **「札」のまま**。木の4つの言葉には「まだ決まっていない札」を指す言葉が無いため
- 失うもの：画面に「札」が約150か所残る

**プロンプトの「札」を「枝」にするのは反対**
- 朝の取り込みでは、枝になるか葉になるかはチャットの返事で初めて決まる。「入らない枝」のように文が食い違い、無理に幹へ付けて葉（今は33枚/145枚）が減るおそれ（どれだけ減るかは測れません）
- 返事の JSON の名前は、日本語を変えても変わらない

**データの欄名（`miki` など）を変えるのは反対**：壊れるもの
- GitHub 上の幹の記録167件は一度書いたら変えない記録。古い名前を永久に読むか、ファイルを書き直すことになる
- v20.50〜53 の端末では、新しく付いた枝が見えない・幹から枝が消えて見える
- 「知らない欄を残す」仕組みが守るのは、調べた記録の月ファイルの一番上だけ。札の中の欄は、古い端末が書き戻すと消える
- 更新前にコピーしたプロンプトを後で貼ると、黙って枝が付かない
- 欄名はもともと英語なので、変えても分かりやすさは増えない。代わりに**言葉と欄名の対応表を仕様書に1つ**置く

### 問2 世界タブの外の「札」

- 画面に出るのは**撮る**の2か所だけで、意味は「言葉のメモ」→ **「言葉」に直す**のを勧める
- ホーム・記録・設定の5か所は世界の札なので、世界と同じ扱い
- 「種」は言葉タブの問いと記録の画面ですでに使っているので、葉には使わない方がよい

### 問3 地図の「根」（自分に使う）の呼び名

今の地図では、国の点から真下に伸びる短い棒で、「自分の側に積んだ金」と説明している。

| **① 杭**（推奨） | 形がそのまま（点から下に打ち込まれた棒）。アプリの中で使っていない | 伸びる・育つ感じは無い |

### 問5 いつやるか：**段4を書き直す前に、名前だけの版を1回出す**

- 量の見込み：画面だけで約60行、データとプロンプトは0
- 実機で見るだけで済む所：世界の一番上・幹の画面・札・地図・ホーム・撮る
- 回さないと見られない所：朝の取り込みと読む回の結果。割り直しの画面は、もう一度割り直さない限り本物では見られない
- 理由：段4は新しい文言を大量に作るので、先に名前を決めれば2度書かずに済む。段4と一緒に出すと、新しい機能の不具合と言い換えの漏れが混ざる
- 失うもの：公開と確かめが1回増える。地図の根の名前（問3）を先に決める必要がある

## 2. 調べたことを戻したあとの「札の候補」（問6〜9）

### 問6 仕様か、作りかけか、不具合か：**押せないのは仕様どおり。ただし実際には押せないのと同じ**

- ボタンは、候補の枠の中の［url を開く］（ボタンの形のもの）をその画面で押すまで押せない作り。**人が出典を開いて確かめた札だけを作る**ための決まり
- 本物の候補7件は、字数・日付・出す側/受け取る側・url の条件は全部満たしていて、止めているのはこの1つだけ
- 押せる道が見えにくく、消えやすい（試しのページで確認）
  - 押せない理由の1行（「url を開いて確かめてください」）が薄い灰色の小さな字で、理由に見えない
  - 出典の行の小さい「url」を押しても、開いた扱いにならない
  - 開いた印は画面の記憶にしか無く、ページを読み直すと消える。アプリは新しい版があると戻ったときに自動で読み直すので、url を開いて戻るとまた押せなくなることがある（端末で実際にそうなったかは測れません）
- **押せた後の不具合**：朝のプロンプトをコピーしてから取り込むまでの間に候補から札を作ると、「新しい幹の候補を聞いた」控えを使ってしまい、コピーした内容の控えが消える
- **押せた後の作りかけ**：候補から作った札は、どの幹にも付かず、葉の数にも入らない。主体も増えない

### 問7 いまの道（押す2回）

1. 元の札を開き、「自分で調べたこと」を開く
2. 候補の枠の中の、ボタン形の［url を開く］を押す（出典の行の小さい「url」ではない）
3. 開いたページに書いてあるか見て、同じ画面に戻り［書いてあった・札を作る］を押す
- 戻ったときに押せなくなっていたら、もう一度［url を開く］から
- **こうして作った札は枝にならない。** 候補を枝にする道は、いま無い

### 問9 候補から枝を作れるようにするには

**どの案でも要るもの**
- 押せない穴を塞ぐ：出典の小さい「url」も開いた扱いにする・開いた印を端末に残す・押せない理由を目立たせる。失うもの：開いただけで読まずに通る余地が少し広がる
- **「開かずに作れるようにする」には反対**：人が確かめた札だけ、という決まりが崩れる
- 札を作る道を、朝の取り込みの控えから切り離す（問6の不具合）
- 幹に付けた記録を残し、どの幹にも入らなければ葉として数える

**幹への付け方**

| 案 | 押す回数 | 失うもの |
|---|---|---|
| A：自動で元の札の幹を引き継ぐ | 2回のまま | 「続報でも前の札の幹を写さない」決まりと逆。**候補7件中5件は元の札より古い脇道の出来事**で、黙って元の幹に付き、幹が太る |
| B：チャットに選ばせる | 2回のまま | 依頼文が約2,100字から約3,000字に延びる（推測）。コピーから取り込みまでに幹を割り直すと番号が合わず落ちる。結果が案Aに寄る見込み（測れません） |
| **C：人が選ぶ（はじめは元の札の幹に印）**（推奨） | 変えなければ2回、変えるときだけ1〜2回増える | 押す前に1行読む手間。見ずに押せば案Aと同じ。狭い幅で幹11本の行が長くなる |

推奨の理由：候補は1回に0〜2件と少なく、調べた日だけの手間で済む。脇道の出来事を「葉」に落とす選択肢が目の前にあるので、葉が新しい幹の芽になる道にもつながる。

### 問17 枝1件の地図：**反対**

### 問18 置き場所と重さ

### 問20 幹の地図に時の流れを出す

太さ（ドル換算）・線の種類（点線＝換算なし）・薄さ（約束）はすでに使っているので、使えるのは色の明るさ・番号・地図の外の帯。

| 案 | 見え方 | 失うもの |
|---|---|---|
| **1 前に読んだ日より新しい枝だけ強調**（推奨・まず） | 新しい線だけ明るく、古い線は落ち着いた色 | 順番は出ない。灰色の線が暗い地図で見えるかは実機で確かめが要る |
| 2 古い順に番号 | 線の中ほどに ①②③ | 線が重なると番号が読めない。6本を超えると使えない |

### 問23 動線のどこに入るか

```
着火点 ───────→ お金の動き ───────→ 行動 ───────→ 主体の意思 ──→ 幹：今の答え
(朝の取り込み)      (幹の画面の地図)      (枝の主体)       (読む回の推定)    (読む回が書き直す)
  │ 札が枝か葉に分かれる  ├ 根から今日の枝までの線                                    │
  │ 葉が積もると芽        ├ 開いた枝の線を濃く                                          │
  │                       └ 隣の幹（またぐ枝）③ ─→ 別の幹の画面へ                     │
  │                                                                                     │
  └── 調べたことを戻す → 候補 → 人が幹を選ぶ → 枝／葉 ②  ←──── 札の画面から ──────┘
        ▲                                                                              │
        └──────────────── 翌朝のプロンプトに幹の名前と1行 ────────────────────┘
```

- 地図は「お金の動き」の位置、つまり幹の画面の中に入る（別の部屋にしない）
- 隣の幹は、幹の画面から横に出る線
- 調べたことは、札の画面から枝か葉に戻り、輪の中に入る

### 問24 人が開かなくても育つか・地図と同じ道をたどらないか

**育つもの（人が開かなくても）**
- 枝・葉・芽：朝の取り込みで増える（今と同じ）
- 幹の地図：枝のお金の動きから毎回組み立てるので、世話は要らない。枝が増えれば線が増える
- 隣の幹：チャットが1枚ずつ選んだ結果から毎回数えるので、世話は要らない

**人の手が要るもの**
- 調べたことを枝か葉に戻す：調べた日だけ（幹を選ぶ1回）

**地図と同じ道（作ったが見ない）をたどらない理由**
- 今の地図は、見に行く場所（地図タブ）にしか無かった。幹の地図は、**毎朝通る「今日動いた幹 → 幹の画面」の途中に出る**
- 地図単体の画面を増やさない。地図タブは奥に下げ、入口を幹の地図の中に置く
- **ただし、幹の画面そのものが毎日開かれているかは測れません**（画面を開いた跡を残していない）。開かれていなければ幹の地図も見られない。これは、①②を出した4週間後に、本人の使い方の感触で確かめるしかない
