## 1. できたこと

- 朝の取り込みの返事に **`cmp`（比べる相手：名前・値・関係・比）** を書かせるようにした
- **「最近のお金の動き」の節（2,053字）を外した**
- 印が `size` の札で、欄に `total` が無いとき、**棒2本**を「なぜ」の直下に出す
- **100倍を超えたら棒をやめて言葉にする**

書かせる形はこれです。

```json
"cmp":{"name":"前年同期の設備投資","value":"396億4300万ドル","rel":"prev","ratio":2.03}
```

`ratio` は「**この札の額 ÷ 相手の額**」の1つだけ。単位をそろえてから割らせます。

規則に入れた1行（そのまま）：
> **比べる相手は、その出典の中にある数字だけ。外から探してこない。**

## 4. 「最近のお金の動き」を外して失うもの

**測って分かっていること**

- この節は、直近のお金の動きを最大30件、id つきで渡していました（2,053字）
- その id は `after`（前の動き）を書くためのものでした。**前回の実測では、`after` は8本のうち鎖として読めたのが2本だけ**で、6本は後ろの日付を指すか、同じ日の重複札を指していました
- 外したことで、`after` に **`w_…` の id を書く道が消え**、同じ JSON の中の `#番号` だけになりました。**別の日の札へつなぐ鎖は、これから作られません**
- 節に出ていた札は、消えたわけではなく「すでにある札」の節に回りました（+45字）。**重複を見つける材料（`same`・`follows`）としては残っています**

**測れないこと**

- これから `after` がどれくらい減るか。いまの実績（実質2本）から考えると失うものは小さいと見ていますが、これは推測です

## 5. 公開の前に実機で確かめてほしいこと

**触ると壊れる形から**

1. **次の朝の取り込みで、返事が壊れないか。** `cmp` を足し、`after` の渡し方を変えたので、**返事の形が崩れる可能性がいちばん高いのがここ**です。JSON が読めない・件数が減るなどが起きたら、段2-2 だけ取り消せます
2. **`cmp` をチャットが書けているか。** 取り込みの結果の行に「比べる相手 …」が出るかで分かります
3. **比べる相手が出典の中の数字だけになっているか**（外から探してきていないか）。棒の横の名前と値を、元の記事と照らしてください
4. 棒2本が「なぜ」と1行の間で読みにくくないか。帯（段2-1）と並んだときに紛らわしくないか
5. 既存の145枚が今までどおりか（帯13枚・地図13枚・1行が減っていないか）
6. `after` が書かれなくなっても、朝の取り込みが困らないか
7. もう片方の端末で同じか

**戻すとき**：v20.65 のコミットだけを取り消せば、`cmp` の無い形（v20.64）に戻り、「最近のお金の動き」の節も戻ります。データには何も書いていません。
