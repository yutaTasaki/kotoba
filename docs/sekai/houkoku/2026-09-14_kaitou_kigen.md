# 予告の期限と聞き直し：仕様書を書いた

仕様書：[`spec/sekai_kigen.md`](../spec/sekai_kigen.md)

## 何をしたか

- 回答書の6つの答えと「時間の扱い」を、v20.40 の1回で公開する仕様にした
- 前の調査で読んだ期限の判定・押す処理・答え合わせの選び方・取り込みを、もう一度コードで確かめ、1つの決まりにまとめる形を決めた

## 結果（先に）

1. **回答書の6つにすべて賛成。反対は無い。**
2. **予告の「時期」を1つの関数で決める。** 待っている／期限当日／期限が来た／もう一度確かめる時期／押したもの／畳んだもの。画面・件数・答え合わせは全部これを使い、期限を直接比べる所を残さない

| 時期 | 押せるか | 答え合わせに載るか |
|---|---|---|
| 待っている（期限前） | 押せない | 載らない |
| **期限当日** | **押せる** | **載らない（翌日から）** |
| 期限が来た（翌日以降） | 押せる | 載る |
| **もう一度確かめる時期**（確かめられないを数えた日から7日） | 押せる | 載る |
| 押したもの | 押し直せる | 載らない |
| 畳んだもの（3回） | 押せない | 載らない |

3. **回数は「確かめ直した後に押したときだけ」増やす。** 確かめ直した＝前に数えた後に見立てを取り込んだ、または前に数えた日から7日たった。続けて押す・押し替えるだけでは増えない
4. **米財務省の1本は、書き込みなしで 9/21 から戻る**（数えた日時が無い予告は押した日時 9/14 で数える）
5. **回答書に無い小さい足しが5つ**（どれも賛成なので仕様に入れた）

| # | 足し | 理由 |
|---|---|---|
| 足1 | 「確かめられないを数えた日時」の欄を1つ足す | 押した日時は［外れ］を押しても変わるので、それで数えると「確かめられない→外れ→確かめられない」の押し替えで回数が増え、穴が残る |
| 足2 | v20.39 の「見立てがまだの予告が無ければ全部聞き直す」をやめ、7日の決まりに一本化 | 取り込んだ直後にもう一度コピーすると、同じ予告をすぐ聞き直してしまう |
| 足3 | 予告の画面に「もう一度確かめる時期」の欄を足し、ホーム・世界の画面の件数にも入れる | 載せ直した予告が「押したもの」に埋もれると、返事を取り込んだ後に押す予告を見つけにくい |
| 足4 | 取り込みは「確かめられない・畳んでいない」予告も受け付ける（結果は変えない） | 聞き直しの返事を取り込むため |
| 足5 | 期限前の予告の答えは取り込まず、本数を出す | 期限前に見立てが入ると、期限が来たときに後回しになる |

6. **時刻の決まりは作らない。** 答え合わせは夜にする運用（回答書どおり）。画面に「夜がおすすめ」のような1行も足していない（仕組みを変えないため）

## やった場合に失うもの

- 期限当日の予告は、押せるが答え合わせのプロンプトには載らない（調べるのは手作業）
- 確かめられない予告が7日ごとに最大2回戻り、コピーと貼り付けが増える。畳むまで約3週間
- 7日たつ前に自分で調べ直して［確かめられない］を押しても、回数に数えない（見立ての取り込みが無いと確かめ直したと分からない）
- 見立てを取り込んだ直後に同じ予告を聞き直したいときは、7日待つ
- 予告に欄が1つ増える。v20.39 までの端末は落とす（落ちても押した日時で数えるので、ずれるのは押し替えた後だけ）

## 仕様書で決めた確かめ方（回答書の分を含む）

- 端末の日付を動かして：期限当日の予告が「期限が来た」に出て押せる／プロンプトに載らず翌日に載る
- ［確かめられない］を続けて3回押しても畳まれない、押し替えても増えない
- 押した日から6日目は載らず7日目に載る。見立てを取り込んで押すと回数2、さらに7日後に3回目で畳まれ、畳んだものに回数と理由
- 見立てを取り込んだが押していない予告は、見立てから7日目に載る
- 米財務省の1本が、日付 9/20 では押したもの、9/21 ではもう一度確かめる時期に出てプロンプトに載る（書き込みなし）
- 期限前の予告の答えは取り込まれず、確かめられないの予告の答えは結果を変えずに取り込まれる
- ホーム・世界の画面の件数、本物のデータの整え直し、決まった8項目と予告の画面のボタンを本当に押す
