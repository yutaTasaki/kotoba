## 変えたこと

**前：** 歩いた日数が多い方を丸ごと採る。同じなら自分の分を書く（後から同期した端末の分で上書き）

**今：** 日ごと・欄ごとに、あとから変えた方を採る

| 欄のまとまり | 中身 |
|---|---|
| 散歩した印 | その日を歩いたか、と記録した日時 |
| 今朝の体調 | 1つ |
| 散歩後の体調 | 1つ |
| 歩数と距離 | 歩数・距離・保存した日時（1回の保存で一緒に書くので1つ） |
| 開始日・最長記録の手直し | それぞれ1つ |

- いつ変えたかを、散歩のファイルの `fieldAt` に残す（体調を押す・歩数を保存する・散歩した・その日の記録を取り消す・開始日・最長記録・最初の登録）
- **消したときも日時を残す。** 「その日の記録を取り消す」をした後に、別の端末の古い記録と合わせても戻ってこない
- 日時の無い今までの記録どうしは「有る方」を採る。両方に有って違う値のときだけ、どちらの端末で合わせても同じ答えになる決まりで1つに決める（2台が互いに書き直し続けないため）
- 開始日は、日時が無いときは早い日付を採る（何も入れていない端末は今日の日付を持っているため）
- 「散歩データを全て削除」「読み込み」は、その時より前の記録を別の端末から戻さない印を立てる（今までどおり GitHub を上書きする）
- 「その日の記録を取り消す」「最初の登録」は、GitHub を上書きせず合わせて送るようにした（上書きすると、別の端末で入れた別の日の記録まで消えるため）

**ついでに直した2つ（前からあった）**
- 何も入っていない端末で初めて同期できたとき、ホームが「散歩データを読み込めていません」のまま残っていた → 初めて同期できたら画面を描き直す
- 同期の途中で押した体調などは「送った」扱いになり、次のきっかけまで送られなかった → 残して、もう一度送る

## 失うもの

- 散歩のファイルが少し大きくなる（いつ変えたかの日時。1日あたり約100〜150字。1万日で約1〜1.5MB の見込み。1ファイル50MB の警告には遠い）
- 2台の時計がずれていると、「あとから変えた方」は時計の進んだ端末になる
- 日時の無い今までの記録で、2台が別々の値を持っていた欄は、片方の値になる（今の本物の散歩データでは、2台の値は同じはず。確かめる方法はありません）
