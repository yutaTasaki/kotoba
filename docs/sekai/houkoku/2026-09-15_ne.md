## 先に：結論と、指示書への反対・直してほしい点

**結論：根は入れられる。ただし「線の途中の部屋」ではなく、「線の終点に置いて翌朝に戻す輪」にする。そうすれば、人が根の画面を開かなくても、毎朝の取り込みと読む回だけで育つ。** 押す回数は、ふだんの日は増えない（取り込み1回＋読む1回で8回のまま）。増えるのは、結果に出る数行を読む量。

## データ

### 1. 根はどこに持つか

**推奨**
- 根を立てた・札をぶら下げた・答えを直した・変えなかった、を**一度書いたら変えない記録**にする
- 置き場は、調べた記録の月ファイル（押した日の月）に相乗りさせる
- 根の一覧と今の答えは、端末で記録を並べ直して作る
- 2台で合わせる単位は記録1件。記録は消さないので、足し合わせるだけで衝突しない。v20.48 で「今日見るべき3件」「重複の記録」を置いたのと同じ場所・同じ合わせ方で、2台での動きと、古い版に消されても書き戻る動きは確かめ済み

**失うもの**
- GitHub の上で、根の一覧を1ファイルでは読めない
- 調べた記録の月ファイルに、3つ目の相乗りが増える
- 起動時に全部の月を読むので、1万日後に端末が持つ量が増える（中くらいの使い方で約90MB、推測）。データ量の判断待ちの件と一緒に決める必要がある

**根拠**：札・主体・予告・世界の索引は、項目ごとに丸ごと勝ち、知らない欄を落とす。調べた記録の月ファイルだけが、知らない記録を残して書き戻す。

### 2. 根と札の紐づけ

**推奨**：札側にも根側にも持たず、紐づけそのものを1の記録にする。記録には札の番号と、札の「何が起きたか」の写しを入れる。
- 札 → 根：記録から表を作るだけ。通信は要らない
- 根 → 札：札番号に日付が入っているので月が分かる。写しがあるので、月を取りに行かなくても根の一覧に札を並べられる

**失うもの**
- 札のファイルだけを見ても、根が分からない
- 紐づけ1件あたり約0.55KB

**札側に持つのは反対**：古い版がその月の札を1枚でも書き直すと、月の全部の札から根の印が落ちる。新しい版はそれに気づかず、書き戻さない（コードを読んだ推測。動かしてはいない）。

### 3. 今の答えの履歴と、1万日もつか

**推奨**：答えは全部の版を月ごとの記録に残す。札の中の読み（最初の文と今の文の2つだけ）と同じ形にはしない。

**実測**：札1枚 約3.5KB、主体1人 0.42KB、予告1本 0.97KB、答え1件 約1.0KB（150字で作って数えた）。

**1万日の見込み（推測。根は同時に10本）**

| 読む回 | 1万日の合計 | 1か月のファイル |
|---|---|---|
| 週1 | 約34MB | 約0.1MB |
| 週3 | 約94MB | 約0.3MB |
| 毎日 | 約255MB | 約0.8MB |

月ごとなら1万日もつ。1ファイルにすると、週3回で約100日で1MB を超え、毎日だと約4,000日で GitHub の上限100MiB に届く。

**測れません**：ふだんの読む回の回数。立ち上がりの3日間は9回だった。

**失うもの**：画面に出すのは今の答えと、1つ前の答えまでにする。それより古い版は、根の画面の「履歴」を開かないと見えない。

### 4.「変えなかった」の記録

**推奨**：残す。その読む回に新しい枝が来た根だけ、根ごとに1行。画面には根ごとに「最後に確かめた日」を出す。

**失うもの**：1万日で約4〜55MB。

**根拠**：「見て変えなかった」と「見ていない」を分けられるのは、この記録だけ。人が開かなくても根が生きているかを判断する材料になる。チャットが返事を省いた根は、読む回の結果に「返事の無い根 N本」と出す。

## 既存の仕組みとの関係

### 5. 根と概念は何が違うか（一番聞きたい点）

**違い**

| | 概念 | 根 |
|---|---|---|
| 何か | **仕組みの名前**（チョークポイント、財政支配、余剰生産能力） | **いま進んでいる話**（ホルムズ・紅海が詰まる） |
| 時と主体 | 持たない。どの時代・どの国にも当てはまる | 持つ。誰が、いつから、どちら向きに |
| 答え | 持たない（定義の1文） | 持つ（得る側・払う側／誰に向けた手か／ずれ） |
| 終わり | 終わらない | 終わる・向きが変わる |

**実測（今の概念）**
- 45件。ファイル10万字のうち、説明文は2.4%、同じ札に出た回数の記録が68%
- 札に付いた数：チョークポイント30、余剰生産能力20、生産能力の先行投資20、交易条件20
- 同じ「AとBの関係」の組が2回以上出たもの：私の数えで17組（評価報告書では19組と数えた。数え方の違い）
- 人の操作（上位の概念を付ける・名前を直す・隠す・概念から聞く）は全部0回

**筋を壊している原因**：概念そのものではなく、**概念が「札どうしをつなぐ役」までしていること**。
- 札の画面の「つながる札」と、読む回に添える2枚は、どちらも「同じ概念に触れている札」で選ばれる
- そのため「チョークポイント」で、TSMC の売上とホルムズの封鎖がつながる

**推奨：吸収せず、役割を分ける**
1. 概念は残し、**「仕組みの辞書」に下げる**。今の用語より一段上の、「話を読むための道具の言葉」
2. **札どうしをつなぐ役は、概念から根に移す**。つながる札は「同じ根の札」に、読む回に添えるものは「その札の根の今の答え」に替える
3. 根の画面に「この話を読むための仕組み」として、概念を0〜3個添える。**根が概念を指し、概念は根を指さない**
4. 同じ札に出た回数の記録（ファイルの68%）は、新しく足すのを止める。今ある分は消さない
5. 概念を新しく作るのは、今のまま取り込みのとき

**吸収しない理由**
- 概念は根をまたいで使われる（チョークポイントは、ホルムズにも紅海にも台湾にも出る）
- 根に吸収すると、同じ説明を根ごとに書くことになる
- 根が終わったとき、仕組みの説明まで一緒に沈む

**失うもの**
- 概念からたどる「根をまたぐ気づき」。今つながる札に出る3枚のうち、同じ根なのは48%。残りの52%は、根をまたぐつながりとして消える
- 同じ札に出た回数の集計（使った跡は無い）

**迷いどころ（本人に決めてほしい）**：概念の新設を取り込みから外せば、プロンプトが軽くなる（概念の一覧は上限120件の枠）。ただ、仕組みの言葉が増えなくなる。推奨は「今は外さない」。

### 7. 予告と根

**根拠**：予告も知らない欄を落とし、結果を押すたびに丸ごと上書きされる。v20.37 で3本消えた場所でもある。

### 8. 問いモードと「開いている問い」

**失うもの**：「問い」に近い場所が2つ残る。

### 10. 「どの根の枝か」を書かせる形

**推奨**
- 札ごとに、続報の印の次へ「根の番号を0〜2個、強い順」と「3本目を付けたかったか」の印を置く
- どの根にも入らなければ、空を返させる
- 規則は約300字、形式は約70字
- 知らない番号が返ったときは、重複の印と同じく捨てずに件数を出す

**足りない論点**：初期投入と問いから作った札（計53枚）には根が付かない。読む回で根の無い札に付けさせるなら、約700字増える。

**失うもの**
- 3本目の中身は数えるだけで、札には残らない
- 続報でも、前の札の根は自動では引き継がない

**確かめが要る**：古い版の端末が札を書き直したとき、この印が消えるか。1の推奨（記録にする）なら影響しない。

### 11. 新しい根の候補の条件

**推奨**
- 候補の節は**毎回は入れない**
- 重複を除いて根に入らなかった札が**3枚たまった日だけ**、その札の一覧と一緒に入れる（その日だけ約950字増える）
- 規則：「2枚以上が1本の話にまとまるときだけ」「1社・1国・1回きりは出さない」「立っている根の言い換えなら出さない」

**当てはめ（実測。評価の振り分け表で）**
- 4日間19回の取り込みで、節が入るのは3回。候補になりそうなのは1〜2回（推測）
- 他の条件だと、2枚で3〜5回、5枚で1〜2回
- 9/12の後半以降の11回では、新しい根に当たる札は0枚だった

**失うもの**：1枚だけで根になる大きな出来事は、3枚たまるまで候補にならない。

**反対**：言い換えの禁止を入れないこと。「関税」は「なぜ」の文に10枚出るので、毎回候補に出るおそれがある。

### 12. 読む回に今の答えを渡す範囲（実測）

今の読む回は **17,170字・20枚**（切れた推定12・浅い読み3・未読5）。

**推奨**
- **その回の札が掛かる根だけ**を渡し、前の答えは渡さない → 19,636字
- 全部の根を渡すと 20,253字
- 今の20枚は10本中7本の根に掛かるので、差は617字しかない
- 画面と動線の調べからの見込み：今添えている「同じ概念の札2枚」（20枚で2,511字）を答えに替えれば、増える分はほぼ消える（1,100〜1,540字の見込み）

**失うもの**
- 札の来ない根は、書き直す機会も「変えなかった」の1行も無い。止まった根は「最後に確かめた日」でしか分からない
- 根をまたぐ食い違い（サウジは借りに行く一方、ファンドは国外に出す）は拾えない

**反対**：全部の根に毎回「変えなかった」を返させること。

### 13. 書き直しの基準4つは、どれくらい当たるか（実測・1人の判定）

4本の根（ホルムズ・紅海／国債の買い手／制裁とドル離れ／欧州が戦費を埋める）に、札を日付順に当てた。

| | 当てた札 | 得る側・払う側 | 前の手と矛盾 | 理由と行動のずれ | 向きが変わった | 変えなかった |
|---|---|---|---|---|---|---|
| 計 | 76 | 4 | 4 | 14 | 5 | **54（71%）** |
| 重複・続報を除く | 52 | 3 | 2 | 12 | 5 | 34（65%） |

**気づいたこと**
- **「ずれ」ばかり当たる**（22回中14回）
  - 取り込みで書かれたずれの欄に引っ張られる
  - 「同じ型のずれが続くだけなら変えない」「対象はその根の主な主体に限る」を文面に入れる
- **「得る側・払う側が違う」は厳しすぎる**（当たりは4回）
  - 得る側が増えるだけの札が20枚ある → 5つ目の出口「足す」（反対・直し ア）
  - 「足す」も数えると、書き直し＋足すで約半分、迷いまで入れると74%
  - この開きが、そのまま文面のあいまいさ。判定に迷ったのは76回中18回
- **「前の手と矛盾」と「向きが変わった」は分けにくい**。分け方の案：
  - 主体の狙いの読みが外れた → 矛盾
  - お金や物の流れの向き・増減が逆になった → 向き
- **見かけの書き直しが出る**
  - 週ごとの数字に読みを付けた札どうし
  - 数字の月と札の日付がずれた札（6月までの年度の数字が、8月の札として「戻る」を作る）
  - 文面に「数字の対象期間で比べる」を入れる
- **答えが周辺から始まる**
  - 日付の古い順だと、最初の2枚が周辺の札になり、中心の札は基準に当たらないまま通り過ぎた
  - **最初の答えは、出発点の札と中心の札から書かせる**必要がある（26の段の順に効く）
- **2本の根にかかる札8枚のうち3枚は、片方の根だけが変わった**
- **60字で切れた推定**：4本の根で82件。文末の「〜に向けて」の手前で切れることが多く、**②誰に向けた手かの相手が落ちる**

**測れません**
- チャットに同じ基準を渡したときの当たり方
- 実際の読む回で、1日に何本の根が書き直されるか
- 書き直しが正しかったか

**推奨**
- 既定画面（主体の盤面）は入れ替えない
- 一番上に「**今日動いた根**」（その日に札が付いた根と、答えが動いた根だけ）と、「根 10本 ▸」の1行を足す
- 今日見るべき件は、その根の行の下に入れる

**失うもの**
- 画面が1日4行ほど長くなる（9/13・9/14 に触った根は1日4本）
- 主体の盤面が下がる

### 18. 2回割らせて食い違いを見る方法

**推奨**
- 段B を**別のチャットで2回**、2回目は札の順を逆にする
- 食い違いは**作業用のファイル**の表で見る（画面は作らない）
- 食い違った札だけ人が見て決め、1の記録として取り込む

**見込み（推測）**
- 根を固定すれば、食い違いは **25〜40枚**
- 根も毎回作らせると 50〜80枚
- 小さな試し（30枚を1人で2回）では、食い違いは4〜5枚で、全部「根に入れるか、入れないか」の境目だった。根どうしの取り違えは0枚
- チャットに根の名前だけを渡すか、含む・含まないの例まで渡すかで、食い違いの数が変わる

**反対**：根まで毎回作らせて比べること。根どうしの対応が取れない。

**失うもの**
- iPhone だけでは進められない
- 後でまた割り直すときの道具が、アプリに残らない

### 19. 出発点の札と、古い日付の札

**推奨**

**失うもの**：出発点は、根の画面からしか見えない。

## 動線

### 20. 根は1本の線のどこに入るか

**線の途中の部屋でも、横の部屋でもなく、線の終点に置いて、翌朝の始まりに戻す。**

```
今：
 着火点 ─→ お金の動き ─→ 行動 ─→ 主体の意思     （ここで終わり。翌朝に何も戻らない）
(取り込み)  (札のお金)   (動かした側) (読む回の推定)

根を入れた後：
 着火点 ─→ お金の動き ─→ 行動 ─→ 主体の意思 ─→ 根：今の答え①②③
(取り込み)  (札のお金)   (動かした側) (読む回の推定)  (読む回が 書き直す／足す／変えなかった)
   ▲ 取り込みで「どの根の枝か」を付ける                              │
   └─────────── 翌朝のプロンプトに根の名前＋1行 ─────────────┘
```

**失うもの**：答えが間違っていると、翌朝の取り込みがそれに寄る（推測）。答えは取り込みには渡さず、名前と1行だけにするのは、これを弱めるためでもある（問9）。

### 22. 根は、開かなくても育つか

**毎日の2つの回を通すだけで育つもの**
- ぶら下がる札（取り込み）
- 今の答えと履歴、「変えなかった」（読む回）
- 主な主体（記録から数える）
- 予告と結果（元の札から引く）

**開かないと止まるもの**
- 新しい根を立てる。ただし入口は取り込みの結果の1行に置くので、根の画面を開く必要はない
- 出発点の札
- まだ分からないこと（読む回が足す形にすれば止まらない）

**概念の経緯（確かめたこと）**
- 9/10 に「たまに整理する場所」と決め、同じ日の夜にタブを消し、9/11 にデータを捨てている
- 器ができて5日しかないので、「降格したから育たなかった」とは言い切れない
- 確かなのは、**人が整理しない限り説明が1文字も増えない作り**だったこと

**根が同じ道をたどらない条件**
1. 答えの書き手を読む回に置き、人ではなくチャットが書く
2. 「変えなかった」も必ず返させ、結果の1行に出す（黙って止まらない）
3. 人に頼むのは「根を立てる」だけ。その入口を取り込みの結果に置く
4. 一覧に「最後に確かめた日」を出す

**残る穴（推測）**
- 読む回に誘う朝の1行は、読んでいない札が8枚以上のときしか出ない
- 取り込みを3〜5件に絞る（論点2）と、誘いが出ない日が増え、根の答えも止まる
- 「根に新しい枝が来た日は、枚数に関わらず誘う」に変えるのを推奨

### 24. 根が育つと、取り込みや読む回が楽になるか

**正直に言うと、押す回数と手間は楽にならない。** 楽になるのは「読んだあとに何が残るか」。

- **朝の取り込み**：根の一覧のぶん、プロンプトは約1,000字重くなる
  - 3枚たまった日だけ候補の節が入る
  - 楽になるのは結果の読み方。「どの根に何枚」と出るので、12枚をばらばらに読まずに済む
- **読む回**：同じ概念の札2枚を、その札の根の今の答えに替えられる。字数はほぼ変わらない
  - 前の答えを見て読むので、同じ主体の読みが言い換えで並ぶ（米財務省の5枚）ことが減る見込み（推測）
- **読む回の回数そのもの**：根だけでは減らない。取り込みを絞ったとき（論点2）に初めて減る

## 順番

### 25. データの傷を先に直すか

**60字で切れた推定（135件・札102枚）**
- 原因：v20.32 までは保存時に60字で切っていた。v20.33〜36 で直した「切れる」と同じもので、135件は全部それより前に読んだ分
- 残っている理由：直す枠が、1回の読む回で12枚ほどしか回らない
- **推奨：割り直し（段B）の前には直さなくてよい。最初の答えを作る前には直す**
  - 割り直しは「何が起きたか＋なぜ」しか使わないので、汚れない
  - 答えの②（誰に向けた手か）は、切れた推定だと相手が落ちる（問13）
  - 直す枠を一時的に20枚にすれば、読む回5〜6回で終わる
- 失うもの：その読む回5〜6回ぶんの時間。直し方は「切れた文を別の欄に移して入れ替える」で、厳密な追記のみではない（反対・直し ウ）

**同じ出来事で食い違う札**
- 札は消さず、「同じ出来事の組」の記録を足す
- 段B の割り直しと同じ回に書かせ、2回とも同じ組になったものだけ残す
- 攻撃した側の食い違いは、その根の「まだ分からないこと」に入れる

**日付が逆の「前の動き」（6枚中2枚）**
- データは直さず、表示の決まりで外す
- 取り込みに、日付の前後を確かめる規則を足す
- いつでもできる
