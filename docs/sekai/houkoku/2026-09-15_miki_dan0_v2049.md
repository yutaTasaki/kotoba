## 1. 段3を始める条件と、読む回の回数（回答書の2）

**直した条件**：出発点の札と、各幹の中心の札に、切れた推定が0枚。

**数え方（推測を含む）**
- 中心の札は、段1の割り直しで幹ごとに決まる（段Aで1本5枚まで。まだ無い）
- 目安として、評価のときの「核」の札43枚を中心の札とみなした
- 実データ（9/15）で、核43枚のうち切れた推定がある札は **34枚**（実測）
- 1回12枚の枠を中心の札に先に回すと、34 ÷ 12 で **約3回**
- 段0を公開してから段1までに読む回を回していれば、そのぶん減る

**出発点の札**は朝の取り込みで新しく作るので、切れた推定は最初から無い（v20.33 以降は60字で切らない）。

**1つ、順番の都合がある**：「幹に掛かる札から先に直す」は、幹が立つ段1からしか効かない。段0のあいだは今の順（予告の元の札 → 新しい出来事）で12枚ずつ直す。仕様書では、直す順の変更を段1に入れた。

## 2. 並行か直列か（回答書の3-1）

**並行して進む。** 直列になるのは次の2か所だけ。

1. 割り直し（段1）の後でないと、直す順を幹で決められない。出発点も探せない
2. 出発点が見つかった（または見つからないと返った）幹でないと、最初の答えを書かない

並行にするため、**出発点を探す仕事を段3から段2に前へ出した**（朝の取り込み1回に1本）。こうすると、段2のあいだに「出発点探し」と「中心の札の直し」が同時に進み、段3を公開した時点で条件が揃っている。

| 期間（推測。取り込み1日1〜2回、読む回 週2〜3回） | 何が進むか |
|---|---|
| 段0 公開〜段1 | 切れた推定を1回12枚ずつ直す |
| 段1 割り直し（1回） | 幹が立つ。直す順が中心の札から先になる |
| 段2 公開から 5〜10日 | 出発点10本（取り込み10回） |
| 段1 の後 1〜1.5週間 | 中心の札の切れた推定が0枚（読む回3回） |
| 段3 公開から 1.5〜2週間 | 最初の答え10本（読む回4回、1回3本まで） |

**合計：段1の割り直しから、全部の幹に最初の答えが付くまで約3〜4週間。** 各段の実装と公開の間は、実機での確かめの速さで決まる。

## 3. 世界貿易/GDP の2025年（回答書の3-2）

**入れなかった。**
- 世界銀行の「Trade (% of GDP)」世界全体（9/15 に読んだ値）は、2024年 56.7% → 2025年 68.5%
- 同じ世界銀行の「輸出 (% of GDP)」と「輸入 (% of GDP)」を足すと
  - 2024年：29.1 ＋ 28.1 ＝ 57.2（貿易 56.7 とほぼ合う）
  - 2025年：29.5 ＋ 28.5 ＝ **58.0（貿易 68.5 と合わない）**
- 2025年の貿易の値だけが跳ねているので、嘘の数字とみなした
- 入れたのは 1970〜2024年の55点。刻みは「年」、確認先は世界銀行の指標のページ
- **失うもの**：最新の値が2024年末なので、地層の画面で「623日前」と古い印が付く（年に1度の数字なので、2026年の値が出るまでこう見える）。毎年の取り直しは作っていない

## 6. 公開の前に、実機で確かめてほしいこと（段0）

**触ると壊れる形（数と見た目では見つからないもの）を先に並べる。**

1. **朝の画面の「途中で切れた推定 N枚 ▸」を指で押す** → 取り込む画面の「読む」の欄に移り、プロンプトがコピーされる。そのまま Claude に貼って、返ってきた JSON を貼り、［読んだ結果を取り込む］を押す
2. 取り込んだあと、**設定 → 世界 を開き直して**、「切れた推定：残り」が12枚ほど減っている
3. **iPhone で、今日の取り込みが無い日に**朝の画面を開き、1行が出ていること（取り込みがある日だけ出ていた不具合を直した所）
4. 世界 → 地層 → **世界貿易/GDP を押す** → 値と「確認先を開く」。確認先を押すと世界銀行のページが開く
5. **PC と iPhone の両方**で、設定 → 世界 の一番下が「版 v20.49」になってから、朝の取り込みを流す（片方が古い版だと、世界貿易/GDP の値が戻るまで1回同期が要る）
6. 朝の取り込みの結果に、前の動きの日付の1行が出たら、その札を開いて前の動きが付いていないこと（出ない日が多いはず）
