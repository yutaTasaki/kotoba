## 2. 本当にぶつかるのか

### 同期で同じ番号をどう扱うか（種類ごと）

| 種類 | 同じ番号が2つあったら | 本物のコードで2台に作らせて合わせた結果 |
|---|---|---|
| 言葉 | 更新日時の新しい方が残る。消した印の方が新しければ消える | 「Aの言葉」「Bの言葉」→ **Bの言葉だけ** |
| 日誌 | 同じ | 相談・朝 → **朝だけ** |
| 下書き | 同じ（言葉と同じ作り） | （同じ作りなので試していない） |
| 札 | 同じ（消した印も同じ） | 「Aの札」「Bの札」→ **Bの札だけ** |
| 概念・用語・主体 | 新しい方が丸ごと残る（消した印は無い） | 「A概念」「B概念」→ **B概念だけ** |
| 聞いたこと | 新しい方が残る。聞いた回（runs）だけは両方を足す | 「Aの問い」「Bの問い」→ **Bの問いだけ**（回は足される） |
| 瞑想 | 新しい方が残る | — |
| デッキのカード | デッキ（日誌の1件）ごと新しい方が残る。カードの番号は関係ない | — |

どれも、負けた側は**画面に何も出ずに消える**。札の場合は、概念・主体が持っている「この札に出てきた」の一覧や、予告の「元の札」が、別の中身の札を指すようになる。

### 札・概念の「ぶつかる余地」はどれだけ小さいか

- 同期は **起動したとき・画面に戻ったとき・保存した後・通信が戻ったとき** に走り、そのたびに、札の月・概念・用語・主体・聞いたことは、索引の更新日時が変わっていれば取りに行く（予告と違って日時を捨てていない）
- ただし番号は、**番号を作るその時に端末にあるものだけ**を見て決める。作る前に取りに行く作りではない
- だから、ぶつかる条件は種類を問わず同じ：**端末 A が最後に同期した後に、端末 B が同じ種類を同じ日付で作って送っていて、その後に A が作る**
  - 例：PC のタブを開いたまま（画面に戻ったことにならない）で、iPhone で言葉を足し、その後 PC でも言葉を足す
  - 例：電波の無い所で片方が作る
  - 札は「出来事の日付」が同じときだけ。言葉・日誌・概念・聞いたことは「作った日」が同じときだけ
- **予告との違いは「同期するたびに取りに行くか」だけ**で、上の条件がそろえばぶつかる。予告は「一度も取りに行かない」ので、同じ日に両方で作れば必ずぶつかっていた
- 端末ごとの使い方（同じ日に2台で作るか・タブを開いたままにするか）は、データに端末の印が無いので**測れません**

## 3. 直すとしたら何を失うか

### 今ある番号はそのままでよいか

**そのままでよい。作り直しは要らない。**
- 番号から読み取っているのは、頭の「種類_日付_」だけ：言葉・日誌は番号の日付でどの月のファイルに入れるかを決め、札も番号の日付で月と日付を読む。瞑想は番号の年で年のファイルを決める
- 後ろの数の形を見ているのは、**札の「お金の流れの続き」（どの札の続きか）を確かめる1か所だけ**で、「`w_` 8桁 `_` 数字」に合わないと続きを空にする
- だから、**頭の「種類_日付_」を残して、後ろだけ変えれば、古い番号と新しい番号が混ざっても読める**

### 後ろを何にするか

| 後ろの形 | 札の「続き」の確かめ | v20.37 までの端末 |
|---|---|---|
| 英数字8文字（予告と同じ） | 通らない → 直す必要がある | **古い端末は、新しい番号を指す「続き」を空にして保存する（消える）** |
| **数字6桁の乱数（100000〜999999）** | 今のまま通る | 今のまま通る。古い端末が作る 1〜999 とは重ならない |

→ 札・言葉などは **数字6桁の乱数**を勧める。ぶつかる確率は、同じ日・同じ種類で2台が作った分どうしで、1組あたり90万分の1。

### 番号を別の場所から参照している所

どれも「番号の文字列が同じか」で引いているだけで、形には頼っていない（上の「続き」の確かめを除く）。

| 番号 | 参照している所 | 形が変わって困るか |
|---|---|---|
| 札 | 予告の「元の札」、概念・用語・主体の「この札に出てきた」一覧とつながり、お金の流れの「続き」、索引の期限の一覧、今日の世界の3件、読む回・主語を補う回・取り込む回のプロンプトと返ってくる JSON のキー | 「続き」の確かめだけ（6桁の数字なら困らない） |
| 言葉 | 日誌の picks（朝・相談で選んだ言葉）、言葉どうしのつながり・外したつながり、重複を見送った組、引く回・問い・デッキの材料、朝・相談・関連づけのプロンプトと返ってくる JSON | 困らない |
| 日誌 | ★を押すとき・デッキ（日誌の1件）を開くときに番号で引く | 困らない |
| 概念・用語・主体 | 概念どうしのつながり、見送った組、統合 | 困らない |
| 聞いたこと | 札の「どの問いから掘り当てたか」、いま開いている問い（画面の状態） | 困らない |

- **画面の並び順：** 番号で並べている所は、デッキのカード（同じ枠・同じ順のときだけ）と、組の鍵を作るときの並べ替えだけ。言葉・札・日誌は作った日時か出来事の日付で並べている
- **URL：** 番号を URL に入れている所は無い
- **画面に番号が出ている所：** 見つからなかった（画面に出す文を組み立てる所を探した。見落としが無いとは言い切れない）

| 案 | 中身 | 失うもの |
|---|---|---|
| **0 直さない** | 今のまま | 同期の間に2台で同じ種類・同じ日付を作ると、どちらかが黙って消える。起きたことに気づく仕組みも無い。9/7 以降の跡は予告だけ |

## 質問への答え

**種類ごとに危なさが違うなら、危ない所だけ直すほうがよいか**
- **まとめて直すほうを勧める（案2）。** 直す中身は、どの種類も「番号の後ろを乱数にする」同じ1行の書き換えで、6か所でも3か所でも手間と確かめる範囲がほとんど変わらない。概念・聞いたことの作り方は札・言葉とほぼ同じなので、残す理由が無い
- 瞑想は、秒まで同じ時に2台で始めないとぶつからないので直さない。デッキのカードは、番号ではなくデッキごと新しい方が残る作りなので、番号を直しても何も変わらない（2台で同じデッキを直すと片方の直しが消える、は別の問題として残る）

**今ある番号を残したまま、これから作る分だけ新しい形にできるか**
- **できる。** 番号から読むのは頭の「種類_日付_」だけで、後ろを数字にしておけば、札の「続き」の確かめも古い版の端末も通る。今ある番号の作り直し・移し替えは要らない
- 古い版の端末が残っている間は、古い端末どうしではぶつかり得る（古い端末は 1〜999 を使い、新しい端末は 100000 以上を使うので、新しい端末とはぶつからない）。両方の端末を新しい版にすれば無くなる

## 測れていないこと

- 2台の端末で、同じ日に同じ種類を作っているか（データに端末の印が無い）
- 負けた側が kotoba-data に一度も書かれなかったぶつかりの数、9/7 より前
- 生成が番号を写し間違える割合（今の番号・長くした番号とも）
- 番号を長くしたときの出力の伸び
