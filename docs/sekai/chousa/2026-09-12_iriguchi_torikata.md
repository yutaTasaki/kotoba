# 調査：チャットの取得役が、どの出典を開けるか（2026-09-12）

朝の取り込みは「チャットが出典を開いて数字を読む」形なので、**どのホストが開けるか**が全ての前提になる。
ここが分からないまま入口を差し替えると、同じ失敗を繰り返す（今回トヨタで4回繰り返した）。

## 1. いちばん大事な性質

**チャットの取得役は、自分で組み立てた URL を開けない。プロンプトに印字された URL しか開けない。**

そのため、年・四半期が URL に入る出典（TSMC の四半期ページなど）は、
**アプリ側が日付を入れて完成した URL を並べる**必要がある（`openUrls`）。
「この形式で組み立てて開け」と指示しても開けない。

## 2. ホストごとの結果

| 出典 | 取得役（Claude の UA） | ブラウザの UA | 使えるか |
|---|---|---|---|
| stockanalysis.com | **200・本文約7,000字**。capex／dividends／buyback あり | 200 | **使える**（トヨタの四半期はここ） |
| SEC（EDGAR の書類本体） | **開ける** | 開ける | **使える**（一次資料） |
| SEC の XBRL API・FilingSummary・index.json | — | **CORS 無し**（アプリから直接は叩けない） | アプリが R 番号の URL を印字する形にした |
| FRED の系列ページ | **開ける** | 開ける | **使える**（DFA はこちら） |
| FRB の CSV | **中身が binary で読めない** | — | 使えない。FRED に変更 |
| TSMC 公式 | **開ける** | **403** | 使える（取得役だけ） |
| global.toyota（トヨタ公式） | **403**（一覧・PDF・アーカイブ・ライブラリとも） | 200 だが **JS 描画で本文に数字が無い** | 使えない。札の url に書くだけ |
| IR BANK | **実機で2回続けてボット検知** | — | 使えない（v20.16 で採用→v20.17 で撤去） |

| macrotrends・FT・WSJ | **403／401** | — | 使えない |
| Yahoo ファイナンス | 開ける | 開ける | **設備投資と研究開発が無い**ので用を成さない |

※ 「ブラウザの UA」の列は、こちらの環境から確かめた範囲。空欄は未測定。

## 3. そのほか測ったこと

- **SEC の R 番号は、会社ごと・書類の種類ごとに安定している**（10-K では 10-Q から1つずれる）。
  だから会社ごとに `{'10-Q': [...], '10-K': [...]}` の形で持つ。
- **8-K の item 2.02（決算発表）は、10-Q／10-K より 0〜1日早いだけ**。
  先回りの値打ちが無いので、8-K を主たる入口にはしない。
- トヨタは **SEC に 20-F を出している**（CIK 0001094517）。年1回だが一次資料なので、
  出ている時期はこちらを優先する。

## 4. 外れた見立て（同じ道を二度通らないために）

- 「UA を見て弾いているのだろう」と推測で入口を決めて2回失敗した。
  以後は**必ず取得役で実際に開いてから**プロンプトに載せる。
- 「日本語の語で本文を探す」判定を英語のサイトに当てたため、
  stockanalysis を「中身なし」と誤判定した。英語の見出し（Capital expenditures など）で測り直して発見した。

## 5. 未測定・持ち越し

- ブラウザ UA 側の挙動は、必要になった出典しか測っていない。
- 各ホストが将来も同じ扱いをする保証は無い。**入口を変えるときは、その都度この表を測り直す。**
