## 10. 「どの根の枝か」を書かせる形式

### 10.1 案

出来事ごと（`follows` の次）：

```
  "follows":null,
  "roots":["rt_hormuz","rt_sanction"],
  "rootsMore":null
```

- `roots`：根の id を 0〜2個、関係が強い順
- `rootsMore`：3本目を付けたくなったときの id を1つ（無ければ null）。アプリは付けない。数えて結果に「3本目を付けたかった 1件（rt_…）」と出す
- 当てはまらないとき：`"roots": []`。出力形式の下の「〜のとき」の並びに「どの根にも入らないとき： "roots": []」を足す（今の today・same・follows と同じ書き方）
- 候補（11 の条件の日だけ）は一番上の段に：

```
"same":[…],
"newRoot":[{"name":"...","line":"...","cards":["w_...","#2"],"why":"..."}],
"today":[…],
"checked":[…]
```

### 10.2 今の出力形式との整合（コードを読んで）

- **番号の書き方**：same・follows は `w_…`、today と after は `"#番号"`。newRoot の cards は両方あり得る（すでにある札と、この JSON の出来事）ので両方を受ける。roots は根の id（`rt_…`）だけ
- **知らない番号**：same は「番号が見つからない」も捨てずに記録している。roots も同じにし、一覧に無い id は札に付けず、結果に「根の番号が見つからない N件」。**名前を書いてきたときに名前で引き当てるかは、決めが要る**（引き当てると表記ゆれは吸収できるが、根が増えたときに誤って付く）
- **初期投入**：same・today は初期投入には付けていない。roots も付けないのが揃う。ただし、そうすると初期投入・問いから作った札・自分で作った札（今は計53枚）には根が付かない。**→ 足りない論点**：読む回で「根の無い札」に根を付けさせるか（下の 12.4）
- **続報**：follows で前の札を指しても、前の札の根は自動では引き継がない（チャットが書いた roots をそのまま使う）。食い違ったら結果に数だけ出す
  - 失うもの：チャットが続報の roots を空にすると、話の続きなのに根から外れる。引き継ぐ形にすると、前の札の根が間違っていたときに誤りが広がる
- **same の件**：札にならないので roots は要らない（書かせない）
- **月ファイルの知らない欄を残す**（v20.48 で入れた）ので、roots を足しても v20.48 以降の端末は消さない。**v20.47 以前の端末が札を書き直すと roots が消える**（札の欄を整える所が知らない欄を落とすかは、今回コードで確かめていない。仕様の前に確かめる）

### 推奨：上の形

- **失うもの**：3本目の中身（どの根か）は数だけで、札には残らない（残すなら欄が1つ増える）。1行ずつの `"roots"` と形式の決まり行で約67字、規則で約295字増える

### 11.3 「根なしかつ核」の条件について

- 表では0回だが、**今の取り込みには「核かどうか」を書く欄が無い**ので、アプリは数えられない。核の印を足すと、それはそれで判断が揺れる（評価B の迷い印は核43枚中22枚）
- 反対：核を条件にするのは今の段では勧めない

### 11.4 「同じ候補が複数回出たら」について

- 候補を毎回出させて、2回出たら人に見せる形。**名前は回ごとにずれる**ので、名前でなく「まとまる札の id が重なっているか」で同じと見る必要がある
- 失うもの：毎回の節（約300字＋一覧）が要り、11.1 のとおりほぼ毎回候補が返る。見せない候補が作業ファイルに溜まる

### 推奨

1. 候補の節は**毎回は入れない**。アプリが、根に入らなかった札（重複・続報で same にしたものは札にならないので自然に除かれる。続報で follows のある札も除く）を数え、**3枚以上たまった日だけ**、その札の一覧（直近30日）と節を足す
2. 規則：「2枚以上が1本の話（誰が得をし、誰が払うかが同じ）にまとまるときだけ候補を1つ」「1社・1国・1回きりは候補にしない」「立っている根の言い換えなら候補にせず roots に書く」
3. 候補を出した（または `newRoot: []` が返った）ら数え直す。人が押さなかった候補は消さず、次の節には渡さない

- **失うもの**：1枚だけで根になる大きな出来事（例：開戦・大きな制度の発動）は、3枚たまるまで候補にならない。表では B8 以降そういう札は0枚だったが、4日分なので長い目では**測れません**。取り込みのたびに「根に入らなかった札 N枚（あと M枚で候補を聞きます）」を結果に出す必要がある（黙って溜まる形にしない）

- 返ってくる JSON（132件に根0〜2個と核の印）：**約8,600字**（評価B の振り分けを入れた形で作って数えた）
- 半分ずつ（作った順）にすると、fact＋why＋お金＋主体名で 11,067字と 11,398字

### 17.2 1回で渡せるか

- 字数では**1回で渡せる**。fact＋why＋お金＋主体名（23,689字）は、毎朝貼っている取り込みプロンプト（25,439字）より短い
- 心配は入れる側より**返す側**：132件を1つも落とさず返すか。132件の JSON は約8,600字で、今の読む回の返事（20枚）より長い。途中で省く・まとめる（「残りも同様」）おそれがある（推測。**測れません**）
- fact だけでは足りない：評価B では「根そのものが why に散っている」（関税の水準・米国の支援停止）。why を渡さないと、根の始まりが見えない
- 主体の「した」と読みまで渡すのは、根を割るには要らない（読みは推定なので、根を読みで切る誤りを呼ぶ、推測）

### 17.3 分けると根の名前がずれる問題

- 分けて「根も立てて、割って」を2回頼むと、1回目の「ホルムズ・紅海の詰まり」と2回目の「中東の供給途絶」が同じ根か、アプリにも人にも決められない
- 対処は**根を立てる段と、割る段を分ける**こと。割る段は、決まった id の一覧から選ばせる（取り込みで roots を書かせるのと同じ形）。これなら何回に分けても名前はずれない

### 推奨：2段

- **段A（根を立てる）**：132枚を fact＋why で渡し（約17,900字）、根を8〜12本、名前・1行・出発点（札が無ければ why の言葉で）を返させる。参考の根10本は「そのまま使わない」と書いて渡す。→ 人が10本前後に決め、id を振る
- **段B（割る）**：決めた根の一覧（名前＋1行）で、132枚を fact＋why＋お金＋主体名で渡し（約24,000字）、札ごとに roots（0〜2・強い順）・more・core を返させる。1回で渡す。返事が途中で切れたら、返らなかった札だけをもう一度渡す（id で分かる）
- **失うもの**：
  - 貼る回数が段A 1回＋段B 2回（18）で最低3回、段A も2回にすると4回
  - 段B は人が決めた根の一覧に縛られるので、「チャットが割ると、そもそも違う根になった」ことは段A でしか見えない
  - 段A で人が決める手間（10本前後を選ぶ・名前を直す）が1回入る

## 18. 2回割らせて食い違いを見る

### 18.1 どう2回割らせるか

| 方法 | 見えるもの | 失うもの |
|---|---|---|
| 同じプロンプトで2回（別のチャット） | チャットの揺れ | 並び順のくせ（先に読んだ札から根を作る）は2回とも同じに出て、見えない |
| **2回目は札の順を逆にする**（別のチャット） | 揺れ＋並び順のくせ | 食い違いの原因が「揺れ」か「順」か分けられない |
| 聞き方を変える（札ごとに根 ↔ 根ごとに札） | 形式の違いによるずれ | 本当に迷う札ではなく、形式のせいで食い違う札が混じる。勧めない |

- **根まで毎回作らせて2回比べるのは反対**：根の切り方が回ごとに違うと、札の食い違いのほとんどが「根の対応が取れない」ことから来て、人が見る札が多くなりすぎる（推測 50〜80枚）
- 3.5 の「2回、別々に割らせる」は、**段B（根の一覧を決めた後の割り振り）を2回**と読むのを勧める。根そのものの揺れを見たいなら、段A も2回して、根の一覧どうしを比べる（10本ほどなので人がすぐ見られる）

### 18.2 食い違いの見込み（推測）

**推測。** 評価B の表の数（実測）を元にした見立て：

- 根が2本の札 14枚（2本目の有無・順が揺れやすい）
- 根に入らなかった札 12枚（どこかの根に入れられやすい。ICC・安保理 → F など）
- 根が1本で、核が全部迷いの根（E 関税・H 外貨・I 円安・J 資産）に掛かる札 27枚
- 迷いの印48枚のうち、根が1本の札が40枚。ただし迷いの多くは「核か枝葉か」の迷いで、どの根かの迷いではない
- 大きな根（A 29枚・F 21枚・D 19枚）は中身がはっきりしていて揺れにくい

食い違いを「根の組（0〜2個、順は見ない）が違う札」と数えると、
- **段B（根を固定）を2回：25〜40枚（132枚の19〜30%）**
- 根も毎回作らせて2回：50〜80枚
- 順まで比べる（1本目が違う）と、段B でさらに5〜10枚増える

### 18.3 画面か作業用ファイルか

**推奨：作業用ファイル。**
- 2回分の返事を貼ったものから、食い違った札だけを表にする（札の fact・why・1回目の根・2回目の根・評価B の見立て）。人はその表を見て、札ごとに根を決める。決めたものを1つの JSON にしてアプリに入れる
- 1回きりの作業のために画面を作ると、その画面は割り直しの後に使われなくなる（押しても何も起きないボタンに近づく）
- **失うもの**：
  - PC で Claude Code のセッションを開かないと見られない。iPhone だけでは進められない
  - 後で根の切り方が粗くなったとき（rootsMore が溜まったとき）に、また割り直す道具がアプリに残らない
  - アプリに根を入れる入口（JSON を貼る所）は、どちらにしても作る必要がある

## 測れないこと

- 根の一覧を足したとき、チャットがほかの規則（flow の下限・same・today）をどれだけ読まなくなるか
- チャットが132件を落とさず返すか、候補の節を入れた日に本当に `[]` を返すか
- 数字と決算の節の実際の字数（通信しないので入らない。コードの注記の値を使った）
- 根の本物の文の長さ（仮の文で測った）
- 候補の条件の当てはめは4日分・19回だけ。根が長い目で本当に根か、新しい根が何か月に1本来るかは分からない
