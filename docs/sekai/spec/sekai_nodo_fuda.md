## 1. 戻した記録の日付（hiduke 1）

### 1.1 決まり

| 書かれた形 | 持ち方 | 表示 | 色 |
|---|---|---|---|
| `2026-08-05`（年月日で、ある日） | 日付の欄 `date` | 2026-08-05 | ふつう |
| **`2026-02`（月まで）** | **日付の欄 `date`**（今は元の文字の欄 `dateRaw` に移していた） | **2026年2月** | ふつう |
| `2026-02-30`（無い日）・`2025`・`2026-Q1`・「2026年春」など | 元の文字の欄 `dateRaw` | 日付の書き方：2026年春 | **薄い字** |
| 空 | 無し | 出さない | — |

- 月は 01〜12 だけ。`2026-13` は「ほかの形」
- 今ある8件（すべて `dateRaw` に `YYYY-MM`）は、**読み込むときに `date` として扱う**。保存されている文字は変えない（次にその月のファイルを書くとき、`date` の欄に移る。中身の文字は同じ）

### 1.2 赤い字（hiduke 1）

| 印 | 今 | v20.45 |
|---|---|---|
| url の形が正しくないので出典なし | 赤 | **赤のまま** |
| 長くて切りました | 赤 | **赤のまま** |
| 日付の形が正しくない | 赤 | **やめる**（月までは正しい形。ほかの形は薄い字の「日付の書き方」） |
| 書かれていた種類：… | 赤 | **薄い字**に（間違いではなく、チャットが書いた言葉のまま残しているだけなので） |

取り込んだあとの1行の「日付の形が正しくない N件」も、「日付の書き方が年月日・年月でない N件」に変える（月までは数えない）。

## 3. 札にする欄

### 3.1 並び

```
 ┌ 札にする ──────────────────────────────
 │ 何が起きたか（40字まで） [……………………]  22/40   チャット
 │ 日付 [2026-02]  ( ) 年月日  (•) 月まで（日は分からない）   チャット
 │   この日付だと地図（直近90日）に出ません
 │ 動かした側 [アル・ハラフィ社]                         チャット
 │ お金の動き（地図の線の元。入れないと札を作れません）
 │   出す側 [          ]  受け取る側 [          ]          自分で入力
 │   何 [          ]  額 [          ]
 │ 出典 [pv magazine 2026-08-07]                         チャット
 │ url  [https://www.pv-magazine.com/…]                  チャット
 │ ［url を開く］ ［書いてあった］ ［開けなかった・書いてなかった］
 │ 元の札とのつながり ( ) この動きの前 ( ) この動きの後 (•) どちらでもない
 │ ［チャットの値に戻す］                ［札を作る］
 │ （状態の1行）
 └──────────────────────────────────────
```

- 欄の右に「チャット」か「自分で入力」を出す。**入れ直すたびにその場で変わる**（3.3）
- お金の動きの欄が空の件（シリアの記録など）は、最初から「自分で入力」の枠として出し、見出しに「入れないと札を作れません」

### 3.2 押せる・押せない

| 条件 | ［札を作る］ |
|---|---|
| 何が起きたかが空、または40字を超える | 押せない（「40字までにしてください（今 52字）」） |
| 日付が「年月日」なのに年月日の形でない／無い日／今日より後 | 押せない |
| 日付が「月まで」なのに YYYY-MM の形でない／今月より後 | 押せない |
| お金の動きの「出す側」「受け取る側」の**どちらも空** | 押せない（「お金の動きの出す側か受け取る側を入れてください」） |
| url が空 | 押せない |
| url を開いて［書いてあった］を押していない（前の仕様書 4.3 のまま） | 押せない |
| 上が全部そろった | **押せる** |

- 何・額は空でもよい（今の札も、額の無い動きを持てる。額が無いと地図では細い点線）
- ［チャットの値に戻す］（足4）：全部の欄を戻した記録の値に戻し、印を「チャット」に戻す。url を開いた印も消える（url が変わるため）

### 3.3 誰が入れたか（hiduke 3・足1）

**欄ごとに、札にする瞬間の値を戻した記録の値と比べて決める。**

| 欄 | 「チャット」 | 「自分で入力」 |
|---|---|---|
| 何が起きたか | 記録の文と1文字も違わない | 1文字でも違う（短くしたときも） |
| 日付 | 記録の日付と同じ | 違う・記録に無かった |
| 動かした側 | 記録と同じ | 違う・記録に無かった |
| お金の動き（出す側・受け取る側・何・額を別々に） | 記録の flow のその欄と同じ | 違う・記録に無かった |
| 出典 | 記録と同じ | 違う・記録に無かった |
| url | 記録の url と同じ（`urlBy: 'chat'`） | 人が貼った（`urlBy: 'self'`） |

- 空の欄は「無し」（誰も入れていない）
- これは「どちらが入れたか」を残すだけで、値が正しいかは判定しない
- 失うもの：チャットの文を1文字だけ直しても「自分で入力」になる（言い換えの程度は区別しない）。**40字に縮めた「何が起きたか」は必ず「自分で入力」になる**

### 3.4 残す場所（hiduke 3「記録にも札にも」・足2）

**戻した記録の件**（前の仕様書 4.7 に足す）：

| 欄 | 中身 |
|---|---|
| cardId・cardAt・rel・urlBy・urlCheckedAt・urlChecked・urlFailed | 前の仕様書のまま |
| **cardBy** | 札にしたときの、欄ごとの誰が入れたか：`{ fact, date, actor, from, to, what, amount, source, url }` それぞれ `chat`・`self`・空 |
| **cardValues** | 札にした瞬間の値（何が起きたか・日付・動かした側・お金の動き4つ・出典・url）。記録の元の値は消さずに残るので、並べると何を直したかが分かる |
| **datePrec** | `month`（月まで）・`day`（年月日） |

**作った札の中**（足2。今の札の欄は変えず、自分で作った札だけに1つ足す）：

```
"self": { "digId": "dg_…", "by": { "fact": "self", "amount": "self", "from": "chat", … }, "datePrec": "month" }
```

- 札を開くと、一番上に「自分で調べて作った札（元の札：…）」、その下に「自分で入れた値：何が起きたか・額」の1行（`self` の欄の名前を並べる。全部チャットなら「値は全部チャットが書いたもの」）
- お金の動きの1行で、自分で入れた欄に「（自分で入力）」を添える。例：`アル・ハラフィ社 → シリア電力公社　売電　（額：自分で入力）`
- 表示は記録（`cardBy`）を先に見て、無ければ札の `self` を見る
- **失うもの：札の中に欄が1つ増える**（自分で作った札だけ）。v20.44 以前の版の端末がその月のファイルを書き直すと、この欄は落ちる（札の欄を決まった名前だけ残す作りのため）。**記録の側に同じものがあるので表示は変わらない**が、札のファイルだけを見たときの印は消える。**両端末を v20.45 にしてから札にしてほしい**

## 4. 月までの札（hiduke 2）

### 4.1 札の日付と表示（足3）

- 札の日付（eventDate）は月の1日（`2026-02-01`）。番号 `w_20260201_…`・月ファイル 2026-02 は今の決まりのまま
- 日付を出す所を1つの関数にまとめ、札が月までなら「2026年2月（日は分からない）」、一覧の短い表示では「2026年2月」
  - 使う所：札の一覧の左の日付・札を開いたとき・主体の時系列・つながる札・調べたことの一覧
  - **ほかの所（朝の「今日動いた主体」の畳んだ行など、札の日付を「2/1」の形で出している所）で、全部を今回直すかは実装のとき数えて報告する**（今、日付を短く出す所は29か所ある）
- プロンプトの素材（朝の取り込み・読む回・問い・［Claude に聞く］・まとめの依頼文）で札の日付を書く所も、月までなら「2026-02（日は分からない）」

### 4.2 地図（hiduke 2）

- 地図の元の関数で「直近90日（小さな地図は7日）に入るか」を比べている所を1か所だけ変える
  - 今：`札の日付 >= 期間の最初の日`
  - v20.45：月までの札は `その月の最後の日 >= 期間の最初の日`
- 例：今日 9/14、期間の最初は 6/16 → 月までの `2026-06` の札は 6/30 で判定して**描く**。`2026-05` は 5/31 で**描かない**
- **失うもの（回答書で受け入れ済み）**：実際は 6/2 の出来事でも描かれる（1か月ぶん広めに入る）
- 線の位置は出す側・受け取る側の国で決まるので、日が無くても引ける。国が分からなければ今と同じく「場所不明」

### 4.3 重複の確かめ（hiduke 2）

- 今：札の日付の前後3日に、url が同じか文が似ている札があれば重複
- v20.45：月までの札は、**その月の1日〜最後の日**（と前後3日）を見る
- 例：「2026年2月にサウジとシリアが投資協定」を札にするとき、AI が集めた「2026-02-16 サウジがシリアと投資協定」があれば「似た札がもうあります」
- 失うもの：月の中に別の似た出来事があると、重複と言われて札にできないことがある。**そのときは理由と相手の札を出す**（黙って落とさない）

## 6. 確かめ

**手元の試し**
- 日付：`2026-02` → date・「2026年2月」・赤なし／`2026-13`・`2025`・`2026-02-30`・「2026年春」→ dateRaw・薄い字／今ある `dateRaw: "2026-02"` が読み込みで date になる
- 札にする欄の出る・出ない（2章の表）、押せる・押せない（3.2 の表）
- 誰が入れたか：何も直さない → 全部チャット／何が起きたかを縮める → fact だけ自分／額を足す → amount だけ自分／［チャットの値に戻す］→ 全部チャットに戻る
- 作った札：`self` の欄・日付 `2026-02-01`・`datePrec: month`／元の札の文字列が作る前と1文字も違わない
- 地図：今日を 9/14 にして、`2026-06` の月までの札は描く・`2026-05` は描かない・`2026-06-01` の年月日の札は描かない
- 重複：月までの `2026-02` と、既存の `2026-02-16` の似た札 → 重複。`2026-03-01` の似た札 → 重複しない（月の外で前後3日も外）

**偽の GitHub と2台に見立てたブラウザ**

- 開けない url：［開けなかった・書いてなかった］→ url が空・記録に残る
