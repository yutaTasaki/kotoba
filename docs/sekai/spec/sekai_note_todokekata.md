## 0. 決まったこと（質問し直さない）

### 0.1 読者と記事

| # | 決まり |
|---|---|
| 1 | 読者は**ほとんど何も知らない**（ニュースの見出しを見たことがある程度）。アプリの中の決まりや言葉は一切知らない |
| 2 | 連載の芯：**言っていることと、実際に動くモノ（お金・人・物）は違う**。連載名は後で決める（そのとき複数案を出す） |
| 3 | 長さ：**通勤中に読める**（本文 約2,000字・4〜5分） |
| 4 | **毎日投稿**する |
| 5 | 本文は Claude が書く。本人は最小限直して note に貼る |

### 0.2 記事の部品

| 部品 | 決まり |
|---|---|
| サムネ | 本人が画像生成AIで作る。アプリは**複数案（絵の中身・サムネの文字・プロンプト）**を出す。**サムネ単体で興味を引く。タイトルは補助** |
| タイトル | 複数案から選ぶ |
| Plot Promise | ①何の食い違いか ②誰の思惑か ③**次のニュースで使える見方**。③は毎回入れ、最後に必ず回収する |
| 冒頭 | イントロと一体。最初に一番強い食い違い、続けて前提を最低限（3つまで・1つ1文） |
| 本文 | 立場ごとの語り → 実際の動き → 思惑（推測） → 次のニュースで見るところ |
| 言い切り | **「こうなるはず」と言い切らない**。どこまでも推測。「もしこの読みが当たっているなら、〜が見えてくるかもしれない」「次のニュースで見ておきたいのは〜」 |
| 出典 | **文章の塊ごとに、その直後**に置く。最後にまとめない |
| 図 | 塊2〜3つごとに1枚、全部で3〜4枚。型はその都度合うもの（グラフ・地図・構図・資料） |
| グラフ | **数値データから Claude に描かせる**（画像生成AIは数字や日本語を崩すため）。地図・構図・資料は画像生成AI |

### 0.3 確かさの書き分け

| 確かさ | 記事での書き方 |
|---|---|
| 一次資料・数字で確かめられる | 事実として書く（出典つき） |
| 報道だけ | 「〇〇（媒体名）によると」と、誰が言ったかを必ず付ける |
| 未確認・食い違いがある・見出しだけしか読めていない | **結論の根拠に使わない**。使うときは「確かめられていない話」と書き、**なぜ出回っているのか・流して得をするのは誰か**として扱う |

### 0.4 作り方

- **実際に書くのは Claude。アプリは中継**（依頼文のコピー・返事の取り込み・選ぶ・最後のコピー）
- **機能ごとに依頼文を分け、往復する**（5回でいったん試す）
- 確かめの返事は**シンプルな形**にする

## 1. 段3-0：語り方の依頼文の直し（開けなかった媒体の代わり）

語り方の依頼文（v20.72）の「集める媒体」の例を、**国ごと・持ち主ごとの近い媒体の一覧**に置き換える。開けなかったら同じ行の別の媒体を順に試し、試したものは全部残させる。

```
■ 開けなかったときに当たる、近い立場の媒体（同じ行の中で順に試す）
- イラン・政府系：IRNA／Tehran Times／Press TV
- イラン・革命防衛隊系：Tasnim／Fars
- ロシア・国営：TASS／RIA Novosti／RT
- ロシア・民間：Interfax／Kommersant
- 中国・国営：新華社／CGTN／China Daily
- 中国・党系：環球時報／人民日報
- イスラエル・民間：Times of Israel／Jerusalem Post／Haaretz
- サウジ・政府寄り：Arab News／Asharq Al-Awsat／Saudi Gazette
- カタール・政府寄り：アルジャジーラ／Al Araby
- UAE・政府寄り：The National／Gulf News
- トルコ・政府寄り：Daily Sabah／Anadolu
- インド・民間：The Hindu／Times of India／Hindustan Times

## 2. 往復2：企画

### 2.1 依頼文に渡すもの
- 札に元から書いてあったこと（語り方の依頼文と同じ組み立て）
- 語り方の記録の全部（媒体の表・動き・割れ方・思惑・問い・仕組み・疑い）
- 記事の決まり（0章。企画に関わるものだけ）

### 2.2 頼むこと
- **日本での伝わり方を調べる**：日本の大手報道（NHK・日経など）でこの出来事がどう報じられたか。見出しだけでよい。報じられていなければ「報じられていない」
- **読者との差（gap）**：読者が知っていそうなこと（上の見出しの水準）／知らないこと（立場による語りの違い・動きとの食い違い・誰の思惑か）
- **サムネ案 3〜5**：1つずつ、サムネの文字（15字以内）・絵の中身（1〜2文）・画像生成AIに渡すプロンプト・なぜ目を引くか。**サムネ単体で興味を引く**こと。タイトルと同じことを言わない
- **タイトル案 10〜20**：型を混ぜる（食い違い型・逆説型・身近型・数字型・対立型）。26字以内を目安（note の一覧で切れにくい）。サムネを補う
- **Plot Promise**：①何の食い違いか ②誰の思惑か ③次のニュースで使える見方（各1文）
- **食い違って見える数字は、自分で計算して本当に食い違いかを確かめる**（試作で、隻数と日量が両立しうることがいちばん面白い所になった）
- **冒頭案 2〜3**：一番強い食い違いから入り、前提を最低限（3つまで）。1案250字以内

### 2.3 返事（JSON）
```
{"eventId":"w_…",
 "jpNews":[{"name":"","headline":"","url":""}],
 "gap":{"known":"","unknown":""},
 "thumbs":[{"text":"","picture":"","prompt":"","why":""}],
 "titles":[{"text":"","type":""}],
 "promise":{"what":"","who":"","lens":""},
 "intros":[{"text":""}]}
```

### 2.4 画面
- サムネ案・タイトル案・冒頭案を**1つずつ選ぶ**（押すだけ）。Plot Promise と読者との差は読むだけ
- 選んだら［本文を書く依頼文をコピー］が出る

## 3. 往復3：本文

### 3.1 依頼文に渡すもの
- 選んだサムネの文字・タイトル・冒頭、Plot Promise、読者との差
- 語り方の記録の全部（媒体・url・日付・開けたか）
- 札の確かさ（札の確度と、語り方で見出しだけだった媒体）

### 3.2 決まり（依頼文にそのまま書く）
- 約2,000字。見出しは `##` だけ。太字と箇条書きは使ってよい。表は使わない（note に貼ったとき崩れるおそれ）
- 冒頭は選んだ冒頭をそのまま使う（言い回しの調整はよい）
- 流れ：冒頭 → 立場ごとの語り → 実際の動き → 思惑（推測） → 次のニュースで見るところ（Plot Promise ③の回収）
- **出典は文章の塊ごとに、その直後に1行**：`（出典：媒体名・日付 url）`
- 確かさの書き分け（0.3 の表をそのまま渡す）
- 言い切らない（0.2 の例を渡す）
- **使わない言葉**：幹・枝・葉・札・ずれ・確度・語り方・読む回・取り込み（アプリの中の言葉。読者は知らない）
- 専門用語は、出てきた所で1文で説明する
- **数字は url を開いて確かめてから使う。開けなければ「〜と報じられている」にする**（試作で、検索の要約だけの数字が元の記事と違っていた）
- 図を入れる場所に `［図1：型・何を見せるか］` を置く。塊2〜3つごとに1枚、全部で3〜4枚。型は グラフ・地図・構図・資料 のどれか
- 返事は**本文だけ**（マークダウン）。最初の行を `# タイトル` にする

### 3.3 画面
- 貼る欄に本文をそのまま貼る（JSON ではない）
- 取り込むと、字数・図の印の数・出典の行の数・使わない言葉が混ざっていないかを**アプリが数えて1行で出す**（機械で分かることは機械で見る）
- ［図の依頼文をコピー］が出る

## 4. 往復4：図

### 4.1 頼むこと
本文の `［図N：…］` ごとに：
- 型（グラフ・地図・構図・資料）と、読者に何を一目で分からせるか（1文）
- **グラフ**：数値データ（項目・値・単位・出典）と、**Claude にグラフを描かせる依頼文**（数値はデータのまま、日本語の文字は短く）
- **地図・構図・資料**：画像生成AIに渡すプロンプトと、絵の中に入れる文字（できるだけ少なく、数字は入れない）

### 4.2 返事（JSON）
```
{"figs":[{"n":1,"type":"グラフ","show":"",
          "data":[{"label":"","value":"","unit":"","source":""}],
          "prompt":"","text":[""]}]}
```

### 4.3 画面
- 図ごとに［プロンプトをコピー］。グラフは「Claude に貼る」、それ以外は「画像生成AIに貼る」と書き分ける
- 本文の印の数と図の数が合わなければ1行で知らせる

## 5. 往復5：確かめ

### 5.1 渡すもの
- 本文・図の一覧・語り方の記録（出典の元）

### 5.2 点検すること
- 本文の数字と媒体を、url を開き直して確かめる（開けなければ「報じられている」の形か）
- 言い切り（「〜になる」「〜に違いない」「〜はず」）
- 出典の無い塊
- 確かめられていない話が、結論の根拠になっていないか
- 語り方の記録に無い数字・媒体が本文に出ていないか
- アプリの中の言葉が混ざっていないか
- Plot Promise の3つが本文で回収されているか
- タイトル・サムネの約束と中身がずれていないか

### 5.3 返事（シンプルな形。JSON ではない）
```
直した点：3
- 「〜になるはず」→「〜が見えてくるかもしれない」（言い切り）
- 第3段落に出典が無い → 語り方の記録の Kpler の行を足した
- 「確度」→ 削った（アプリの言葉）
---本文---
# タイトル
（直した本文の全部）
```
- 直す点が無ければ `直した点：0` の後に `---本文---` と本文
- 1点1行。理由は（）に一言

### 5.4 画面：できあがり
```
今日の記事（9/17）
タイトル　　　　　　　　　［コピー］
サムネの文字・プロンプト　［コピー］

図1 グラフ（Claude に貼る）［コピー］
図2 地図（画像生成AIに貼る）［コピー］
…
［note に出した］← 押すと出した日を残す

## 7. 失うもの・心配

- **毎日6往復**（語り方＋企画＋本文＋図＋確かめ＋あなたの画像づくり）。Pro の使用量がいちばんの心配。**1週間の使用量を見て、往復を減らすか決める**（減らすなら、図を本文に入れる、の順）
- 記事の画面が1つ増える
- 画像生成AIとグラフ描きは、アプリの外（あなたの手元）

## 8. 確かめ方

- 手元：本物の写しで依頼文4つを作り、返事の形（試作の返事）を取り込み、画面で選ぶ・コピーする・字数の数えを押して確かめる
- 実機：1本目を通しで作り、どの往復で手が止まったか・直した量を報告してもらう
