## 2. 往復2：企画

### 2.1 依頼文に渡すもの
- 札に元から書いてあったこと（語り方の依頼文と同じ組み立て）
- 語り方の記録の全部（媒体の表・動き・割れ方・思惑・問い・仕組み・疑い）
- 記事の決まり（0章。企画に関わるものだけ）

### 2.2 頼むこと
- **日本での伝わり方を調べる**：日本の大手報道（NHK・日経など）でこの出来事がどう報じられたか。見出しだけでよい。報じられていなければ「報じられていない」
- **読者との差（gap）**：読者が知っていそうなこと（上の見出しの水準）／知らないこと（立場による語りの違い・動きとの食い違い・誰の思惑か）
- **サムネ案 3〜5**：1つずつ、サムネの文字（15字以内）・絵の中身（1〜2文）・画像生成AIに渡すプロンプト・なぜ目を引くか。**サムネ単体で興味を引く**こと。タイトルと同じことを言わない
- **タイトル案 10〜20**：型を混ぜる（食い違い型・逆説型・身近型・数字型・対立型）。26字以内を目安（note の一覧で切れにくい）。サムネを補う
- **Plot Promise**：①何の食い違いか ②誰の思惑か ③次のニュースで使える見方（各1文）
- **食い違って見える数字は、自分で計算して本当に食い違いかを確かめる**（試作で、隻数と日量が両立しうることがいちばん面白い所になった）
- **冒頭案 2〜3**：一番強い食い違いから入り、前提を最低限（3つまで）。1案250字以内

### 2.3 返事（JSON）
```
{"eventId":"w_…",
 "jpNews":[{"name":"","headline":"","url":""}],
 "gap":{"known":"","unknown":""},
 "thumbs":[{"text":"","picture":"","prompt":"","why":""}],
 "titles":[{"text":"","type":""}],
 "promise":{"what":"","who":"","lens":""},
 "intros":[{"text":""}]}
```

### 2.4 画面
- サムネ案・タイトル案・冒頭案を**1つずつ選ぶ**（押すだけ）。Plot Promise と読者との差は読むだけ
- 選んだら［本文を書く依頼文をコピー］が出る

## 3. 往復3：本文

### 3.1 依頼文に渡すもの
- 選んだサムネの文字・タイトル・冒頭、Plot Promise、読者との差
- 語り方の記録の全部（媒体・url・日付・開けたか）
- 札の確かさ（札の確度と、語り方で見出しだけだった媒体）

### 3.2 決まり（依頼文にそのまま書く）
- 本文は1,500〜2,500字（出典の行・見出し・図の印は数えない）。見出しは `##` だけ。太字と箇条書きは使ってよい。表は使わない（note に貼ったとき崩れるおそれ）
- 冒頭は選んだ冒頭をそのまま使う（言い回しの調整はよい）
- 流れ：冒頭 → 立場ごとの語り → 実際の動き → 思惑（推測） → 次のニュースで見るところ（Plot Promise ③の回収）
- **出典は文章の塊ごとに、その直後に1行**：`（出典：媒体名・日付 url）`
- 確かさの書き分け（0.3 の表をそのまま渡す）
- 言い切らない（0.2 の例を渡す）
- **使わない言葉**：幹・枝・葉・札・ずれ・確度・語り方・読む回・取り込み（アプリの中の言葉。読者は知らない）
- 専門用語は、出てきた所で1文で説明する
- **数字は url を開いて確かめてから使う。開けなければ「〜と報じられている」にする**（試作で、検索の要約だけの数字が元の記事と違っていた）
- 図を入れる場所に `［図1：型・何を見せるか］` を置く。塊2〜3つごとに1枚、全部で3〜4枚。型は グラフ・地図・構図・資料 のどれか
- 返事は**本文だけ**（マークダウン）。最初の行を `# タイトル` にする

### 3.3 画面
- 貼る欄に本文をそのまま貼る（JSON ではない）
- 取り込むと、字数（下限より短い・上限より長いときは知らせる）・図の印の数・出典の行の数・使わない言葉が混ざっていないかを**アプリが数えて1行で出す**（機械で分かることは機械で見る）
- ［図の依頼文をコピー］が出る

## 5. 往復5：確かめ

### 5.1 渡すもの
- 本文・図の一覧・語り方の記録（出典の元）

### 5.2 点検すること
- 本文の数字と媒体を、url を開き直して確かめる（開けなければ「報じられている」の形か）
- 言い切り（「〜になる」「〜に違いない」「〜はず」）
- 出典の無い塊
- 確かめられていない話が、結論の根拠になっていないか
- 語り方の記録に無い数字・媒体が本文に出ていないか
- アプリの中の言葉が混ざっていないか
- Plot Promise の3つが本文で回収されているか

```
# タイトル

```

## 10. v20.75 の直し：高校生が読んでも分かる仕組み

本人の感想：つかみ案「日銀の金庫から、10日間で11兆円が消えました。でも、金利はほとんど動いていません」を読んでも、「日銀の金庫って？」「なんで金利が関係するの？」が分からない。本文も同じ。高校生が読んでも分かる仕組みが要る。

決まりを1つ足すのではなく、**3つの往復に役を分けた**：

| 往復 | 役 |
|---|---|
| 企画 | **引っかかる言葉と「なんで？」を5〜8つ書き出す**（questions：q と、高校生に分かる答え a）。言葉だけでなく「AとBがなぜつながるのか」を必ず入れる。**つかみは高校生が説明なしで分かる言葉だけ** |

| 確かめ | **高校生の目で、つかみから最後まで読み直す**。説明なしの言葉と、答えのない「なんで？」を全部直す |

- 読者の決まりを「高校生が読んでも分かる。経済や国際の言葉（金利・日銀・国債・制裁など）もほとんど知らない前提」に変えた

## 12. v20.77 マガジン（テーマ別）

## 13. v20.78 マガジンを幹にする

本人の判断：今の幹は見ていないので意味をなしていない。最初の幹は取り込んだ内容からしか作られていない。マガジンのほうがしっかりジャンル分けされている → **マガジンを幹にする**（マガジンが増えるたびに幹が増える）。決めたこと：①全部の札を割り直す（段B を2回）②幹の答えと根（出発点）を止める ③記事のマガジン＝札の幹を先に入れ、企画でチャットが「ほかにも入るマガジン」を足す。

| 項目 | 中身 |
|---|---|
| 切り替え | 設定 → 世界「幹を立てる（割り直し）」の［マガジンを幹にする］（2回押し）。今の幹を全部閉じ（`rename closed`。記録は残る）、マガジンの一覧から幹を立てる（`open`・`from: mag`・番号はマガジンの番号 mg_…）。そのあと段B（2回）で全部の札を割り直す |
| マガジン＝幹 | `from: mag` の幹が1本でも開いていれば、幹の一覧＝マガジンの一覧。［マガジンを足す］は幹を立てる |
| 依頼文の決まり | 朝の取り込み・段B・読む回の「幹に入らない札」で、「幹＝誰が得をし誰が払う話」を「マガジン＝読者向けのテーマ。そのテーマが好きな読者が読みたくなるかで選ぶ」に替える。芽は「新しいマガジンの案（〇〇の思惑の形）」 |
| 止めたもの | 幹の答え（読む回の答えの節・最初の答え）・根（朝の取り込みの出発点探し）・幹の新しい枝で読む回に誘う行・幹の画面の答えの欄と一覧の「答えはまだ」（`WORLD_MIKI_ANSWERS_ON = false`）。前の答え12件・根3件は記録に残る |
| 呼び名 | 世界の画面「マガジン N個・葉 N枚 ▸」、「今日動いたマガジン」、札の画面「マガジン：〇〇 ▸」、幹の一覧の題「マガジン（N）」 |
| 記事 | 記事のマガジン＝札のマガジン＋チャットが足したもの。企画の依頼文に「この出来事は、すでに『〇〇』に入っている。ほかにも入るものだけ書く」 |
| マガジンの一覧の画面 | マガジンごとに［札 N枚 ▸］（押すとそのマガジンの枝の画面）。切り替える前は「設定のその欄へ ▸」 |
