## 1. プロンプト

### 1.1 すでにある札の一覧

末尾（「最近のお金の動き」の後ろ）に：

```
■ すでにある札（取り込んだ日が直近14日の札。same・follows の id はここか「最近のお金の動き」から選ぶ）
w_20260911_2　9/11　サウジが紅海向けの原油パイプラインを止めた
w_20260910_1　9/10　ECBが政策金利を0.25%上げ、預金金利2.50%に
…
```

- **対象**：取り込んだ日（札を作った日）が今日を含めて直近14日の札。初期投入の札・自分で作った札・非表示の札も含む（非表示の札を戻さないため。今の重複弾きも非表示の札を見ている）
- **並び**：作った日時の新しい順。上限100件
- **重ねない**（足1）：「最近のお金の動き」に出ている札は、この一覧に出さない
- **1行**：札の番号・出来事の日付（今の年なら M/D）・何が起きたか（fact）
- **定数**（回答書1）：`WORLD_KNOWN_CARDS_DAYS = 14`、`WORLD_KNOWN_CARDS_MAX = 100` を1か所に置く
- **朝の取り込みと取り込む画面の［プロンプトをコピー］の両方**に付ける（同じ1本を通っている）
- **初期投入には付けない**（足8）：地域ごとに90日を集める回で、直近14日の一覧とは合わない。重複は今の弾きで落ちる
- 字数：実データ（9/14）で数えた見込みは、一覧 **+4,453字**（102件）と、1.2 の規則で約700字。**実装したら前後を実データで測って報告する**

### 1.2 規則の節

「■ 並べ方」の前に：

```
■ すでにある札との関係（same・follows）
末尾の「すでにある札」「最近のお金の動き」は、もう札になっている出来事。
見つけた出来事を札にする前に、ここと見比べる。
- 同じ出来事なら、札にしない。"same" に1件ずつ書く。
  同じ出来事＝同じ主体が同じ時に同じことをした。媒体・言い回し・単位が違うだけ、
  または同じ発表から別の数字を取っただけで、新しい事実が無いもの。
  - id：同じだと判断した札の番号（w_ で始まる。一覧にある番号だけ）
  - fact：見つけた出来事を1行（札の fact と同じ書き方）
  - why：なぜ同じと判断したかを1行（40字以内）
  - url：見つけた出来事の出典ページ（分かれば）
- 続きなら、新しい札にして、その札の "follows" に続きの元の札の番号を書く。
  続き＝同じ話で、新しい事実（新しい日付の動き・新しい数字・新しい主体）があるもの。
  迷ったら続きにする（新しい事実を捨てない）。
- どちらでもなければ "follows": null。
```

- `after`（お金の動きの続き）とは別。`after` は今のまま
- 出力形式の例：各出来事に `"follows": null`、`events` の後に `"same":[{"id":"w_…","fact":"…","why":"…","url":"https://…"}]`
- 末尾の決まりの行に：`同じ出来事が無いとき： "same": []`、`続きでないとき： "follows": null`

### 1.3 コピーしたとき

- 取り込んだ日が14日以内の札が入っている月を、コピーする前に読み込む（足3）。見分け方：世界の索引の月ごとの更新日時が14日以内の月
- 読み込めなかった月があれば、コピーしたときの文に「読み込めなかった月 2026-06（その月の札は一覧に入っていません）」
- 上限で外れたら「すでにある札 100件を渡しました（上限で外れた札 12件）」（足2）。外れなければ「すでにある札 58件を渡しました」

## 2. 取り込み

### 2.1 same

`same` が配列で書かれていたら、1件ずつ読む。**札は作らない。**

| 欄 | 中身 |
|---|---|
| id | 書かれていた札の番号 |
| cardId | 端末で見つかった札の番号（見つからなければ空） |
| fact | 見つけた出来事（安全弁 WORLD_FACT_MAX 字。超えたら切って印） |
| why | 理由（120字まで。超えたら切って印） |
| url | 出典（安全な url でなければ、元の文字を urlRaw に残す） |
| gone | 番号が無い（一覧にも端末にも無い）・書かれていない |
| notSameAt | ［別の出来事だった］を押した日時（3.3） |
| cardMadeId | その場で作った札の番号（3.3） |

- **何も落とさない**：番号が無くても、fact が空でも、1件として残す（画面で「番号が無い」「何が起きたかが書かれていません」）
- 件数の上限は置かない（多ければ結果に「多かった」と出す。安全弁は50件で、超えても残す）
- 番号の確かめ：端末の札（月を読み込んでから）で探す。**一覧に出していない札の番号でも、端末にあれば同じ札とみなす**

### 2.2 follows

- 各出来事の `follows` が `w_…` の形で、端末にある札なら、新しい札との組を記録する
- 番号が無い・形が違う：組を作らず、数えて結果に出す（「続きの元が見つからなかった 1件」）。**札は作る**（続きの印だけが付かない）
- 自分自身・同じ JSON の中の札は指せない（`#N` は受けない）

### 2.3 記録の形

1回の取り込みで1つ、「取り込みの記録」を作る。`same` も `follows` も書かれていなければ作らない。

| 欄 | 中身 |
|---|---|
| id | `im_YYYYMMDD_` ＋ 乱数 |
| date / at | 取り込んだ日・日時 |
| batchId | その取り込みの番号（札の batchId と同じ） |
| sameReported | JSON に `same` が書かれていたか |
| same | 2.1 の並び |
| follows | `[{ cardId: 新しい札, follows: 元の札 }]` |
| followsMissing | 続きの元が見つからなかった件数 |

## 3. 画面

### 3.1 取り込みの結果の1行

今の結果の文（重複・今日見るべき件の後）に：

- 「**同じなので入れなかった 3件 ▸**」（押すと 3.3 の中身が開く）
- 0件：「同じなので入れなかった：0件」
- 書かれていない（足4）：「同じ出来事の報告なし（JSON に same がありません）」
- 番号が無い件があれば：「うち 1件は同じと判断した札が見つかりません」
- 続き：「続きの札 2件」、元が見つからなければ「続きの元が見つからなかった 1件」

### 3.2 取り込む画面の「最近、同じなので入れなかった出来事」（足5）

- 取り込む画面の、貼る欄の結果の下に「最近、同じなので入れなかった出来事（14日）12件 ▸」
- 押すと、取り込んだ日ごとに 3.3 の中身が並ぶ
- 1件も無ければ出さない
- 日数は 1.1 と同じ定数

### 3.3 中身の1件

```
┌──────────────────────────────
│ 見つけた出来事：ECBが預金金利を2.50%に引き上げた
│ 同じと判断した札：9/10 ECBが政策金利を0.25%上げ、預金金利2.50%に ▸
│ なぜ：同じ9/10の理事会の決定。別の媒体
│ 出典：https://…（押すと開く）
│ ［別の出来事だった］
└──────────────────────────────
```

- 「同じと判断した札」を押すと、その札が開く
- 番号が無い件：「同じと判断した札：w_…（見つかりません）」。押せない
- **［別の出来事だった］**（足6）：押すと記録に日時が残り、その場に札を作る欄が開く（v20.46 の［url を開く］→［書いてあった・札を作る］と同じ2押し。fact・出典・url は見つけた出来事から入り、日付は人が入れる。チャットが書いた欄は「チャットが書いた」と印）
  - 押しただけで札は作らない（作るのは［書いてあった・札を作る］を押したとき）
  - 札を作ったら「札にしました ▸」（押すとその札が開く）
- **1件ずつ「同じだった」を押す場所は作らない**（回答書7・守ること。既定は「同じとして受ける」、違うものだけ押す）

### 3.4 続きの印（札を開いたとき）

- 続きの札を開くと：「前の札：9/10 フーシ派が紅海の港町モカを制圧した ▸」
- 元の札を開くと：「続きの札 2枚 ▸」（押すと並べて出す）
- 段3で表示を畳むまで、一覧・地図・つながる札・主体の盤面は変えない

## 4. 置き場所

### 4.1 取り込みの記録

- **調べたことの月ファイル（`world/dig/YYYY-MM.json`）の `imports` に置く。** 月は取り込んだ日の月
- 理由：印と記録は札と別に置く。世界の索引に足すと古い版の端末が落とす。この月ファイルは 2台の合わせ方と「古い版が消しても新しい版が書き戻す」ことを v20.47 で確かめた
- 合わせ方：id ごと。同じ id は更新日時の新しい方（［別の出来事だった］を押すと更新日時が変わる）

### 4.2 知らない欄を残す（足7）

- 月ファイルを読むとき、知らない欄（`id` を持つ記録の並び）を捨てずに持ち、書くときに戻す。2台で合わせるときは id ごとに足し合わせる
- 理由：v20.47 の端末は `imports` を知らないので落とす。この版で直しておけば、段2・段3で欄を足しても v20.48 以降の端末は消さない
- 失うもの：知らない欄の中身の形は確かめない（壊れた形でもそのまま残る）

### 段1を何回か流したあとに測ること（回答書）

kotoba-data を読むだけで、次を数えて報告する。

1. 段1の後に作られた札のうち、すでにある札の同じ出来事・同じ発表・続報だったのは何枚か（前回と同じ L1・L2・L3 の基準、1人の読み）
