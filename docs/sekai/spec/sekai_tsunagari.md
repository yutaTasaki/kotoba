## 2. 候補の穴（①-1 の最初）

いま：候補の枠の［書いてあった・札を作る］は、枠の中の［url を開く］をその画面で押すまで押せない。出典の行の小さい「url」は開いた扱いにならず、開いた印は読み直すと消える。

### 2.1 開いた扱い

- 次のどれを押しても「この url を開いた」とする
  - 枠の［url を開く］
  - 出典の行の小さい「url」
  - ［直す］の欄の中の［url を開く］
- 開いた印は**端末に残す**（読み直し・アプリの切り替え・新しい版の自動読み直しでも消えない）
  - 持つもの：候補ごと（調べた記録の番号＋候補の番号）に、開いた url と開いた日
  - 残す期間：札を作ったら消す。作らないまま 30日たったら消す
  - 端末ごと（同期しない）。開いた端末と作る端末が違うときは、作る端末でもう一度開く
- url を［直す］で書き換えたら、その候補の開いた印は消す（今と同じ）
- **開かずに作れるようにはしない**（人が確かめた札だけ、を守る）

### 2.2 押せない理由の見え方

- 押せない理由が「url を開いていない」のとき：ボタンのすぐ下に、ふつうの字の色・ふつうの大きさで
  「↑ 先に［url を開く］を押して、ページに書いてあるか見てください（開くと、このボタンが押せます）」
- 赤にはしない（次の手順であって、誤りではない）
- 字数・日付・お金の動きなどで押せないときは今のまま（赤、［直す］で直せます）

### 2.3 失うもの

- 開いた印が端末に残るので、開いただけで読まずに押せる余地が今より少し広がる
- 端末ごとなので、iPhone で開いて PC で作るときは開き直しが要る

## 3. 候補から作った札を、枝か葉にする

いま：候補から作った札（分かったことの［札にする］、取り込みの「別の出来事だった」から作る札も同じ道）は、どの幹にも付かず、葉にも数えられない。

### 3.1 画面（案C：人が選ぶ。はじめは元の札の幹に印）

［書いてあった・札を作る］のすぐ上に1行足す。

```
付ける幹：［✓ 制裁が武器になる］［✓ 国債の買い手が細る］［ほかの幹 ▸］［葉にする］
```

- はじめの印：**元の札**（調べた元の札。取り込みの「別の出来事だった」から作るときは、同じと言われた札）の今の幹。元の札が葉なら［葉にする］に印
- 押すと印が付く／外れる。幹は2本まで。3本目を押したら、押した幹に印を付けず「幹は2本までです（1本外してから選んでください）」を1行出す
- ［ほかの幹 ▸］：開くと残りの幹を並べる（新しい枝の順。外した幹は出さない）
- ［葉にする］：押すと幹の印を全部外す。幹を押すと［葉にする］の印が外れる
- 何も印が無い状態は［葉にする］と同じ
- 幹が1本も立っていないときは、この1行を出さない（今と同じに作る。記録も書かない）
- 押す回数：元の札の幹のままなら今と同じ2回。変えるときだけ1〜2回増える

### 3.2 記録

札ができたら、幹の記録に「枝を付けた」記録を1件書く（札ができなかったら書かない）。

| 欄 | 値 |
|---|---|
| type | `attach` |
| by | `hito` |
| src | `dig`（新しい値） |
| card・eventDate・fact | 作った札 |
| miki | 選んだ幹（0〜2本、押した順） |
| more | null |
| digId | 調べた記録の番号（取り込みの「別の出来事だった」なら取り込みの記録の番号） |
| origin | はじめの印のままなら `kept`、変えたら `changed` |

### 3.3 数え方

- 葉の数（芽を探すまでの「積もった葉」）に、`src` が `dig` で幹0本の札も入れる（今は朝の取り込みの葉だけ）
- 「幹に新しい枝」（ホームの誘い）に、`dig` で付いた枝も入れる（今は割り直しと読む回の枝を除いた残りなので、足さなくても入る。確かめだけ）
- 今日動いた幹に、`dig` で付いた枝も入れる
- 幹の画面の枝の並びで、`dig` から来た枝に「自分で調べた」の印を出す（札の頭の「自分で作った」と同じ字）
- 古い版の端末：`dig` の記録も「枝を付けた」記録として読むので、幹の枝には出る。葉の数には入らない（困らない）

### 3.4 入れないもの

- 主体を増やすこと（候補に「動かした側」が無い）。［直す］で入れた「動かした側」は、今のとおり札に入る
- 候補の枠で幹を**あとから**変えること（作ったあとは、札の画面の今の道で変える）

### 3.5 失うもの

- 押す前に1行読む手間。見ずに押せば元の札の幹に付く（はじめの印の癖が残る）
- 狭い幅で幹の名前が長い。［ほかの幹 ▸］で畳む

## 4. 控えが消える不具合

いま：朝のプロンプトをコピーしてから取り込むまでに候補から札を作ると、作る道が朝の取り込みと同じ入口を通るため、「芽を探した」記録（返事なし）が1件足され、コピーしたプロンプトの控えが消える。**積もった葉の数も0から数え直しになる**（芽を探した記録の後の葉だけを数えるため）。

直し方
- 候補から札を作るとき（3章の道すべて）は、取り込みの入口を通っても、幹の記録（枝・根・芽・芽を探した）を書く処理を通さない。控えにも触らない
- 枝の記録は 3.2 のとおり、作る道の側で書く
- 取り込みの記録（同じ出来事・続き）も書かない（今も書かれていないことを確かめる）

いまのデータ：芽を探した記録は0件。この不具合で壊れた記録は無い（実測）。直すデータは無い。

## 5. 3本目を捨てない

### 5.1 枝の記録に足す欄

`attach` の記録に、捨てていたものを控えとして残す欄を足す。**控えは枝の付け方に効かない**（幹に付けない・数に入れない）。空なら欄ごと書かない。

| 欄 | 中身 |
|---|---|
| `moreFrom` | 3本目を幹の欄から移したとき `miki`。3本目の欄に書いてあったとき `more`。3本目が無いときは書かない |
| `extra.over` | 付けなかった幹の番号（4本目以降・3本目の欄にもう書いてあったときの幹の欄の3本目以降）。最大5 |
| `extra.unknown` | 知らない幹の番号として書かれた文字（40字まで、最大5） |
| `extra.moreSame` | 3本目の欄に、付けた幹と同じ番号が書かれていたときの番号 |
| `extra.moreBad` | 3本目の欄が読めなかったとき 1 |

### 5.2 朝の取り込み

札ごとに、上から順に決める。

1. 幹の欄の番号から、知らない番号を外す（`extra.unknown` に残し、数える）。同じ番号の重なりを1つにする
2. 根の札なら、根の幹を先頭にする（今と同じ）
3. 3本目の欄を読む
   - 文字なら、その番号。配列なら、最初の読める番号。どちらでもなければ空（読めない形なら `extra.moreBad`）
   - 知らない番号なら空にして `extra.unknown`
   - **付ける幹と同じ番号なら空にして `extra.moreSame`**（数えない）
4. 幹の欄が3本以上なら、2本までを付ける
   - 3本目の欄が空なら、幹の欄の3本目を3本目にする（`moreFrom: 'miki'`）
   - 残り（4本目以降、または3本目の欄がすでにあるときの3本目以降）は `extra.over`
5. 3本目が決まれば「3本目を付けたかった」に数える

### 5.3 割り直し・読む回

- 割り直し：1回分の返事を読むとき、5.2 と同じ決まりで3本目を決める（2回を比べて付ける幹を決めるのは今と同じ。枝の記録の3本目は1回目の分）
- 読む回（幹がまだの札に幹を付ける）：5.2 の 1・4 と同じ決まりにする。黙って切らない。3本目の欄はプロンプトに無いので、幹の欄の3本目だけを 3本目にする

### 5.4 前の記録の読み方

- 3本目が付けた幹と同じ番号の記録（今1件：サウジの保険プール）は、3本目が無いものとして読む（記録は書き換えない）
- 3本目を数える所（取り込みの結果・③の材料になる所）は、すべてこの読み方を通す

### 5.5 結果の1行

| いま | これから |
|---|---|
| 3本目を付けたかった N枚。 | 3本目を付けたかった N枚（うち幹の欄から移した M枚）。 |
| ※ 3本目以降 N件は外しました。 | ※ 4本目以降 N件は付けずに控えに残しました。 |
| ※ 幹の番号が見つからない N件（付けていません）。 | ※ 幹の番号が見つからない N件（付けずに控えに残しました）。 |
| （出ない） | ※ 3本目が付けた幹と同じ N件（3本目にしていません）。 |
| （出ない） | ※ 読めない3本目 N件。 |
| 読む回：（出ない） | ※ 3本目 N枚・4本目以降 N件（控えに残しました）。 |

### 5.6 失うもの

- 3本目の欄に書かれた3本目と、幹の欄の書き間違いから移した3本目が、`moreFrom` の印でしか分けられない
- 枝の記録が1件あたり数十字増える（控えがあるときだけ）
