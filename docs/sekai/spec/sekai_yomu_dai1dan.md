# 集めることと読むことを分ける（第1段）

v20.17 で入れたもの。朝のプロンプトは**一切変えていない**（第2段で判断する）。

## 1. なぜ分けたか

朝のプロンプトは「探す・書き写す・思惑を読む・分かれ目を立てる」を一度にやらせていた。
出典を開いた直後は事実の書き写しに気が向き、`read`（思惑）が「述べた理由のなぞり」に落ちやすい。
集める仕事と読む仕事を別の回に分け、読む回では**新しい出来事を探させない**。

## 2. 入れたもの

| もの | 中身 |
|---|---|
| `worldReadPromptText()` | 読むプロンプト。未読の札を新しい順に最大 `WORLD_READ_MAX`（20）枚 |
| `worldUnreadCards()` | 未読＝**`readAt` が無く、`actors` が1つ以上ある札**。`read` が空かどうかでは見ない |
| `worldReadLinkedLines(ev)` | 同じ概念に触れている札を `WORLD_READ_LINKED`（2）枚、**id と fact だけ**添える |
| `worldImportReadJson(raw)` | 読んだ結果を足す。遡及と同じ考え方で**足すだけ** |
| `readAt` / `zure` | 札に足した項目（`normalizeWorldEvent` に明示的に足した） |
| `renderHomeReadRow(box)` | 朝の1行。`WORLD_READ_NUDGE`（8）枚以上溜まったときだけ出す |
| `worldOpenRead()` | 1行を押すと、プロンプトを写して取り込む画面の貼る欄まで連れていく |

### なぜ「`read` が空」を未読の印にしなかったか

述べた理由（`said`）と同じ内容なら `read` は**正直に空**になる。
空を未読と見なすと、その札は毎回プロンプトに出続け、読むたびに同じ判断を繰り返す。
だから「読む側を通したかどうか」を `readAt` で別に持つ。材料が足りずに空振りした札にも `readAt` を押す。

## 3. 読む側に許したこと・禁じたこと

- `read`：主体ごとの思惑。**同じ主体には違う読みを書く**（同じ文の使い回しを禁じた）
- `zure`（尺度2）：`said` と `did` がずれている札の、ずれの中身を1文
- 損を承知でやっているなら何を犠牲にしたか（尺度3）を `read` に書く
- `fork`：**すでに答えが出ていることは立てない**。分かっているなら `read` に書く
- `confidence`：**下げるのは可、上げるのは禁止**。下げたときは `confidenceWhy` が必須
- 出典は開けない。`fact`・`why`・`detail` に書かれていることが全部（遡及の文面をそのまま流用）

尺度1と5は第1段では入れていない。

## 4. 足すだけ、の中身

既にある値は上書きしない。取り込みで通るのは次だけ。

| 項目 | 通る条件 |
|---|---|
| `read` | その主体の `read` が空。かつ `said` のなぞりでない |
| `zure` | 札に `zure` が無い |
| `fork` | 札に `fork` が無い |
| `reason` | 札に `reason` が無い |
| `confidence` | 今より**小さい**値で、かつ `why` がある |

端末に無い id は無視して数える（`unknown`）。知らない主体名も無視する。

## 5. 測った値（2026-09-12、札25枚・うち主体つき22枚で確認）

| 何 | 値 |
|---|---|
| 20枚の読むプロンプト | **9,634字**（1枚あたり482字） |
| つながる札の行を除いた場合 | 7,123字（1枚356字）。差は概念経由の40行 |
| 未読22枚のときの対象 | 20枚 |
| 1行が出る境目 | 7枚＝出ない／8枚＝「まだ読んでいない札が8枚あります ▸」 |

取り込みの確認（わざと壊しにいった payload の結果）：

- 既にある `read`（1件）は守られた＝`kept:1`、上書きされていない
- 既にある `fork`・`reason` は差し替えられていない
- 空いていた札には `read` 2人ぶん・`fork` 1件・`reason` 1件・`zure` 1件が入った
- `said` のなぞり（「市場機能の回復のためと説明」）は**入らなかった**
- 知らない主体名は無視、端末に無い id は `unknown:1`
- 確度：3→2 は通り、4→**5 は拒否**、理由なしの 5→1 も拒否（`lowered:2`）
- `readAt` は `normalizeWorldEvent` を往復しても残り、読んだ札は未読に戻らない（未読22→16）

## 6. トヨタの入口

チャットの取得役の UA では、トヨタ自身のページ（global.toyota）も IR BANK も開けない。

- 四半期：`https://stockanalysis.com/quote/tyo/7203/financials/cash-flow-statement/`

- 日経（`nikkei.com/nkd/...`）は `retiredUrls` に送った

## 7. 第1段では触っていないもの

- 朝のプロンプト（`worldPromptText`）。`read`・`fork`・`reason` は今も朝が書く
- 尺度1（言行の履歴）と尺度5（コストの蓄積）の置き場
- 第2段（朝から `read`・`fork`・`reason` を外すか）の判断

# 第2段（v20.18）：朝から read・fork・reason を外す

第1段の実測で、分かれ目9件・食い違い4件・確度下げ3件が出た一方、**新しく入った思惑は1枚だけ**だった。
朝が先に浅い `read` を埋めていて、読む側（空欄しか埋めない作り）に書く場所が残っていなかったため。

## 1. 朝から外したもの・残したもの

| 項目 | 朝 | 読む回 |
|---|---|---|
| `did`・`said` | 残す | — |
| `confidence`・`confidenceWhy` | 残す（出典を開いた側でないと判定できない） | 下げるだけ |
| `premise`・`concepts` | 残す（名前を作るだけなら書き写しに近い） | — |
| `read` | **外した** | 書く |
| `fork` | **外した** | 書く |
| `reason` | **外した** | 書く |

プロンプトから消すだけでなく、**朝の取り込みの入口でも落とす**（生成が勝手に返しても入らない）。

- `worldStripMorningRead(list)`：朝が返した `read` キーごと捨てる
- `fork`・`reason` は `normalizeWorldEvent` に渡さない
- 朝の結果の文面から「分かれ目つき」「推定を書いた札」を外し、「思惑と分かれ目は、このあと『読む』で書きます」に変えた

## 2. すでに入っている浅い読み（28人ぶん）の扱い

**印を新しく付けなくても見分けられる。** これから読む回が書いた読みにだけ `readBy:'yomu'` を刻めば、
**印の無い `read` ＝ 朝が書いたもの**になる（移行処理が要らない）。

- `worldRereadCards()`：`readAt` があり `rereadAt` が無く、印の無い `read` を持つ札
- 読む枠（20枚）は未読を優先し、**余った枠だけ**書き直し候補で埋める
- プロンプトには「いまの読み（朝が書いたもの）」として見せ、なぞり・言い換え・当たり前のことなら書き直させる
- 書き直しは **`rewrite: true` を明示したときだけ**通る。付けなければ既存の読みは守られる
- **元の文は `readWas` に必ず残す**（書き直しを重ねても最初の文だけを保つ）
- 一度当てた札には `rereadAt` を刻み、同じ札が毎回出続けないようにする

## 3. read が空の札の見え方

朝が思惑を書かなくなるので、札を開くと `read` が空の主体が増える。空欄を放置に見せないため：

- 「まだ読んでいません（思惑は「読む」でまとめて書きます）」の1行
- そこから「いま読む ▸」で読む回へ直行
- 書き直した主体には「前の読み」を取り消し線で残す（`.waWas`）

## 4. 端末に残る古い「取るもの」（この段で見つかった穴）

出典の `note` は**定数ではなく保存済みのデータから出ている**（`worldDailySources` が保存レコードを展開する）。
起動時の取り込みは「保存された URL が `retiredUrls` に載っているときだけ」中身を入れ替えるので、
URL を変えていない出典の注は古いまま端末に残る。

そのため定数から `read` を外しても、実機の朝のプロンプトは「read にその読みを書く」と言い続けていた
（TSMC・トヨタ・NRI の3件で実測。保存30件中、注を持つ8件のうちちょうど3件）。

**直し方**：`read`・`fork`・`reason` という語を含む注だけを定数から入れ直す。
手で書いた注にこれらの語が入ることはまず無いので、これを目印にした。
入れ替える前の文は `noteWas` に残す（`normalizeWorldSource` にも項目を足した。足さないと保存で消える）。

## 5. 測った値（2026-09-12）

| 何 | 値 |
|---|---|
| 朝のプロンプト | **16,310字**（注を入れ直したあと。入れ直す前は15,905字） |
| そのときの材料 | 毎回見る7件／一次16件／解釈7件／概念3件／既知アクター22件 |
| 朝に残っている項目 | `confidence`・`premise`・`concepts`・`did`・`said` すべて有り |

確かめたこと：

- 朝の取り込みで入った札は `fork: null`・`reason: ""`・`read` 空で、**未読に数えられた**

- 朝が書いた浅い読みは、`rewrite` 無しでは**書き換わらない**。`rewrite: true` で書き直すと
  `readWas` に前の文が残り、`rereadAt` が刻まれて候補から外れる

# v20.19：出典の注が200字で黙って切られていた欠陥

第2段の作業中に見つかった、**第2段とは独立した既存の欠陥**。

## 0. 何をして、どうなったか

**したこと**：朝の取り込みでチャットに渡している「この出典から何を取るか」という指示文が、
保存のときに200字で切られていた。切られていた分を元の長さに戻し、
これから切れたときは設定に出るようにした。

**結果**：欠けていた5件が全て満量に戻った。
トヨタには「SEC の 20-F を使え」、DFA には「どの地層の数字か」という指示が復活し、
朝のプロンプトにも載った。手で書き換えた注は触っていない。

**意味**：トヨタの入口を1日に4回探し直したのも、DFA が読めなかったのも、原因はこれ1つだった。
入口が塞がれていたのではなく、**指示が届いていなかった**。

**残り**：次の取り込みで本当に読めるか。それが答え合わせ。

## 1. 何が起きていたか

`worldStr(v, max)` は `slice` するだけで、**切ったことを誰にも言わない**。
出典の「取るもの」（`note`）は保存のとき200字で切られており、注を持つ7件のうち5件が欠けていた。

| 出典 | 定数 | 保存 | 消えていたもの |
|---|---|---|---|
| トヨタ | 457字 | 200字 | **SEC 20-F を優先する指示・札の url の規則・checked の書き方** |
| DFA | 445字 | 200字 | **地層 id（`st_us_wealth_top01`／`bottom50`）・値の書き方・基準日** |
| 米財務省 日次 | 294字 | 200字 | 準備預金の見方・単位・from／to の規則 |
| 日銀 旬報 | 239字 | 200字 | 差の書き方・from／to |
| NRI | 222字 | 200字 | checked に何年の発表を読んだか書く指示 |

生成が書く欄（`fact` 40字・`did` 40字など）は**プロンプトで同じ字数を指示している**ので整合が取れている。
注だけが「書き手に上限が知らされない欄」だったため、誰にも見えないまま消えていた。

トヨタの入口を1日に4回探し直した件（公式→IR BANK→日経→stockanalysis）と、
DFA が読めなかった件は、どちらもこの1つの欠陥で説明がつく。

## 2. 直し方

1. **上限を上げた**：`WORLD_SRC_NOTE_MAX = 800`（実際の最長は457字）。設定の注入力欄も同じ上限にした
2. **切られた版を入れ直す**：保存された注が定数の注の**先頭一致**なら、上限で切られた版なので元の長さで入れ直す。
   先頭一致は「切られた」以外にまず起きず、失う文字も無いので退避は要らない。
   **手で書き換えた注は先頭一致しないので触らない**
3. **黙って切らない**：`worldStr(v, max, label)` の第3引数に名前を付けた欄は、切ったときに端末へ控える
   （`recordWorldTruncation`。同期しない）。設定に「切り詰めた文」として
   「欄の名前／何字で切ったか／最長何字だったか／件数／最後に起きた日時」を出す

名前を付けたのは「書き手に上限が知らされない欄」だけ（出典の注・出典の名前・出典の立場・概念の注）。
生成が書く欄に付けると、指示どおりの切り詰めで毎回鳴って意味がなくなる。

起動時の読み込みは `worldStr` の定義より前に走るため、`recordWorldTruncation` の中では
**後ろで宣言する const を参照しない**（localStorage の鍵は直書き、日時も `new Date()` で取る）。
