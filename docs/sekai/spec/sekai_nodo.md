## 2. まとめ方の依頼文と、返してもらう形

### 2.1 ［調べたことを戻す］でコピーする依頼文

札の［Claude に聞く］の隣に［調べたことを戻す］を置く。押すと欄が開く（コピーのボタン・貼る欄・取り込むボタン。予告の画面の答え合わせと同じ並び）。

依頼文（`SHOOT_PROMPT_HEAD` は付けない。続きの会話に貼るので、役の説明は要らない）：

```
ここまでの会話で分かったことを、アプリに戻すためにまとめてください。

■ 必ず守ること
- この会話で出てきた内容だけを書く。新しく調べて足さない。
- 分かったことを1件ずつ、次の3つに分ける。
  did：誰かが実際にやったこと（出来事・数字）。
  said：誰かが自分で述べた理由や方針。
  read：推測・解釈。私の推測も、あなたの推測もここ。
- 迷ったら read にする。事実として書かない。
- url は、この会話で開いて確かめたページのものだけ。確かめていなければ空にする。作らない。
- 日付・数字は、出典に書かれていたものだけ。
- お金・物が動いた did には flow を書く。amount は出典の書き方のまま。換算しない。
- JSON のみ。ほかの文章を返さない。

■ 札
（札の番号・日付・何が起きたか）

■ 出力形式
{"eventId":"（この札の番号）",
 "question":"私が何を気にして調べたか（1〜2文）",
 "found":[
  {"kind":"did","actor":"JPモルガン","text":"何をしたか（1文）","date":"YYYY-MM-DD","source":"媒体名と日付","url":"https://...",
   "flow":{"from":"...","to":"...","what":"...","amount":"..."}},
  {"kind":"said","actor":"...","text":"述べた理由（1文）","date":"","source":"...","url":""},
  {"kind":"read","actor":"...","text":"推測（1文）"}
 ],
 "open":["まだ分からないこと（1文）"]}

※ 上の例の中身は架空です。形だけを使ってください。
```

- 例の中身を架空と書くのは、v20.39 で「例に本物の番号を書くと、そのまま写す」ことがあったため
- 札の番号は、コピーするときに本物の番号を入れる（「■ 札」の欄）。例の欄の eventId は「（この札の番号）」のまま
- 字数の見込み：約1,000字（本物で数えるのは実装のとき）

### 2.2 返してもらう形の決まり

| 欄 | 決まり |
|---|---|
| eventId | 札の番号。貼った札と違えば**取り込まない**（別の札の欄に貼った間違いを防ぐ）。空なら貼った札の番号にする |
| question | 200字まで（安全弁） |
| found | 1件ずつ。**50件まで**。超えた分も落とさず取り込み、「多かった」と1行出す（上限は画面が重くならないかを見る目安で、捨てるためではない） |
| found.kind | `did`・`said`・`read`。**どれでもなければ「種類なし」のまま残す**（機械が事実か推定かを決め直さない） |
| found.text | 300字まで（安全弁。`CUT_MAX` と同じく表の1か所に置く）。切ったら「切った」の印を付ける |
| found.actor | 80字まで |
| found.date | YYYY-MM-DD でなければ空（元の文字は `dateRaw` に残す） |
| found.url | 今の札と同じ確かめ方で安全な url だけ残す。形が正しくなければ空にして、元の文字を `urlRaw` に残す（**出典なし**の扱い） |
| found.source | 120字まで |
| found.flow | from・to・what・amount。今の札のお金の動きと同じ字数。**第1段では使わない**（第2段で札にするときの材料として残す） |
| open（足2） | 1件200字・10件まで。超えた分も残す |

- **read に url が付いていても推定のまま。** url は「参考」と出す
- **同じまとめを2回貼ったら取り込まない**（札の番号と、found の文をすべて並べたものが同じなら「同じまとめがもう入っています」）

## 3. 画面

### 3.1 札の下の「自分で調べたこと」

札を開いたときの並び（今の「動かした側」「詳しく」の下、分かれ目の上）：

```
自分で調べたこと（2回）
 9/14　なぜサウジが米国のゲーム会社を買うのか
   事実
    JPモルガン：買収資金のうち200億ドルを出した（出典名 日付）［url］
   述べた理由
    （主体）：…（出典なし）
   推定
    サウジ政府：…　← 推定の色（黄）
   種類なし
    …
   まだ分からないこと
    …
   ［この記録を消す］
 9/12　…
```

- 新しい順。1回目は開いた形、2回目より前は1行（日付と問い）で、押すと開く
- **推定は、今の札の推定と同じ色と形**（黄色）。自分で調べたものでも事実の色にしない
- 出典の無いものは「出典なし」と添える（url の形が正しくなかったものも同じ）
- 「種類なし」「切った」「url の形が正しくなかった」は、その件の横に小さく出す（黙って直さない）

### 3.2 ［調べたことを戻す］の欄

```
［Claude に聞く］［調べたことを戻す］［非表示］
 ┌ 調べたことを戻す ───────────────
 │ ［まとめ方をコピー］
 │ 調べていたチャットの続きに貼ってください。
 │ ┌─────────────────────┐
 │ │ {"eventId":...} をここに貼る       │
 │ └─────────────────────┘
 │ ［取り込む］
 │ 取り込みました：事実 2・述べた理由 1・推定 3（出典なし 2）
 └──────────────────────────
```

- **貼った文章は、取り込むまで端末のメモリに札ごとに持つ（足4）。** 同期が画面を描き直しても、欄を開き直すと戻っている。取り込めたら消す。アプリを閉じたら消える（貼り直せばよい）
- 取り込んだあとの1行は、数を必ず出す（事実・述べた理由・推定・種類なし・出典なし・切った・url の形が正しくなかった）

### 3.3 記録を消す（足3）

- ［この記録を消す］を押す → 確かめ（「この記録を消します。消した印は残ります」）→ 消す
- 消した記録は、ほかの端末から戻ってこない（消した印を残す。今の札と同じ合わせ方）
- 失うもの：押し間違えて消すと戻せない（今の札の削除と同じ）。確かめを1回挟む

### 3.4 札の一覧の右端の「調べた」（足6）

- 札の一覧（世界・お金の一覧・地図から開いた一覧）の右端、確度の横に「調べた」の小さな文字
- 回数は出さない（2回以上でも「調べた」）。回数は札を開くと見える
- 色は白（`--text`）。地図の白い線（第3段）と同じ意味にそろえる
- **見え方は、実装のとき本物の一覧の画面写しで今と並べて見る**

### 3.5 世界の画面の「調べたこと」

- 世界の画面の「予告」の行の下に「調べたこと N件 ▸」（**1件も無いときは出さない**）
- 押すと一覧：戻した新しい順に「日付・札の何が起きたか・問い」。押すとその札を開く
- 札の月が端末に無ければ読み込んでから開く

## 4. ファイルと同期

### 4.1 置き場所（足5）

| ファイル | 中身 |
|---|---|
| `world/dig/index.json` | `{version, updatedAt, months: {"YYYY-MM": {updatedAt, count}}}` |
| `world/dig/YYYY-MM.json` | `{version, month, updatedAt, asked: [...], digs: [...], deletedIds: [{id, deletedAt}]}` |

- **月は「押した・戻した日の月」。** 札の日付の月ではない。古い月のファイルは後から書き換わらない（消したときだけ）
- 世界の索引（world/index.json）には何も足さない。古い版の端末は `world/dig/` を知らないので、触らない

戻した記録（digs の1件）：

| 欄 | 中身 |
|---|---|
| id | `dg_YYYYMMDD_` ＋ 乱数6桁 |
| eventId | 札の番号 |
| at・updatedAt | 取り込んだ日時 |
| question | 問い |
| found | 2.2 のとおり（1件ごとに kind・actor・text・date・dateRaw・source・url・urlRaw・flow・cut） |
| open | まだ分からないこと |

### 4.2 合わせ方

- 聞いた記録・戻した記録とも、**id ごとに足し合わせる**。同じ id が両方にあれば updatedAt の新しい方（聞いた記録は書き換えないので、どちらでも同じ）
- 消した印（deletedIds）は、消した日時が新しければ消したまま（今の札・日誌と同じ）
- 同じ id で中身が違えば、今の「番号がぶつかった」記録に残す（v20.38 の仕組み）

### 4.3 同期の手順

世界の同期（worldSyncNow）の最後、予告のあとに：

1. `world/dig/index.json` を取る（**同期1回につき GitHub への読み込みが1回増える**）
2. 端末で書いた月、索引の日時が端末の覚えと違う月を合わせる（今の世界の月と同じ）
3. 中身が変わった月だけ書く。索引は月の日時が変わったときだけ書く（v20.41 の「変わらなければ書かない」）

端末の保存：`worldDigIndex`、`worldDig:YYYY-MM`、書いた月の一覧、覚えている日時。**起動時は索引と全部の月を読む**（1件1〜3KB の見込みで、1年に1件/日なら約1MB。1万日で端末のメモリに数十MB になる。先の話なので、大きくなったら月ごとに読む形に直す。今は測れません）。

### 4.4 失うもの

- 同期1回あたり GitHub の読み込みが1回増える（今の同期は1回で十数回読んでいる）
- 聞いた記録を残すたびに、その月のファイルを1回書く（1コミット）
- GitHub に `world/dig/` のファイルが増える（月に1つ＋索引）

## 5. 札・線・プロンプトに入らないこと（回答書 2）

記録は `worldEvents`（札の一覧）に入れない。だから今の仕組みでは、次のどれにも使われない。実装のときに本物で確かめる：

| 使わない所 | 確かめ方 |
|---|---|
| 地図の線・お金の一覧 | 戻した記録の flow が線にならない |
| 取り込む回・読む回・問い・答え合わせのプロンプト | 各プロンプトの文字に、戻した文が1つも入っていない |
| ［Claude に聞く］の依頼文 | 同上 |
| つながる札・主体の時系列・概念の回数 | 数が変わらない |
| 読む枠（未読・切れた推定など）の選び方 | 選ばれる札が変わらない |

## 6. 第2段・第3段・第4段（あらまし。第1段を端末で見てから、それぞれ仕様書を書く）

### 第2段：新しい札・線を作る

- 戻した記録のうち、**did で url があり flow のあるもの**に［札にする］を出す（人が押す。1件ずつ）
- 札にするときは今の取り込みを通す（重複・日付・url の確かめも同じ）。**確度は付けない**（生成が付ける値なので）
- 「自分で調べた札」の印は、**戻した記録の側に札の番号を持つ**ことで付ける（札の中身には入れない）
- url の無い件：**url を足す欄**を出し、足したら［札にする］を出す（回答書 2「url が付いたら札にできる道」）
- 主体が一覧に無ければ、今の取り込みと同じく足される（JPモルガンなど）
- 元の札とのつながり：戻した記録に「元の札の前の動き／後の動き」を持ち、お金の鎖を作るときに読む。**元の札は書き換えない**
- 決めること（第2段の仕様書で）：自分で作った札を、読む回の枠や取り込む回の「すでにある札」に入れるか

### 第3段：地図の見え方＋①②

- 自分で作った札の線を白く描く。**本物の地図で、今の線と並べた画面写しを見てから決める**（回答書 7）
- ① 続きが来たら知らせる：新しく入った札が、戻した記録に出てくる主体・札に触れたら、世界の行に「続きが来た」（普段は出さない）
- ② 地図で先に出す：同じ組に線が多いとき、白い線を先に数える

### 第4段：③朝の取り込みで続きを集める

- 取り込む回のプロンプトに「私が掘っている主体と流れ」を並べる。**1回3件まで**（回答書 6）
- 3件を超えた分は、並べなかった数をプロンプトの外（画面）に出す
- 失うもの：掘った所に集まる。上限を超えると減らす（回答書「多すぎたら減らす」）
