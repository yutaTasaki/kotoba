# 仕様書：世界 API 段階B（数字を貯める）

段階A（v19.13）は、朝のボタンを押すたびに米財務省の API から95暦日分（約66営業日・入出金およそ11,900行）を取り直し、何も保存しませんでした。段階Bでは、取った数字を貯めて、毎朝は足りない分と直近の数日だけを取ります。

- 決めたこと：指示書 `sekai_dankai_b_shiji.md` の問いへの回答（`sekai_dankai_b_kaitou.md`）
- 実測（2026-09-11、PC）：入出金 1ページ目 1万行・66KB・2.1秒、2ページ目 1,880行・14KB・1.2秒、口座残高 14日分・1.1秒、政府債務総額 2行・1.0秒。4つを同時に取るので全部でおよそ2秒。取る範囲は毎回「今日から95暦日前まで」で決まっているので、日が経っても遅くはならない
- 段階Bの利点は2つ：毎朝が軽くなること（ふだんは直近の数日分・数KB）と、過去の数字が残ること

---

## 1. 貯める場所と形

- **月ごとのファイル** `world/figures/YYYY-MM.json`（1つの `figures.json` にしない）。API の形のまま1年貯めると約6MB になり、同期のたびに全部を送り直すことになるため。項目名を1か所にまとめて詰めると、ひと月約34KB・1年で約0.4MB
- 月の一覧 `world/figures/index.json`（月ごとの更新日時）。世界の索引（`world/index.json`）とは別に持つ
- 端末の中は `worldFigures` の1つ（「world:」で始めない）
- 1日ごとに3つ：**入出金**（項目ごとの額）・**口座残高**（TGA。毎日4行）・**政府債務総額**（総額・国外を含む市場が持つ分・政府の中の基金が持つ分）。それぞれに取った日時を持つ
- **確認先の URL** はデータの種類ごとに1つ、ファイルに持たせる（値1つずつには持たせない）。どの値も、その URL を確認先として受け継ぐ。これで「url が無い値は取り込まない」を満たす
  - 入出金 `https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/deposits-and-withdrawals-of-operating-cash`
  - 口座残高 `https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/operating-cash-balance`
  - 政府債務総額 `https://fiscaldata.treasury.gov/datasets/debt-to-the-penny/`
- 換算しない、合計しない（API の額をそのまま貯める）

## 2. 毎朝の取り方

- 貯めた分が比べる履歴（60営業日）を覆っていれば、**最後に貯めた日の少し前（約5営業日前）から今日まで**だけを取り、上書きする（米財務省があとから数字を直したときに拾うため）。ふだんは1ページ・数KB
- 覆っていなければ、今までどおり **95暦日分**を取る（最初の1回・新しい端末でまだ同期していないとき・長く開かなかったとき）
- 取れなかったときも、貯めた分でプロンプトを作る。取れなかったものは「■ 今日の数字」の終わりと取り込む画面の1行に書く。どれも取れず貯めた分も無いときは、今までどおり数字なしのプロンプトをコピーする（押しても何も起きないボタンを作らない）
- プロンプトの「■ 今日の数字」の形と、決まった支払いの見分け方（`sekai_api_shiyou_A.md` の2章）は変えない。数字の出どころが「毎朝95暦日分」から「貯めた分」に変わるだけ

## 3. 合わせ方（2台の端末・米財務省の訂正）

- 日付を目印に足し合わせる。同じ日の値が両方にあれば、入出金・口座残高・政府債務総額ごとに**新しく取った方を採る**
  - 米財務省が過去の数字を直したなら、直した方が正しい。「追記のみ・重複弾き」は人が入れた事実を消さないための決まりで、API が自分で訂正した数字には当てはめない
- 貯めた数字は消さない（際限なく貯める。1年で約0.4MB、10年でも約4MB）。プロンプトに使うのは直近95暦日分だけ
- 壊れたときのための「全部取り直す」ボタンは作らない。毎朝、直近の抜けている日を取って足し、読めない月は無いものとして扱って取り直す

## 4. 地層「米国の政府債務総額」

- id `st_us_debt_total`、単位「兆ドル」、小数2桁（「40.07 兆ドル」）、周期 month
- 値は **Debt to the Penny の `tot_pub_debt_out_amt`**（国が借りている総額）の**各月の最後の日の値**。確認先 `https://fiscaldata.treasury.gov/datasets/debt-to-the-penny/`
- **1993年4月から入れる**。API の値が1つも入っていなければ、1993年からの毎日の値を1回で取り（約8,400行・106KB）、月末の値を約400点入れる。そのあとは、終わった月の月末の値を毎朝足す
- API から来た値（出どころ `api`）は、同じ日の API の値だけ新しい方で置き換える。手で入れた値・札から入った値には触らない
- 地層の表は空のときにしか最初の地層を入れないので、今の端末にはこの地層だけを一度足す
- 口座残高（TGA）は地層に入れない（毎日動く残高で、数十年単位でしか動かない地層の考え方に合わない）
- 地層の画面は値を全部並べる作りなので、**新しい24点だけを並べ、「古い値 N件を見る」で残りを開く**（値は全部残る）
- 世界の画面の「今日の地層」の1行にこの地層が出ることがあるが、地層としての表示なので「画面に出さない」の対象外

## 5. 世界のデータを捨てても数字は残す

- 札を作り直すための「世界の世代」を上げて捨てる操作でも、`world/figures/` と端末の `worldFigures` は残す（API の値は札とは別物）

## 6. 画面

- 貯めた数字そのものは画面に出さない（線で見る仕組みは必要になってから）
- 取り込む画面の「今日の数字」の1行に、新しく取った日数と時間を添える

## 7. 確かめること

1. 最初の1回は95暦日分を取り、貯める。2回目は直近の数日分だけを取る（件数と時間を出す）
2. 貯めた分から作った「■ 今日の数字」が、段階Aで毎朝取り直して作ったものと同じになる
3. 2台の端末の合わせ方：同じ日の値は新しく取った方が残る。片方にしかない日は両方に残る
4. 取得に失敗したとき、貯めた分でプロンプトが作られ、コピーされる
5. 地層「米国の政府債務総額」に1993年からの月末の値が入り、「40.07 兆ドル」の形で出る。同じ値を2回入れない
6. 世界のデータを捨てても、貯めた数字が残る
7. 幅360・320ではみ出さない
