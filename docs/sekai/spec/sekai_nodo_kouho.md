## 1. まとめの依頼文

### 1.1 足す節

「■ 出力形式」の前に、次の2節を足す：

```
■ 札の候補（cards）
この会話で分かったことのうち、地図の線になる動き（お金・物・人が、誰から誰へ動いたか）を 0〜2件選ぶ。
線になる動きが無ければ空の配列にする。無理に選ばない。
- fact：1文・40字以内。数字か固有名詞を含む。
- eventDate：YYYY-MM-DD。日が分からなければ YYYY-MM。日を作らない。
- flow：from と to は必ず書く。what・amount は出典の書き方のまま。換算しない。
- url：この会話で出典として示された url のうち、この動きが書いてあるページ。無ければこの動きを候補に選ばない。
- source：媒体名と日付。
- rel：下の「札に元から書いてあったこと」の動きの前なら before、後なら after、どちらでもなければ空。
- why：なぜこの動きを選んだかを1文。必ず書く。
- 札に元から書いてあった動きは選ばない。

■ 流れ（story）
この会話で何を調べて、何が分かったかを 2〜3文。推測は「〜と見られる」のように推測と分かる形で書く。
```

出力形式の例に足す（例の中身は今までどおり架空）：

```
 "story":"…",
 "cards":[{"fact":"A社がB社に100億ドルを融資","eventDate":"YYYY-MM","flow":{"from":"A社","to":"B社","what":"融資","amount":"100億ドル"},
           "url":"https://...","source":"媒体名と日付","rel":"before","why":"…"}],
```

「線になる動きが無いとき：`"cards": []`」を1行足す。

- 字数の見込み：PIF の札で約1,643字 → **約2,100字**。**本物で数えて報告する**（回答書の確かめ方）

### 1.2 変えない所

- 分かったこと（found）・まだ分からないこと（open）・「札に書いてあったことは書かない」・url を緩めた決まり（v20.44）は今のまま

## 2. 取り込み

### 2.1 形

戻した記録に2つ足す：

| 欄 | 中身 |
|---|---|
| story | 流れ。600字まで（安全弁。超えたら切って印） |
| cards | 候補の並び。**JSON に `cards` が書かれていたときだけ持つ**（空の配列も「0件」として持つ）。書かれていない記録（今までの記録）は持たない |

候補1件：

| 欄 | 決まり |
|---|---|
| fact | 300字まで（安全弁）。40字を超えていても取り込み、札を作るときに今の決まりで止める |
| eventDate | YYYY-MM-DD か YYYY-MM なら `date`、ほかの形は `dateRaw`（v20.45 の決まり） |
| flow | from・to・what・amount（v20.45 と同じ字数） |
| url | 今の確かめ方。形が正しくなければ `urlRaw`。`urlBy: 'chat'` |
| source・rel・why | source 120字、rel は before／after／空、why 200字 |
| 札にしたあと | cardId・cardAt・cardBy・cardValues・datePrec・urlChecked・urlCheckedAt・urlFailed（v20.45 の件と同じ） |

### 2.2 数

- 候補が3件以上：**全部持つ**。取り込んだあとの1行に「候補が N件と多かった（全部残しました）」
- 候補が0件：`cards: []`。1行に「札の候補：0件」
- 同じまとめを2回貼ったかの確かめに、流れと候補も含める

### 2.3 欠けている候補（足2）

| 欠け | 扱い |
|---|---|
| url が空（依頼文で選ばせないはずだが来た） | 落とさず候補に出す。「url がありません」。［直す］で貼るまで作れない |
| from も to も空 | 同じく出す。［直す］で入れるまで作れない |
| fact が空 | 候補にしない（何の動きか分からない）。1行に「文の無い候補 N件」 |

## 3. 画面

### 3.1 記録の並び（候補のある記録）

```
自分で調べたこと（1回）
 09-14　湾岸からの無条件の資金なのか…
 流れ：…（2〜3文）
 札の候補（チャットが選んだ・2件）
 ┌──────────────────────────
 │ サウジがシリアと投資協定に署名              15/40
 │ 2026年2月（日は分からない）　サウジ → シリア　投資の約束　240億リヤル
 │ 選んだ理由：…
 │ 日本経済新聞 2026-02-16　url（チャットが示した）
 │ ［url を開く］ ［書いてあった・札を作る］ ［直す］
 │ （作れないときの理由の1行）
 └──────────────────────────
 ▸ 分かったこと 23件（押すと開く。開いた中の事実にも［札にする］）
 ▸ まだ分からないこと 3件
```

- 候補の枠は緑の細い線（今の地図・一覧で使っている色。**見え方は実装のとき画面写しで見る**）
- 選んだ理由が空なら「選んだ理由：（理由が書かれていません）」（足4）
- 札にした候補は、枠の中を「札にした（押すと開く）」と、自分で入れた値の1行に変える
- 候補が0件：「この会話から線になる動きは選ばれませんでした（分かったことから手で札にできます）」
- 「分かったこと」「まだ分からないこと」は**最初は畳む**。開け閉めは今の記録の開け閉めと同じく覚える

### 3.2 候補の［直す］（足3）

- 押すと、v20.45 の［札にする］の欄を、候補の値を入れた形で開く（何が起きたか・日付と年月日／月まで・動かした側・お金の動き・出典・url・元の札とのつながり）
- 「チャット」「自分で入力」の比べる相手は候補の値。直した欄は「自分で入力」
- 動かした側は候補に無いので、空から始まる（入れれば「自分で入力」）

### 3.3 ［書いてあった・札を作る］（回答書 2・足1）

| 状態 | ボタン |
|---|---|
| url が空・形が正しくない | 押せない（「url を貼ってください」→［直す］） |
| ［url を開く］をまだ押していない | **押せない**（「url を開いて確かめてください」） |
| 開いたが、ほかの欄が決まりに合わない（40字超・日付・出す側も受け取る側も空・未来の日付） | 押せない（理由の1行） |
| 開いた・ほかの欄も合う | **押せる** |

- 押すと：url を確かめた印（日時と url）を記録に残し、そのまま札を作る（v20.45 の［札を作る］と同じ：重複・日付・url の確かめ、元の札は書き換えない、読む回に入れない、鎖は rel）
- 重複などで作れなかったとき：url を確かめた印は残し（開いて確かめたことは本当なので）、札は作らない。理由と相手の札を出す
- **分かったことの［札にする］の欄も同じ1つのボタンにする**（足1）

### 3.4 候補の無い記録（回答書 3）

- `cards` を持たない記録（v20.45 までに戻した PIF・シリアなど）は**今の形のまま**：分かったことを開いた状態で並べ、事実に［札にする］
- 候補を作りたくなったら、そのチャットの続きにもう一度［まとめ方をコピー］を貼って取り込む（新しい記録として入る）

## 5. 失うもの

- 依頼文が長くなる（見込み 約1,643字 → 約2,100字）
- 候補はチャットが選んだもの。選び方の癖が先に見える線になる（選んだ理由の1行で気づけるようにする）
- 流れは要約なので、会話の細かい所が落ちる（分かったことは畳んで今どおり残る）
- 分かったことが最初は畳まれる（候補のある記録だけ）
- ［書いてあった］だけを先に押しておく（札はまだ作らない）ことができなくなる
- **v20.45 の端末は、戻した記録の知らない欄を落として書き直す作り。v20.45 の端末が同じ月の記録ファイルを書き直すと（［Claude に聞く］を押す・記録を消す・札にするなど）、その月の記録の候補と流れが消える**（分かったこと・札にした札そのものは残る）。**両端末を v20.46 にしてから、候補のあるまとめを取り込んでほしい**
