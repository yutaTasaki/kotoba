# 仕様書：古い数字を取り込まない（validTo）

- 元：指示 `shiji/sekai_kosinya_shiji.md`、原因 `houkoku/2026-09-17_kosinya_chousa.md`
- 版：v20.68

## 0. 何を直すのか

ガソリン補助の札は、**その週（9月10〜16日）の値としては正しく**、**取り込んだ日（9月16日）には次の回（51.0円）が出ていた**。

つまり直すのは「間違った数字を書いた」ことではなく、**「置き換わる数字だ」とどこにも書かれていなかったこと**。

## 1. `srcCadence` では判定できない（実測）

アプリはすでに `srcCadence`（出典が新しい数字を出す周期）を持っている。「出来事の日＋周期 ≦ 取り込み日 なら古い」という決まりを試した。

| | 結果 |
|---|---|
| 周期が分かる札 | 133 |
| 「古い」に当たる札 | **69（52%）** |
| `day` を外しても | 77枚中13枚。うち本当に置き換わる数字は3枚 |

`srcCadence` は**出典の頻度**であって、**この数字が置き換わるか**ではない。報道（`day`）は翌日に取り込んでも古くならない。

**だから新しい欄が要る。**

## 2. `validTo`（この数字はいつまでの分か）

### 2-1. 札の欄

`validTo`：`YYYY-MM-DD` か空。

- **書くもの**：次の回で置き換わる数字（週ごとの支給単価・補助率、その日の残高、その週の在庫、今月の見通し）
- **書かないもの**：置き換わらない数字（起きた出来事・累計・決算・契約額）→ `null`

### 2-2. プロンプトに足す決まり

```
- validTo：この数字が「いつまでの分」か（YYYY-MM-DD）。次の回で置き換わる数字だけ書く。
  例：週ごとに決まる支給単価・補助率、その日の残高、その週の在庫、今月の見通し。
  置き換わらない数字（起きた出来事・累計・決算・契約額）は null。
- **価格・補助率・為替・金利・在庫量のように決まった周期で置き換わる数字は、その場で最新の回を開き直す。**
  前に見た値や、まとめサイトに載っている値をそのまま使わない。今日より前で終わる回は札にしない。
```

出力形式に `"validTo":null,`、決まりに `次の回で置き換わらない数字のとき： "validTo": null` を足す。

### 2-3. 画面

札の「なぜ」の直下に1行。

- 期限内：`この数字は 9月30日までの分`
- **期限切れ**：`この数字は 9月16日までの分（すでに次の回が出ている）`（橙）
- `validTo` が空の札：**何も出さない**

### 2-4. 取り込みの結果

期限切れの札があれば、結果の1行に出す。

```
※ もう次の回が出ている数字 1件（札に「すでに次の回が出ている」と出ます）。
```

**落とさない。** 過去の回を承知で入れたいこともあるので、知らせるだけにする。

## 3. 「必ず見るもの」の自己申告を保存する

いままで、チャットの `checked`（開いたか・何件取ったか）は**結果の1行に出して捨てていた**（コードにも「保存しない」と書いてあった）。

- 調べた記録の月ファイルの新しい並び `checks` に残す（`views`・`aims`・`cmps` と同じ作り）
- `checked` に **`at`（最新の回を開いて確かめた日時）** を書かせ、一緒に残す

### 3-1. これは「確かめた証拠」ではない（はっきり書く）

**日時を書かせても、使い回しと区別はつきません。** `at` も `opened: true` と同じ自己申告で、書いたことと実際に開いたことは別。

残す目的は1つだけ：**後から癖を見返せるようにする**（毎回 `opened: true` と言っているのに `picked` が常に0、など）。

機械で確かめられるのは次の2つで、こちらの方が効く。
- `validTo`（日付なので期限切れを判定できる）
- URL のドメイン（一次資料か要約サイトかを判定できる）← 今回は入れていない

## 4. 変えないもの

地図・帯・比べる棒・折れ線・1行・地図タブ・確度の決まり。
