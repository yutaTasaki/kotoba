## 0. 第1段で何ができるようになるか

読む回（思惑を書く回）のあと、**「次に起きるはずの行動」が最大5本たまる**。
ホームの一番上に「待っている予告」として並ぶ。**押しても何も起きない**（見せるだけ）。

これだけ。当たり／外れは付かない。

---

## 1. 置き場所と形

### 1.1 ファイル

`world/forecasts.json`（月割りしない）。同期は既存の6つ（概念・用語・地層・主体・問い・出典）と同じ形で1本足す。

```
{ "version": 1, "updatedAt": "", "forecasts": [ …… ] }
```

### 1.2 1本の形

| 項目 | 中身 | 決まり |
|---|---|---|
| `id` | `fc_` + 日付 + 連番 | 端末で作る |
| `actor` | 誰が | 主体の名前。札に出てきた名前をそのまま |
| `verb` | 何を | **4つだけ**（下の 1.3） |
| `what` | 何を・どれくらい | 数字を含む1文。40字以内。**換算しない・合計しない** |
| `due` | いつまでに | **YYYY-MM-DD のみ**。他の書き方は採らない（1.4） |
| `sign` | 当たりの印 | どの出典のどの数字が出れば確認できるか。60字以内 |
| `pledgeOnly` | 約束どまりか | 1＝「約束する」だけの予告、0＝実際に動くはずの予告 |
| `fromEventId` | どの札の思惑から出たか | 札の id |
| `fromRead` | そのときの思惑の文 | **原文を写して残す**（あとで読み直すため） |
| `state` | いまの状態 | `waiting` のみ（第1段では変わらない） |
| `createdAt` | 作った日時 | |
| `stateAt` | 状態を変えた日時 | 第1段では作成時と同じ |

### 1.3 動詞は4つ

買う／売る・出す／止める・貸す／借りる・物や人を動かす。

**「約束する／破る」は動詞にしない。** 第4段で入れた「約束の印」と同じ概念が2か所に分かれるため。
代わりに `pledgeOnly` の印で表す。「約束を破った」は、第2段で
**`pledgeOnly` の予告が期限までに実行に変わらなかった**ことで自動的に記録される。

### 1.4 期限は日付だけ

「9月中」「近いうち」「年内」は**受け取らない**。取り込みのときに落とし、
**落とした本数と理由を画面に出す**（黙って捨てない）。

読むプロンプトには「期限は YYYY-MM-DD で書く。書けないなら、その予告は出さない」と明記する。

### 1.5 本数の上限

**読む回1回につき5本まで。** 6本目以降は落とし、落とした本数を画面に出す。
「思惑が強く読めたものから順に。書けないなら0本でよい」とプロンプトに書く。

## 2. 読む回に足すこと

いまの読むプロンプト（20枚・実測9,634字）の出力に `forecast` を足す。

```
"forecast":[{"fromEventId":"w_20260902_1","actor":"日本銀行","verb":"止める",
             "what":"国債買い入れの減額を四半期4000億円で続ける","due":"2026-12-19",
             "sign":"日銀の金融市場調節の公表","pledgeOnly":false}]
```

字数への影響：1本およそ120字。5本で600字、**9,634字に対して約6%**。

**書かせ方の縛り**（プロンプトに書く）：

- 思惑（read）を書いた主体についてだけ。読めなかった札には予告を付けない
- **出典を開けないので、「当たりの印」は札に出ている出典の名前から選ぶ**
- 期限は3か月以内を目安（読む回の分かれ目と同じ長さ）
- 同じ主体に何本も付けない（1主体1本まで）

## 3. 取り込み（貼り戻し）

第1段では**いまの読む欄をそのまま使う**。貼る欄を1つにするのは第3段。

`worldImportReadJson` に `forecast` の枝を足す。**足すだけ**の原則は読む回と同じ。

### 3.1 重複弾き

**同じ `actor` ＋ 同じ `verb` ＋ 同じ `due`** が既にあれば入れない。
理由：読む回を2回流したときに同じ予告が二重に入るのを防ぐ。落とした本数は画面に出す。

### 3.2 画面に出す結果

```
予告を3本入れました。
※ 期限が日付でないもの1本を落としました（「9月中」）。
※ 同じ予告が既にあったもの1本を落としました。
※ 6本目以降の2本を落としました（1回5本まで）。
```

**落としたものは必ず数と理由を出す。**

## 4. ホームに出す

### 4.1 置き場所

ホームの**一番上**（`HOME_STEP_IDS` の先頭）。並び替えの本体は第4段でやるので、
第1段では**この1か所だけ**を足す。

### 4.2 出すもの

```
待っている予告 3本
　日本銀行が 12/19 までに 国債買い入れの減額を四半期4000億円で続ける
　米財務省が 10/31 までに 2年債の発行額を700億ドル以上にする
　欧州委員会が 11/15 までに ウクライナ支援を追加で拠出する
```

- 期限の近い順
- **最大5本**。超えたら「ほか N本」と数だけ出す
- 0本のときは**この行ごと出さない**（「予告はありません」も出さない。空の行は増やさない）

### 4.3 押せなくする

回答書の「か」のとおり、**第1段では押せる形にしない**。
`<div>` で出し、`cursor` も変えない。第2段で押せるようにする。

---

## 5. 当たり率の置き場所（第1段では出さない）

回答書の「お」は**第2段**に送る。第1段では当たり／外れが1件も付かないので、
出しても「0件」しか言えず、押しても何も起きないものを増やすことになる。

第2段で設定に出す。分母が5件未満のときは割合を出さず「まだ N件」と出す。

---

## 6. 消えないための決まり

| 危険 | 対策 |
|---|---|
| 2台で別々に状態を変える | `stateAt`（状態を変えた日時）を持ち、**新しい方を採る**。主体の表と同じ合わせ方 |
| 予告が書き換わる | 第1段では `state` は `waiting` から動かない。書き換えの経路を作らない |
| 元の思惑が消える | `fromRead` に**思惑の原文を写して持つ**。札側の read が後で書き直されても、予告の根拠は残る |
| 項目が保存で落ちる | `normalizeWorldForecast` を**固定の形**で作る。`readAt`・`noteWas` で二度やった取りこぼしを繰り返さない |
| 上限で古いものが消える | 予告は**消さない**。`waiting` のまま溜まっても、ホームに出すのは5本だけ |

## 7. 第1段で実機で見るもの（回答書どおり）

1. 読む回のあと、予告が**5本以内**で入っているか
2. 期限が**全部 YYYY-MM-DD** になっているか
3. ホームの一番上に出て、**押しても何も起きない**形になっているか

あわせて確かめること：

- 落としたもの（期限が日付でない・重複・6本目以降）の数と理由が画面に出るか
- 0本のときに空の行が出ないか
- 幅360・320ではみ出さないか
- 読む回のこれまでの動き（思惑・ずれ・分かれ目・書き直し）が壊れていないか

## 8. 第2段への申し送り

- **地層の値が本当に溜まっているかを先に確定する。** `world/strata.json` を測ってから設計する
- **米国政府債務は `via:'api'` で入り、同じ日付の値が後から訂正されうる**（`worldAddLevel` は同じ日の API の値だけ新しい方で置き換える）。
  答え合わせで数字を参照するときは、**いつ時点の値で判定したか**を残さないと、後から見て再現できなくなる
- 結果は**4つ**（当たり／外れ／まだ／**確かめられない**）。「確かめられない」を「まだ」に倒さない
- 外れた予告は、元の札を**読む回に戻す**（`rewrite: true` の仕組みを流用できるか、第2段で確かめる）
