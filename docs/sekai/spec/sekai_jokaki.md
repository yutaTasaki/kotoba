# 仕様書：置き換わる数字を、同じ札の中で上書きする（過去の値は残す）

- 元：指示「取り込んだ情報の上書きと、比較できる履歴」
- 背景：`spec/sekai_kosinya.md`（v20.68 の `validTo`）
- 版：v20.70

## 0. 決まり

- 対象は **`validTo`（いつまでの分か）を持つ札だけ**。それ以外の一般的な札の上書きは扱わない（対象を絞ることで安全に保つ）
- 書き換えるのは**観測した値**（事実・理由・詳しく・出典・確度・確度の理由・動き・置き換わり期限）だけ。**分類（用語・アクター・地層・幹の紐付け・見せ方の印・進んだ予告・非表示の状態）は対象の札のまま残す**
- **過去の値は同じ札の中に配列で残す**（上限20件、古い方から捨てる）
- `eventDate`（月ファイルの置き場所）は変えない。月をまたぐ移動はしない
- 新しい欄は `updates`（書き換える先の番号）の1つだけ

## 1. プロンプト

### 1-1. 「置き換わる数字」の一覧

`validTo` を持つ札を、期限の早い順に最大15件、末尾に渡す。

```
■ 置き換わる数字（validTo がある札。新しい回の値を見つけたら、新しい札にせず updates にこの番号を書いて書き換える）
w_20260909_805134　9/9　ガソリン補助が1リットル36.0円に広がった（〜9/16）
（無ければ「まだありません」）
```

### 1-2. 決まりと出力形式

```
- updates：末尾の「置き換わる数字」に、この札が置き換える先があれば、その番号（w_…）。
  新しい回の値は、新しい札としてではなく、その札を書き換える形にする（前の値は自動で残る）。無ければ null。
```

出力形式に `"updates":null,` を足す。

### 1-3. 字数

候補が0件（validTo を使い始める前）のとき、固定部分で**実測205字**。候補が増えると、1件あたり id・日付・fact・期限で**約60字**ずつ伸びる。いまの実データに `validTo` を持つ札はまだ0枚なので、公開直後の増分は205字。

## 2. 取り込みの実処理

1. 各札の `it.updates` を見る。**書き換え先の判定は、重複判定より先に行う**（同じ URL・近い日付だと「重複」に落ちて上書きの機会を失うため）
2. 対象が実在し、かつ `validTo` を持っていれば「書き換え」
   - 対象の札の**過去の値**として `{at, eventDate, fact, amount, validTo, source, url, confidenceWhy}` を1件、その札の `history`（上限20件）に積む
   - 対象の札を土台に、`fact・why・detail・source・url・confidence・confidenceWhy・validTo・flow・premise` の6+1項目だけを新しい値で差し替える（`normalizeWorldEvent` に通し直す）
   - `updatedAt` を今に更新。`createdAt`（最初に分かった日）・`eventDate`・用語・アクター・地層・幹・見せ方の印・非表示・進んだ予告は**対象のまま**
   - 新規の `added` には数えず、`updated` に数える
3. 対象が指定されたが見つからない・`validTo` が無い場合は、**書き換えを諦めて今までどおり新規の札にする**（内容を失わない）

## 3. 画面

### 3-1. 過去の値

「なぜ」の直下、`validTo` の行のすぐ下に、`history` があるときだけ。

```
過去の値
36.0円（〜9/16）
```

複数回書き換わっていれば、古い順に並ぶ。

### 3-2. 取り込みの結果

```
※ 書き換えた札 1件（過去の値は札の中に残しています）。
※ 書き換え先が見つからなかった件 1件（新しい札として入れました）。
```

## 4. 分かっている限界（今回はやらないこと）

- **用語・アクター・地層の値・幹の紐付け・効かせた相手・見せ方の印は、書き換えでは更新しない。** 対象の札のものがそのまま残る。新しい回で分類が変わった場合は、この仕組みでは拾えない
- **`eventDate` は変わらない。** 世界タブの日付の並びは、最初に分かった日のまま動かない。更新があったことは「過去の値」を開けば分かる
- **すでに読んだ札は、書き換えても「未読」には戻らない。** 読む一覧の仕組みには触れていない
- **`usd`（ドル換算）は書き換え後に再計算される**（`worldFillUsdSoon` を、書き換えがあった回にも回すようにした）が、地層の値（`levels`）・アクター・用語は再登録しない

## 5. 確かめ（実測）

### 手元

1. 週1（36.0円・`validTo`9/16）を取り込み、週2（51.0円・`validTo`9/30・`updates`に週1の番号）を取り込むと、**新しい札は増えず**、同じ id のまま事実・確度・`validTo`・金額が新しい値に変わり、`history` に週1の内容が1件残る
2. 過去の値の表示：「過去の値／36.0円（〜9/16）」
3. `updates` が存在しない id を指すと、`updateMissing` が1件増え、**新しい札として入る**（内容を失わない）
4. `updates` が `validTo` を持たない札を指すと、同様に新規の札になる
5. 既存145枚に変化なし（帯13・折れ線6・地図13・1行122/99/55・地図タブ51/28/9/47・エラー0）
6. 145枚を全部開いてページのエラー0
7. 字数：候補0件で実測205字
