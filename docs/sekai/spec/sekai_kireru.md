## 4. 第4段（v20.36）：X の投稿文

### 4.1 自分の言葉は短く切らず、要約させる

| 言葉の状態 | 投稿文に入る説明 |
|---|---|
| 説明（「説明を作る」で作ったもの）がある | 説明（今までどおり） |
| 説明が無く、自分の言葉が60字以内 | 自分の言葉をそのまま |
| 説明が無く、自分の言葉が60字を超える | **要約を頼む**（下） |

**要約の頼み方：** 「説明を作る」と同じ小さな呼び出し（安いほうのモデル）で、「自分の言葉を、意味を変えずに60字以内・1〜2文・句点で終える形に縮める」と頼む。

- 要約は言葉に保存して、次に同じ言葉が朝に出たときは呼ばない
- 投稿文を最初に組み立てるとき：説明を入れずに組み立てて、投稿文の下に「自分の言葉を要約しています…」を出す。返事が来たら、投稿文の説明の所に入れる（その間に投稿文を直していたら、上書きせずに後ろに足す）
- **60字で切って「…」を付ける処理はなくす**

**要約の置き場所の失うもの：** 言葉に欄が1つ増える。古い版の端末は知らない欄を落とすので、落ちたら次の朝にもう一度呼ぶ（費用が1回分増えるだけで、言葉の中身は消えない）。

### 4.2 要約できなかったとき

**黙って短くしない。**

| 理由 | 投稿文の下に出す1行 |
|---|---|
| 今月の使用額が上限を越えている | 「要約できませんでした。理由：今月の API 使用額（$N）が上限（$N）を越えています」 |
| API キーが無い | 「要約できませんでした。理由：Claude API キーがありません」 |
| 通信が無い | 「要約できませんでした。理由：通信がありません」 |
| 呼び出しが失敗した | 「要約できませんでした。理由：（失敗の中身）」 |

**そのとき投稿文に入れるもの：** 自分の言葉の、**最後の句点までの文**（字数では切らない）。句点が1つも無ければ、**説明は入れない**。

**失うもの：** 句点で終わる所までを入れると、長い自分の言葉では投稿文が長くなる（自分の言葉の最長は232字）。X の上限を越えるかは**測っていない**。句点が無い言葉は説明なしになる。

### 4.3 「説明を作る」が何も起きないように見える件

- コードでは、「説明を作る」は成功・失敗・上限のどの場合も、ボタンの下に1行出す作りになっている
- **ただ、成功したときの入れ方に見えにくい所がある：** 説明は投稿文の**一番後ろ**に足す。投稿文の欄は4行の高さで、足した文は欄の外（下）にあり、**欄を動かさないと見えない**。すでに同じ説明が入っていると、投稿文は変わらずに「説明を入れました」だけが出る
- 端末で本当に何が起きたかは**測れない**
- **決まり（案）：**
  1. 足したら、投稿文の欄を足した所まで動かす
  2. すでに同じ説明が入っていたら「同じ説明がすでに入っています」と出す
  3. 失敗の1行は 4.2 と同じ言い方にそろえる（「説明を作れませんでした。理由：〜」）

### 4.4 要約の長さと費用

**実測（使用量の記録、2026-09 の iPhone）：** 「説明を作る」の呼び出し1回で、入力347トークン・出力98トークン。値段はアプリの表（安いほうのモデル：入力100万トークンあたり1ドル、出力5ドル）で、**1回約0.00084ドル**。

- **1回分しか記録が無い。** 要約の入力（自分の言葉。中央74字・最長232字）は説明のときと近いと見て、同じ程度と見込む（**測っていない**）
- 自分の言葉が60字を超える言葉は155件中98件（63%）
- 見込み：
  - 要約を言葉に保存するので、**同じ言葉は1回だけ**。今ある98件を全部要約しても約0.08ドル
  - 毎朝ちがう言葉が出ると仮定しても、1か月30回×63%≒19回で**約0.016ドル**
- **高くない。** 短い言葉のときは呼ばない（60字以内はそのまま）だけで十分と考える
- 端末で安いほうのモデルを別のモデルに変えていれば、値段は変わる（端末の設定は見られない）

**注意：** 今の iPhone の使用額（$2.87）が上限（初期値 $2.00）を越えているなら、第4段を入れても**毎朝「要約できませんでした」が出る**。上限の設定を先に確かめる必要がある。

### 4.5 第4段の確かめ

1. 説明あり・60字以内・60字超（句点あり・句点なし）の言葉で、投稿文に入るものを確かめる
2. 上限越え・キー無し・通信なし・失敗の4つを作って、1行の文と、投稿文に入るもの（句点までか、説明なし）を確かめる
3. 実際に要約を1回呼び、要約の字数・句点で終わっているか・使用量の記録（入力・出力のトークン）を報告する
4. 「説明を作る」を本当に押して、欄が足した所まで動くか、同じ説明のときの1行を確かめる
5. 投稿文の欄に2文字以上打ち、「説明を作る」「Xで投稿」を押す。決まった8項目

## 5. 消えないため・嘘をつかないための決まり

| 危険 | 対策 |
|---|---|
