## 1. 段階C：5社の決算

### 1.1 なぜ「チャットが読む」か

- SEC の数字の API（companyfacts・companyconcept・frames）は、ブラウザから読めない（CORS の許可が無い。2026-09-11 実測）。中継サーバーは作らない
- ブラウザから読めるのは書類の一覧（`https://data.sec.gov/submissions/CIK##########.json`、`Access-Control-Allow-Origin: *`）だけ
- だから、**アプリは「新しい書類が出たか」だけを見て、書類の URL をプロンプトに差し込む。数字を読むのはチャット**。GitHub Actions のような決まった時刻に動く仕組みは使わない（自動実行しない）
- 人の作業は増えない。今までどおり、コピー → チャット → JSON を貼り戻す

### 1.2 5社

| 側 | 会社 | CIK | 控えの鍵 |
|---|---|---|---|
| 作る側 | NVIDIA | 0001045810 | `sec_nvda` |
| 作る側 | Micron | 0000723125 | `sec_mu` |
| 買う側 | Microsoft | 0000789019 | `sec_msft` |
| 買う側 | Amazon | 0001018724 | `sec_amzn` |
| 買う側 | Alphabet | 0001652044 | `sec_googl` |

TSMC は年1回（20-F）なので入れない（TSMC は今までどおり「必ず見るもの」のチャット読み）。

### 1.3 見つけ方

- コピーを押すたびに、5社の書類一覧を同時に取る（1社あたり gzip で約21〜26KB・0.06〜0.4秒。米財務省の数字と並べて取るので、待ちはほぼ増えない。打ち切りは同じ15秒）
- 書類の種類 `10-Q` と `10-K` のうち、提出日（`filingDate`）がいちばん新しいものを1社1つ。訂正（`10-Q/A`）は見ない
- **新しい書類**＝その提出日が、控え（`index.pulls` の `sec_…`）より新しいもの。控えが無ければ新しい（最初の1回は5社とも出る）
- 書類の URL：`https://www.sec.gov/Archives/edgar/data/{CIK}/{受付番号からハイフンを抜いたもの}/{primaryDocument}`（人が開ける本文のページ。札の url になる）
- 新しい書類が無い会社は、プロンプトに出さない（字数のため）

### 1.4 プロンプトの節「■ 決算」

「■ 今日の数字」のすぐ次に置く。新しい書類が1社も無ければ節ごと出さない。

```
■ 決算（SEC に出た新しい書類。5社のうち 5社。書類を開いて読む）
買う側（Microsoft・Amazon・Alphabet）が設備に払った金が、作る側（NVIDIA・Micron）の売上になる。この鎖を見るための節。
- NVIDIA（作る側）：10-Q・2026-07-26 までの期・8/26 提出
  https://www.sec.gov/Archives/edgar/data/1045810/000104581026000075/nvda-20260726.htm
- （以下、新しい書類のある会社だけ）
読み方：
- 読むのは、キャッシュフロー計算書の設備投資・自社株買い・配当と、損益計算書の研究開発費。作る側は、区分ごとの売上（データセンター・メモリなど）も。
- 額は書類に書かれたとおり。10-Q のキャッシュフローは期の初めからの累計なので、引き算して3か月分にしない。flow の span に累計の期間を書く（例：「会計年度の初めから7月26日まで」）。
- 札は1社1枚：設備投資（from＝会社、to＝書類の言葉で行き先）。作る側は、区分の売上の札をもう1枚（from＝書類が名指しする買い手。名指しが無ければ「データセンターの買い手（書類では匿名）」、to＝会社）。
- 研究開発・自社株買い・配当は、設備投資の札の detail に書類の書き方のまま並べる。足さない。書類に無い項目は「記載なし」と書き、別の項目で埋めない。
- 作る側の売上の札の after に、買う側の設備投資の札（同じ JSON の "#番号" か、最近のお金の動きの id）を書いてよい。書類に買い手の名前が無いときは、つながりを read に推定と書き、confidence を7以下にする。
- url は上の書類の URL。source は「会社名 10-Q（提出日）」。eventDate は提出日。
- 1社ずつ "checked" に報告する。source は「決算 会社名」（決算 NVIDIA／…）。
```

- **四半期の値は、出したとおりの「年初からの累計」**（決定2）。引き算はしない。累計であることは flow の `span` に書かせ、一覧では今までどおり「（…の累計）」と出る
- **鎖の作り方**：買う側の設備投資の札 → 作る側の売上の札を `after` でつなぐ。書類に買い手の名前が無ければ、つながりは推定として `read` に書き、確度を7以下にする（「換算しない、合計しない」「url が無い値は取り込まない」はそのまま）
- 項目名が会社ごとに違う（設備投資は `PaymentsToAcquireProductiveAssets` と `PaymentsToAcquirePropertyPlantAndEquipment`、Amazon には研究開発費の行が無い、など）のは、チャットが本文を読むので問題にならない。無い項目は「記載なし」と書かせ、似た項目で埋めさせない
- JSON の見本の `checked` に、「決算 会社名」の行を新しい書類の数だけ足す

### 1.5 控え（同じ書類を2度出さない）

- コピーしたとき、差し込んだ会社と書類の提出日を端末に控える（今までの「必ず見るもの」の控え `kotoba_worldPullPending` に `sec` として足す）
- 貼り戻して取り込めたら、会社ごとに `index.pulls['sec_…']` を**書類の提出日**にする（今日の日付ではない。日本の朝と米国の提出日がずれて、同じ日に出た次の書類を取りこぼさないため）
- `checked` で「開けなかった」（opened: false）と返ってきた会社だけは控えない。次にコピーしたときにもう一度出る
- 控えは世界の索引（`world/index.json`）の `pulls` に入るので、2台の端末で合う（新しい日付が勝つ）
- 取り込む画面の結果の1行に、今までの「必ず見るもの：…」と並べて「決算 NVIDIA 2件」「決算 Micron 開けず（理由）」「決算 Amazon 報告なし」を出す

### 1.6 画面

- 取り込む画面の「今日の数字」の1行の後ろに1つ足す：「決算：新しい書類 2社（NVIDIA 10-Q 8/26・Amazon 10-Q 7/31）をプロンプトに入れました」／「決算：新しい書類はありません（5社を見ました）」／「決算：5社とも取れませんでした（通信できませんでした）」
- 朝の「今日の取り込み」の行は、今までどおり期限の来た「必ず見るもの」で出る。新しい書類があるかは押したときにしか分からないので、書類だけでは朝の行を出さない（どちらの入口からコピーしても、節は入る）

### 1.7 取れなかったとき

- 書類一覧が取れなかった会社は、その会社を出さず、理由を画面の1行に書く。プロンプトはいつもどおりコピーする（押しても何も起きないボタンを作らない）
- 控えは付けない（次にコピーしたとき、また見に行く）

## 2. 富裕層の源

### 2.1 FRB「分配された金融勘定」（DFA）── 必ず見るもの・四半期

- `ws_group_dfa`、周期 quarter。表示名は「米国の富の分布（DFA）」（「FRB」を名前に入れない。H.4.1 の引き当ての鍵に「FRB」があり、取り違えるため）
- 確認先（人が開くページ）：`https://www.federalreserve.gov/releases/efa/efa-distributional-financial-accounts.htm`
- **DFA の表のページは JS で数字が本文に無く、CSV の zip も CORS が無い**ので、チャットには同じ値を出している FRED の CSV（テキスト、約2KB）を読ませる
  - 上位0.1%：`https://fred.stlouisfed.org/graph/fredgraph.csv?id=WFRBSTP1300`
  - 下半分：`https://fred.stlouisfed.org/graph/fredgraph.csv?id=WFRBSB50215`
- 取るもの：最新の四半期の2つの値を、札1枚の `levels` に入れる。主体は「米国の上位0.1%」「米国の下半分」（kind: group）、said は空。この源の札に限り、flow は無くてよい（地層の値を運ぶ札）

### 2.2 地層（決定3：2つとも入れる）

| id | 名前 | 短い名前 | 単位 | 周期 | 1989年7〜9月期 | 2026年1〜3月期 |
|---|---|---|---|---|---|---|
| `st_us_wealth_top01` | 米国 上位0.1%の富の割合 | 上位0.1% | % | quarter | 8.6 | 14.4 |
| `st_us_wealth_bottom50` | 米国 下半分の富の割合 | 下半分 | % | quarter | 3.5 | 2.5 |

- 値は `dfa-networth-shares.csv` の「Net worth」列（`TopPt1` と `Bottom50`）。**合計しない**：CSV に「上位1%」の行は無い（`TopPt1` と `RemainingTop1` を足すと合計になる）ので、上位1%は作らない
- **日付は四半期の末日**（1989-09-30、…、2026-03-31）。FRED の CSV は四半期の最初の日（2026-01-01）で書くので、この2つの地層に入る値は、取り込むときに四半期の末日へ寄せる（札から入る値も、地層を調べた値も）。寄せないと同じ四半期が2点になる
- 確認先は DFA のページ（上と同じ）

### 2.3 過去の147点（決定4：一度だけアプリに入れる）

- 2026-09-11 に落とした `dfa.zip`（891KB）の CSV から、1989年7〜9月期〜2026年1〜3月期の147点ずつをアプリの中に書いておく（2本で約1,200字）
- 地層が無い端末に地層を足すとき、一緒に入れる。地層がすでにある端末（隠した地層も）には触らない。消した値を入れ直さない
- 出どころは `csv`（手入力・札・調べた値・API と分ける）。確認先は `dfa.zip` の URL
- FRB はあとの版で過去の四半期を直すことがあるが、入れた値は上書きしない（地層は履歴。同じ日付の値は落とす、は今までどおり）
- 新しい四半期は、2.1 の「必ず見るもの」から札に乗って入る

### 2.4 WID.world ── よく使う出典

- `ws_wid`、周期なし。`https://wid.world/`。取るもの：「各国の富と所得の分布（上位1%・下半分の割合など）。国をまたいで比べるときに。米国は DFA を先に見る」
- よく使う出典は一度も保存されていないときにしか最初の一覧を入れないので、決まった id で、まだ無ければ一度だけ足す

### 2.5 UBS・Knight Frank・Henley

- 出典の一覧にもともと入っていない（コードのメモだけ）。外す作業は無い
- コードのメモに、見送った理由（UBS は 403、Knight Frank・Henley は本文が JS）と、代わりに DFA・WID を入れたことを残す

## 3. 字数

5社すべてに新しい書類がある日の、毎朝のプロンプトの字数（実測は 4 章）。注意の線は 20,000字のまま。

## 4. 確かめること

1. ブラウザ（GitHub Pages と同じ https の外の origin）から、5社の書類一覧が取れる。最初の1回は5社とも節に出る
2. 取り込んだあとは、同じ書類が節に出ない。「開けなかった」と返った会社は次も出る。控えが提出日で入る
3. 書類一覧が取れないときも、プロンプトがコピーされ、理由が出る
4. 5社すべてに新しい書類がある日の字数を測る。20,000字を超えるなら報告し、上限の案を出す
5. 地層「米国 上位0.1%の富の割合」「米国 下半分の富の割合」に147点ずつ入り、2回起動しても増えない
6. 2026-01-01 の日付で来た値が 2026-03-31 に寄り、すでにある値と重ならない
7. 「必ず見るもの」に DFA、「よく使う出典」に WID が1回だけ入る
8. 幅360・320ではみ出さない
