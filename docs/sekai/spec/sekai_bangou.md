## 1. 番号の作り方を変える

### 1.1 形

頭の「種類_日付_」は今のまま、後ろを **100000〜999999 の数字** にする。

| 種類 | 今 | v20.38 から作る分 |
|---|---|---|
| 言葉 | `n_20260914_010` | `n_20260914_483920` |
| 日誌（朝・相談・問い・引く・読む・デッキ） | `j_20260914_002` | `j_20260914_207515` |
| 下書き | `d_20260914_001` | `d_20260914_950164` |
| 札 | `w_20260912_3`（頭は出来事の日付） | `w_20260912_731288` |
| 概念・用語・主体 | `wc_20260914_1`・`wt_…`・`ac_…` | `wc_20260914_118402` など |
| 聞いたこと | `q_20260914_1` | `q_20260914_664031` |

- 乱数は端末の暗号用の乱数（使えなければふつうの乱数）から作る
- 作った番号が「使用中」（1.3）と同じなら作り直す。同じ起動の中で作った番号も覚えておき、同じものを二度出さない（一括入力で一度に何件も作るため）
- 札の頭の日付は、今までどおり**出来事の日付**。ほかは**作った日**

### 1.2 なぜ数字6桁か（回答書で確定）

- 番号から読み取っているのは頭の「種類_日付_」だけ（どの月・年のファイルに入れるか）。後ろの形を見ているのは、札の「お金の流れの続き」を確かめる1か所（`w_` 8桁 `_` 数字）だけ
- 数字6桁ならその確かめをそのまま通るので、**v20.37 までの端末が札を整えても「続き」は消えない**（4.2 で確かめる）
- v20.37 までの端末が作る番号は後ろが 1〜999（言葉・日誌・下書きは3桁の 001〜999）。新しい番号は 100000 以上なので、**古い端末が作る番号と新しい端末が作る番号は重ならない**
- 新しい端末どうしで同じ番号になるのは、同じ種類・同じ日付で作った2件の間で、1組あたり90万分の1

### 1.3 消した印の番号も使用中とみなす（足し）

- 今は、言葉は「言葉とごみ箱」、日誌・下書きは「今あるもの」だけを見て空きを決めているので、**消した番号を使い直す**（履歴に、言葉1件・下書き12件の使い直しがあった）
- 使い直すと、消す前の古い版を持っている端末と合わさるとき、同じ番号の別の中身として扱われる
- v20.38 では、言葉・日誌・下書き・札は**消した印の番号も使用中**に入れる（札はすでにそうしている）。概念・用語・主体・聞いたことには消した印が無いので今のまま
- 乱数にすれば使い直しはほぼ起きないが、確かめる手間はほぼ無いので入れる

**失うもの：** 無し（消した印の数だけ、空きを決めるときに見る番号が増える。今は数十件）。

### 1.4 触らない所

- 瞑想（秒まで同じ時に2台で始めないとぶつからない）
- デッキのカード（デッキごと新しい方が残る作りなので、番号を変えても何も変わらない）
- 予告（v20.37 で直した）・出典・端末の番号・取り込みのまとまり（すでに時刻と乱数）
- 主体・地層の最初から入っている番号（`ac_boj` など固定の名前）
- 今ある番号（作り直し・移し替えはしない）
- 生成への指示に書いてある番号の例（`w_20260902_1` など）。例のままで困らない。**変えると失うもの**：例と実際の番号の形が違うので、生成が短い形を真似て書く危険はある（今も実際の番号をそのまま写させているので、起きるかは測れない）

### 1.5 番号を作り変えて失うもの

| | 値（実測） |
|---|---|
| 読む回のプロンプト（札63個） | +372字 |
| 主語を補う回（札46個） | +263字 |
| 取り込む回（札30個） | +177字 |
| 朝の言葉・相談のキャッシュする部分（言葉165個） | +495字（今ある言葉は短い番号のままなので、**伸びるのは新しく作った言葉の分だけ**。165件全部が新しい形になったときの値） |
| 関連づけのキャッシュする部分 | 同上 |

- 上の字数は、全部の番号が新しい形になったときの上限。今ある番号は変えないので、しばらくは小さい
- 同じ日の中で番号から作った順が分からなくなる（今、番号で順を見ている所は無い）
- 番号が長くなると、生成が番号を写し間違える危険が増える（**測れない**。写し間違えた札は「端末に無い札 N件は無視」に数えられる）

## 2. 同期でぶつかったら出す（回答書の「追加で考えてほしいこと」）

**賛成。** 手間は小さく、同期は遅くならず（2.5）、毎回は出ない（2.3）。

### 2.1 何を「ぶつかった」とみなすか

同期で2つの版を合わせるとき、**同じ番号のものが両方にあり、作った日時が違う**もの。

- 同じものを2台で直しただけなら、作った日時は同じ（作ったときの日時を持ち回るため）。違うのは、別々に作られたときだけ
- **実データで確かめた：** 今の kotoba-data で、言葉165・日誌38・札（6〜9月）120・概念44・用語118・主体90・聞いたこと2件、**作った日時が無いものは0件**
- **履歴で確かめた：** 9/7〜9/14 の履歴で「同じ番号の作った日時が変わった」ものは、予告の3本のほかは、試しの頃の作り直し・世界を捨てた後の使い直し・消した番号の使い直し・固定の番号の入れ直しだけ（`houkoku/2026-09-14_bangou.md`）
- **固定の番号は見張らない：** 主体の最初から入っている分（`ac_boj` など22件）は、端末ごとに入れたときの日時が付くので、見張ると「ぶつかった」と誤って出る。番号の形が「種類_8桁の日付_数」（予告は「_英数字」）のものだけを見張る

### 2.2 見張る場所

同期で合わせる所は種類ごとに1つずつある。そこで、両方にあった同じ番号の作った日時を比べる。

| 種類 | 合わせる所 |
|---|---|
| 言葉（月のファイル・data.json の両方の道） | 言葉を合わせる所 |
| 日誌 | 日誌を合わせる所 |
| 下書き | data.json を合わせる所の中の下書き |
| 札 | 札の月を合わせる所 |
| 概念・用語・主体 | 概念・用語・主体を合わせる所（1つを共有） |
| 聞いたこと | 聞いたことを合わせる所 |
| 予告 | 予告を合わせる所 |

残す方の決め方は**今のまま**（更新日時の新しい方）。見張りは「消える方を控えて、数える」だけで、何を残すかは変えない。

### 2.3 出す場所と文

**同期の1行（画面の一番上の「同期済み …」）：**
```
同期済み 9/14 10:12　※ 同じ番号が2つありました。1件（新しい方を残しました）
```
- 出すのは、**まだ見ていないぶつかりがあるときだけ**。設定の記録を開くと消える
- ぶつかりが無い端末では何も変わらない

**設定 → 使用量の欄（「切り詰めた文」の下）：**
```
同じ番号でぶつかったもの　2件
  言葉　n_20260914_010　9/14 10:12
    残した方：「怒りを反復して…」（作った 9/14 08:01）
    消えた方：「比べない…」（作った 9/14 08:03）　［消えた方をコピー］
```
- 新しい順に、最大50件
- ［消えた方をコピー］は、消えた方の本文（言葉なら言葉・出典・自分の言葉、札なら fact・detail・出典 URL など）を、人が読める形でクリップボードに入れる。**戻すのは人が手で行う**（新しく言葉を足す・貼り直す）

### 2.4 消えた方の中身を控える

- **控えられる。** 合わせる瞬間には、消える方も手元にあるので、そのまま写せる
- 控える場所：**その端末の中だけ**（端末の保存場所に、最大50件。1件の大きさは、保存している形の文字数で、言葉が平均約1,900字・札が平均約1,900字・札の最大約2,500字（実測）なので、50件で多くて約12万5千字）
- 50件を超えたら古いものから消す（**控えも黙って捨てない**：「古い控え N件を消しました」を設定の記録の頭に出す）
- 同じぶつかり（同じ番号・同じ2つの作った日時）は1回だけ記録する。送り返しに失敗して次の同期でもう一度合わせても、二重に数えない

**控えを kotoba-data に送らない理由：**
- 送るには新しいファイルと、その合わせ方が要る。控えの控えを合わせる作りになり、手間が今回の直しより大きい
- ぶつかりは、両方の中身を持った端末で合わせたときに必ず見つかる（片方しか持っていない端末では合わせが起きない）。見つけた端末に控えがあれば戻せる
- **失うもの：** 見つけた端末と別の端末からは、消えた方の中身を見られない。その端末のデータを消すと控えも消える

### 2.5 手間と遅さ（実測）

- 言葉165件を合わせる1回：0.164ミリ秒 → 同じ番号の作った日時の比べを足して 0.174ミリ秒（本物のコードで500回の平均）。同期全体は通信で数秒かかるので、**遅くなったと分かる差ではない**
- 見張りのコードは、合わせる所7か所に同じ呼び出しを1行ずつ足す形。記録・表示・コピーは1か所にまとめる

### 2.6 自動で両方残す（反対）

ぶつかったとき、消える方に新しい番号を付けて両方残す案も考えた。**反対。**
- ぶつかった番号を指しているもの（日誌が選んだ言葉、概念・主体の「この札に出てきた」、予告の「元の札」、お金の流れの「続き」）が、**どちらの中身を指していたのか、合わせる時点では分からない**。片方に新しい番号を付けても、指しているものを正しく付け替えられない
- 同期の途中で番号を書き換えると、書き換えた版がさらに別の端末と合わさるので、確かめる範囲が大きく広がる
- v20.38 で番号を乱数にすれば、ぶつかりは古い端末が残っている間の、ほとんど起きない場合だけになる。そのために大きな仕組みを入れるより、**出して・控えて・人が戻す**で足りる

### 2.7 見張りを入れて失うもの

- 同期の1行が長くなることがある（ぶつかったときだけ、記録を開くまで）
- 端末の保存場所を、控え50件ぶん（多くて約12万5千字）使う
- 控えはその端末にしか無い
- 戻すのは手作業（自動では戻らない）
- 誤って出る場合：作った日時が無いもの（今は0件）。v20.37 までの端末で作った「消した番号の使い直し」は、古い版と合わさるときに**正しく**ぶつかりとして出る（中身は別物なので）

## 4. 確かめ方

1. **6種類それぞれ、2台で同じ日に同じ種類を作ったとき、両方残る**（回答書の確かめ）
   - 本物のコードを取り出し、同じ状態の「端末 A」「端末 B」で、言葉・日誌・下書き・札（同じ出来事の日付）・概念・聞いたことを1件ずつ作り、合わせて、**12件とも残る**ことを数える
   - 比べとして、v20.37 のコードで同じことをすると6件に減ることも示す
2. **古い版の端末が整えても、札の「お金の流れの続き」が消えない**（回答書の確かめ）
   - v20.37 のコードの札の整え方に、「続き」が新しい形の番号を指す札を通し、続きがそのまま残ることを確かめる
   - 新しい形の番号の札・言葉・日誌を、v20.37 のコードで月のファイルに振り分け、正しい月に入ることを確かめる
3. **番号の形：** 各種類で1万回作り、形（頭・6桁）と重なりなし、消した印の番号を避けることを数える
4. **見張り：**
   - 同じ番号・違う作った日時の言葉・札・概念を合わせる → 同期の1行に出る、設定に出る、控えの中身が消えた方と同じ、［消えた方をコピー］で本文がクリップボードに入る
   - 同じ番号・同じ作った日時（ふつうの直し）→ 出ない
   - 固定の番号の主体（`ac_boj`）の作った日時が違う → 出ない
   - 同じぶつかりを2回合わせる → 1件のまま
   - 設定の記録を開く → 同期の1行から消える
   - 51件目 → 古い1件が消え、そのことが出る
5. **本物のデータ：** 今の kotoba-data を整え直して v20.37 と比べ、違いが0件（番号は作るときにしか変わらないため）
6. **触る確かめ：** 決まった8項目を本当に押す・打つ。この版で触った画面：
   - 言葉の編集で2文字以上打って保存（新しい形の番号になる）
   - 相談・一括入力（API は偽物の返事）で日誌・下書きを作る
   - 世界の取り込む回・聞く回の貼る欄に2文字以上打って「取り込む」を押す（読めない旨が出る）、試しの JSON を貼って札・概念・聞いたことを作る
   - 設定の「同じ番号でぶつかったもの」を開き、［消えた方をコピー］を押す
7. **公開したら、ユーザーに知らせる**（回答書の順番どおり）
