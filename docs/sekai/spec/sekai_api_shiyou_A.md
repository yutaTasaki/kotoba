# 一万日 v19.13 仕様書 — 世界：朝ボタンで米財務省の数字を取り、プロンプトに差し込む（段階 A）

回答書 `sekai_api_kaitousho.md` を受けた、**段階 A だけ**の仕様書です。B（`figures.json`・地層に債務総額）と C（SEC 5社）は、A を1週間使ってから書きます。

**段階 A は何も保存しません。** 押すたびに API から取り、プロンプトに差し込んで捨てます。壊れてもデータは減りません。

数字と判定は、2026-09-11 に実際に API を叩いて確かめたものです（直近60営業日・12,780行）。

## 0. 押したときに起きること

```
朝タブの「今日の取り込み（N件）」を押す（または 世界 → 取り込む →「プロンプトをコピー」）
  ① ボタンが「数字を取っています…」に変わる（2度押しを防ぐ）
  ② API を3〜4本、同時に叩く（見込み 2〜4秒。15秒で打ち切り）
  ③ 取れた数字で「■ 今日の数字」の節を作り、プロンプトの「毎回必ず見るもの」の直後に差し込む
  ④ コピーする（今までどおり）。取れなかったときは、理由を1行出して、数字なしのプロンプトをコピーする
  ⑤ 取り込む画面の、プロンプトの下に1行：「今日の数字：9/9 分を取りました（2.8秒）」
```

**2つの入口の両方に入れます。** 朝の「今日の取り込み」と、世界 → 取り込むの「プロンプトをコピー」。どちらも同じプロンプトを作る関数（`worldPromptText`）を通るので、片方だけにすると、押す場所で中身が変わってしまいます。

## 1. 叩く API（すべて鍵なし・無料・ブラウザから直接）

| 何 | エンドポイント（`https://api.fiscaldata.treasury.gov/services/api/fiscal_service/` の下） | 取り方 | 実測 |
|---|---|---|---|
| 入出金（明細） | `v1/accounting/dts/deposits_withdrawals_operating_cash` | `filter=record_date:gte:（今日−95日）`・`fields=record_date,transaction_type,transaction_catg,transaction_today_amt`・`page[size]=10000`・`sort=-record_date`。**`meta.total-count` が 10,000 を超えたら2ページ目も取る**（60営業日は約12,800行なので、ほぼ毎回2ページ） | 1ページ目 1.6秒・転送 66KB（gzip。ブラウザが自動で付ける）、2ページ目 2.4秒 |
| TGA の残高 | `v1/accounting/dts/operating_cash_balance` | `filter=record_date:gte:（今日−14日）`・`sort=-record_date`・`page[size]=100` | 1秒・7KB |
| 政府債務の総額 | `v2/accounting/od/debt_to_penny` | `sort=-record_date`・`page[size]=2` | 1秒 |

- 4本を `Promise.allSettled` で同時に叩きます。どれかが落ちても、取れた分だけで節を作ります。
- 全体に **15秒の打ち切り**（`AbortController`）。
- ヘッダを足さない GET なので、事前の問い合わせ（CORS のプリフライト）は起きません。
- 人が開ける確認先（すべて開くことを確かめた）：
  - 入出金：`https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/deposits-and-withdrawals-of-operating-cash`
  - 残高：`https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/operating-cash-balance`
  - 債務：`https://fiscaldata.treasury.gov/datasets/debt-to-the-penny/`

### 気をつける癖（実測で見つけたもの）

- **TGA の終値の欄（`close_today_bal`）は毎日空です。** 値は「Treasury General Account (TGA) Closing Balance」の行の **`open_today_bal`** に入っています。前日比は、同じ日の「… Opening Balance」の行の `open_today_bal` との差で出します（9/9：843,705 − 880,019 = −36,314 百万ドル）。**保存しなくても前日比が出るので、段階 A でも TGA を出せます。**
- 同じ日の「Total TGA Deposits (Table II)」「Total TGA Withdrawals (Table II) (-)」の `open_today_bal` が、その日の入金・出金の合計です。
- 金額の単位は **百万ドル**（債務だけドル）。
- 米国の公表は日本時間の翌朝5時ごろ。**日本の朝に取れるのは、米国の1〜2営業日前の分**です。節の見出しに「米国の 9/9 分」と必ず書きます。
- 国債の発行・償還は、国債の API（`public_debt_transactions`）を使いません。そちらには政府内部の勘定（Government Account Series、1日6,000億ドル規模）が混ざっていて紛らわしいためです。入出金の明細にある「Public Debt Cash Issues (Table IIIB)」「Public Debt Cash Redemp. (Table IIIB)」を使います。

## 2. 定例と「その日だけ」を分ける規則（機械が毎朝やる）

**対象の日** ＝ 入出金の明細にある一番新しい `record_date`。**比べる履歴** ＝ その日より前の、明細にある営業日のうち新しい60日。

### 2.1 先に外すもの
- 項目名（`transaction_catg`）が空の行＝入金・出金の合計行。
- 「Table IIIB」の行＝国債の発行・償還（毎日の借換え）。→ 代わりに **発行 − 償還の純額を1行**。

### 2.2 項目ごとに持つもの（その場で計算し、保存しない）
- **中央値**：履歴60日のうち、0でない日の `transaction_today_amt` の中央値。
- **出る日の割合**：履歴60日のうち、0でない日の割合。
- **山**：履歴のうち「中央値の3倍以上、かつ3億ドル以上」だった日。
- **山の中央値**：山だった日の額の中央値。

### 2.3 分け方（上から順に当てる）
| 分類 | 条件 | 出し方 |
|---|---|---|
| **定例（決まった日の山）** | 山が2回以上あり、今日の額が「山の中央値」の 0.5〜2倍 | 「動き」に出さない。定例の候補 |
| **定例（毎日）** | 出る日の割合が80%以上で、山が1回も無い | 同上 |
| **動き** | 今日の額が中央値の3倍以上かつ3億ドル以上、または60日で初めて出た項目で3億ドル以上 | 大きい順に最大5件。倍率つき |
| それ以外 | — | 出さない |

- 定例は、今日の額が大きい順に **2件だけ**「定例（参考）」に1行（回答書3のとおり、1行を超えない）。
- **判定を「山の間隔」でなく「山の規模」にした理由**：最初は「山がほぼ等間隔に3回以上」で試しましたが、社会保障の給付（月4回・間隔5営業日）と月初の給付（60営業日に過去の山が2回しかない）が毎回「動き」に出ました。規模で見ると両方とも定例に回ります。

## 3. プロンプトに差し込む節

**場所**：「■ 毎回必ず見るもの」の直後、「■ よく使う出典」の前（回答書6：今日の数字は材料なので上に置く）。

**見本（9/9 の実データ）**
```
■ 今日の数字（API で取ったもの。事実。米国の 9/9 分。日本の朝に取れるのは米国の1〜2営業日前の分）
- 米財務省の口座残高（TGA）：8,437億ドル（前日比 −363億ドル。入金 159億ドル・出金 523億ドル）
  確認先 https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/operating-cash-balance
- 米国の政府債務総額：40.07兆ドル（前日比 −98.1億ドル）
  確認先 https://fiscaldata.treasury.gov/datasets/debt-to-the-penny/
- 国債（市場で売ったもの）：発行 21.3億ドル − 償還 12.8億ドル ＝ 純額 +8.6億ドル
- 9/9 の出入りで、ふだん（過去60営業日の中央値）から外れたもの（3倍以上・3億ドル以上）：
  入 Taxes - Non Withheld Ind/SECA Electronic 35.8億ドル（ふだんの5.8倍）
  出 Dept of Education (ED) 22.8億ドル（ふだんの3.7倍）
  確認先 https://fiscaldata.treasury.gov/datasets/daily-treasury-statement/deposits-and-withdrawals-of-operating-cash
- 定例（参考）：SSA - Benefits Payments 331億ドル（決まった日の山）、HHS - Grants to States for Medicaid 56億ドル
使い方：
- 上の数字は事実として使ってよい。札の url は上の確認先。差と倍率は計算し直さない。
- なぜ動いたかは検索で確かめる。確かめられなければ why と read に推定として書き、confidence を下げる。
- 外れたものを札にするときは、from／to を書く（例：米財務省 → 教育省の支払い先）。
```

- **項目名は API の英語のまま**にします。言い換えはチャットに任せます（こちらで訳すと、訳の誤りが事実の顔をして入るため）。
- **金額の書き方**：百万ドルの値を 100 で割って「億ドル」と書きます（同じ通貨の桁の書き換えで、換算ではありません）。100億ドル以上は整数にカンマ、それ未満は小数1桁。債務は兆ドルで小数2桁。
- **差は計算済みで渡す**：前日比（TGA・債務）と倍率は端末が計算し、「計算し直さない」と書きます。差を出すのは、同じ量の同じ単位の2つの日付のあいだだけです（TGA の終値と始値、債務の2日）。

### 取れなかったとき
節を丸ごと、この2行に置き換えます（64字）。
```
■ 今日の数字（API）
今日の数字は取れませんでした（DTS：公表がまだ。最新は 9/8 分のまま）。数字は検索で確かめる。
```
一部だけ取れたときは、取れた行だけ出し、取れなかったものを1行で書きます（例：「政府債務の総額は取れませんでした（通信の打ち切り）」）。

## 4. 理由を必ず書く（回答書9）

取り込む画面のプロンプトの下と、取れなかったときの節の中に、同じ理由を書きます。

| 起きたこと | 見分け方 | 出す文 |
|---|---|---|
| 通信できない | `fetch` が例外（オフライン・DNS）／打ち切り | 「通信できませんでした」／「15秒で打ち切りました」 |
| 相手のエラー | HTTP が 200 以外 | 「相手が 503 を返しました」 |
| **形が変わった** | JSON が読めない、`data` が無い、必要な欄（`record_date`・`transaction_catg`・`transaction_today_amt`、TGA の Closing Balance の行）が無い | 「返ってきた形が変わっています（〇〇が無い）」 |
| **公表がまだ／止まっている** | 最新の `record_date` が、今日から数えて米国の営業日で3日より古い | 「公表がまだです（最新は 9/8 分）」 |
| 取れた | — | 「今日の数字：9/9 分を取りました（2.8秒）」 |

「公表がまだ」は数字を出したうえで添えます（古い日付の数字でも、見出しに日付があれば間違いにはならないため）。

## 5. コピーの作り直し（iPhone の Safari 対策）

**いまのコピーは、押した直後に `navigator.clipboard.writeText` を呼んでいます。数字を取る2〜4秒の待ちを挟むと、iPhone の Safari は「押した瞬間の操作」と見なさず、コピーが失敗します。**

直し方：
- 押した瞬間に、中身が後で決まるコピーを始めます：`navigator.clipboard.write([new ClipboardItem({ 'text/plain': 文を返す Promise を Blob にしたもの })])`。Safari と Chrome はこの形で、待ちの後の中身を書けます。
- `ClipboardItem` が無い、または失敗したら、今までどおり **貼る欄にプロンプトを出し、「コピーできませんでした。下の欄から選んでコピーしてください」**。押しても何も起きない、にはなりません。
- この直しは、世界の2つの入口だけに入れます（ほかの画面のコピーは待ちが無いので、今のまま）。

**Yuta さんに確かめてほしいこと**：iPhone で朝のボタンを押して、コピーできたか。できなければ上の逃げ道が出るはずです。

## 9. 決めていないこと（確認したい）

1. **2つの入口の両方に入れる**でよいか（推奨：両方。押す場所で中身が変わらないように）。
2. **項目名を英語のまま**でよいか（推奨：英語のまま。訳はチャットに任せる）。
3. **金額を「億ドル」で書く**でよいか（百万ドルの値を100で割るだけの、桁の書き換え）。それとも API のまま「百万ドル」で書くか。
