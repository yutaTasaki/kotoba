## 1. ［Claude に聞く］で url を出させる（v20.44）

### 1.1 今

- 札の依頼4つ（やさしく説明・なぜ今なのか・日本にどう効くか・反対の見方は）と主体の依頼1つは、末尾に共通の決まりを付けている：「web 検索を使ってよい。出典のある事実と推測を分ける」「見出し・箇条書き・太字を使わない」「前置きを書かない」「最初から全部書かない」
- **url を求める言葉がどこにも無い。** 9/14 の本人の会話では url が出ず、戻した24件に url が0件だった

### 1.2 案（3つ比べた）

| 案 | 中身 | 読みやすさ | url が出る見込み |
|---|---|---|---|
| A 本文の中に出典を添える | 事実の文の後ろに（媒体 日付 url） | **悪い。** 300字の中に url が並び、「やさしく説明」が読めなくなる | 高い |
| B 依頼の種類で変える | 「なぜ今」「反対の見方」だけ出典を出させる | 「やさしく説明」は読みやすい | **低い。** 本人は「やさしく説明」から始めていた。そこで出ないと、続きの会話にも出ない |
| **C 本文と分けて、最後にまとめる（勧める）** | 本文には url を書かない。最後に1行空けて「出典」とだけ書き、本文で使ったページを1行に1つ | 本文は今と同じ。出典は最後に固まるので、読むときは飛ばせる | 高い。**続きの質問にも同じ形で**と書いておく |

**勧める：C。** 4つの依頼すべてと主体の依頼に付ける。概念・用語の依頼（やさしく説明・この概念を厚くする）には付けない（出来事ではなく考え方の説明なので、出典が要らない）。

### 1.3 足す文（C）

```
- 本文には url を書かない。
- 最後に1行空けて「出典」とだけ書き、本文で使ったページを1行に1つ、「媒体名 日付 url」の形で並べる。
  web 検索で実際に見たページだけ。見ていないページ・覚えている url を書かない。
  出典の行は、上の字数にも「箇条書きを使わない」にも数えない。
- この会話の続きで私が質問したときも、同じ形で最後に出典を並べる。
```

- 「見出し・箇条書きを使わない」と食い違わないよう、出典の行は例外と明記する
- 失うもの：返事の最後に出典の行が増える（1回の返事で数行）。字数の決まり（300字）は本文だけに当てるので、返事全体は長くなる

## 4. 調べたことを札にする（v20.45・第2段）

### 4.1 札にできる件

戻した記録の1件ずつのうち：

| 条件 | 札にする欄を出すか |
|---|---|
| 種類が「事実」（did）で、お金の動き（flow）がある | **出す** |
| 事実でもお金の動きが無い | 出さない（第2段はお金の動きだけ。回答書どおり） |
| 述べた理由・推定・種類なし | 出さない |
| もう札にした（札の番号を持っている） | 出さない。「札にした（押すと開く）」 |

9/14 の本人の記録では、**JPモルガン → 買収目的会社（後にEA） 200億ドル** と **PIF・シルバーレイク・アフィニティ → EAの株主 550億ドル**（元の札と同じ中身）の2件が当たる。

### 4.2 札にする欄

件の横の［札にする］を押すと開く：

```
 ┌ 札にする ────────────────────────
 │ 何が起きたか（40字まで） [JPモルガンが買収資金200億ドルを融資]  22/40
 │ 日付 [2026-08-04]   この日付だと地図（直近90日）に出ます
 │ 動かした側 [JPモルガン]
 │ お金の動き  出す側[JPモルガン] 受け取る側[買収目的会社（後にEA）]
 │             何[買収資金の融資] 額[200億ドル]
 │ 出典 [報道 2025年10月]
 │ url  [                                  ]
 │      （チャットが示した url があれば最初から入っている）
 │ ［url を開く］
 │   開いたら、この内容が書いてあったかを押してください
 │ ［書いてあった］ ［開けなかった・書いてなかった］
 │ 元の札とのつながり
 │   ( ) この動きの前（このお金が元の札の動きに使われた）
 │   ( ) この動きの後（元の札の動きのお金がここへ行った）
 │   (•) どちらでもない
 │ ［札を作る］
 │ （状態の1行）
 └──────────────────────────────
```

- 欄は全部、戻した記録の値を最初に入れておき、人が直せる
- 何が起きたか：文字数を出す。**40字を超えていたら［札を作る］を押せない**（足3。今の取り込みは黙って40字で切るため）
- 日付：日付の形でなければ押せない。今日より後なら押せない（今の取り込みと同じ）。直近90日に入るかを1行出す（足4）
- 動かした側：空でもよい（空なら札の「動かした側」は無し）
- 入れた文字は、札を作るまで端末のメモリに持つ（第1段の貼る欄と同じ。url を開きに行って戻ったときに消えないため）

### 4.3 url を開いて確かめる（回答書 1・「仕組みで確かめさせる」）

| 状態 | ［書いてあった］ | ［札を作る］ |
|---|---|---|
| url が空 | 押せない | 押せない。「url を貼ってください」 |
| url がある・［url を開く］をまだ押していない | **押せない** | 押せない。「url を開いて確かめてください」 |
| ［url を開く］を押した | 押せる | 押せない |
| ［書いてあった］を押した | — | **押せる** |
| url の欄を書き換えた | 開く前に戻る | 押せない |

- ［url を開く］は新しいタブ（iPhone では Safari）で開く。**アプリは url を取りに行かない**（ほかのサイトの中身はアプリから読めない。読めても「書いてあったか」は人が決める）
- ［書いてあった］：押した日時と url を戻した記録の件に残す（`urlCheckedAt`・`urlChecked`）
- ［開けなかった・書いてなかった］：その url と日時を件に残し（`urlFailed`：何回でも足す）、url の欄を空にして「別の url を貼ってください」。**件は消さない**
- 失うもの：札を作るたびに、人が url を開いて読む手間が残る。回答書の「開けない url・作り話の url が混ざる危険」を防ぐための手間で、仕組みで省かない

### 4.4 札を作る

［札を作る］を押すと：

1. 今の取り込み（朝の取り込みと同じ入口）に1件だけ通す。重複（±3日で url が同じか、文が似ている）・日付・url の確かめも今のまま
2. 通らなければ理由を出して、何も保存しない（「似た札がもうあります：8/4 サウジ政府系ファンドが…」など）
3. 通ったら、戻した記録の件に `cardId`（作った札の番号）・`cardAt`・`rel`（前／後／どちらでもない）を残す
4. 作った札の欄：
   - **確度は付けない**（生成が付ける値なので）
   - 読んだ日（readDate）は今日（本人が作った＝見た）
   - 動かした側に、した事＝何が起きたか。述べた理由・推定は空
   - 概念・用語・地層は付けない
5. 主体が一覧に無ければ、今の取り込みと同じく足される（JPモルガンなど）。国は分からないまま → **地図では「場所不明」に入る見込み**。主体の画面の「国」から直せる（今ある）

**元の札は書き換えない。** 元の札の `flow.after`・`updatedAt` も触らない。

### 4.5 自分で作った札の見え方（足6）

- 札を開くと、一番上に「自分で調べて作った札（元の札：8/4 サウジ政府系ファンドが…）」の1行。押すと元の札を開く
- 一覧の右端に「自分で作った」（白い小さな字）。**見え方は実装のとき画面写しで今の「調べた」と並べて見る**
- 地図の白い線は第3段（仕様書 `sekai_nodo.md`）

### 4.6 読む回・お金の鎖

- **読む回の枠に入れない**（足5）：自分で作った札の番号の一覧（戻した記録の `cardId` から作る）を、読む回の選び方で最初に除く
  - 失うもの：自分で作った札に AI の推定（思惑）が付かない。付けたいときは、自分で調べて推定として戻す
- **お金の鎖**：`rel` が「前」なら「作った札 → 元の札」、「後」なら「元の札 → 作った札」を、鎖を作るときに足す（元の札の `flow.after` は書き換えずに、記録から読む）
- 朝の取り込み・問い・答え合わせ・［Claude に聞く］の素材は、今の札と同じ扱い（自分で作った札も「すでにある札」として重複判定などに使われる）

### 4.7 データ（戻した記録の件に足す欄）

| 欄 | 中身 |
|---|---|
| urlBy | `chat`（取り込んだときに url があった）。人が貼った url は `self` |
| urlCheckedAt・urlChecked | ［書いてあった］を押した日時と、そのときの url |
| urlFailed | ［開けなかった・書いてなかった］の `{url, at}` の並び |
| cardId・cardAt | 作った札の番号と日時 |
| rel | `before`・`after`・`''` |

- 件を書き換えたら、その戻した記録の `updatedAt` を進める（合わせ方は第1段と同じ：新しい方が勝つ）
- 失うもの：2台で同じ記録を同時に札にすると、片方の `cardId` の書き込みが負ける。札そのものは残るが、記録からの印が1つ消える。もう一度［札にする］を押すと、重複の確かめで「似た札がもうあります」になる
