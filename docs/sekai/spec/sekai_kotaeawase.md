## 1. 答え合わせのプロンプト

### 1.1 置き場所

予告の画面（世界 → 予告）の「期限が来た（押して確定してください）」の上に、次を置く。

```
期限が来た予告 1本
［答え合わせのプロンプトをコピー］
（返ってきた JSON を貼る欄）
［答え合わせを取り込む］
（結果の1行）
```

- 期限が来た予告が0本のときは、この塊を出さない（押しても何も起きないボタンを作らない）
- ホームの「待っている予告 N本・期限が来たもの N本 ▸」は今のまま（押すと予告の画面へ）

### 1.2 載せる予告

- 対象：**期限が来て、まだ押していない、畳んでいない**予告
- 並べ方（足2）：
  1. まだ見立てが付いていないもの（期限の古い順）
  2. 1 が0本のときだけ、見立てが付いているもの（見立てを取り込んだ日時の古い順）＝聞き直し
- **1回10本まで。** 残りがあれば、コピーしたときの1行に「ほか N本は、取り込んだ後にもう一度コピーすると出ます」
- 押したときに組み立てる。中身は全部端末にあり、通信は要らない

**足2 の理由：** 見立てが付いた予告も「まだ押していない」ので、そのままでは次のコピーにも同じ予告が載り、「ほか N本は次に」が回らない。

### 1.3 中身（案。実装で文面を整える）

```
（このまま Claude のチャットに貼ってください。返事は JSON だけにしてください。）
あなたは、期限が来た「予告」について、実際に何が起きたかを一次ソースで確かめる係です。
当たり外れを決めるのは本人です。あなたは確かめた事実と、その根拠のページを返します。
今日は 2026-09-15 です。

■ 必ず守ること
- web 検索を必ず使う。検索せずに書かない。
- 当たり（hit）・外れ（miss）と書くときは、確かめに使ったページの url を必ず書く。
  url を書けないなら unverifiable にする。
- 動きが見当たらないことを外れにするときは、動きがあれば載るはずのページ（当たりの印の発表一覧など）の url を書く。
  書けなければ unverifiable と fact:"none"。
- 数字は、ページに書かれているものだけ。換算しない・合計しない。
- 思惑が合っていたかは書かない（本人が決める）。起きたことだけを書く。
- JSON のみ。

■ 期限が来た予告（1本）
[fc_20260913_1]　米財務省が「9月14日に大手金融機関1行以上を制裁対象に指定」（出す／止める）
  期限 2026-09-14 ／ 当たりの印：CNBC
  元の推定：（予告を作ったときの推定）
  元の札：2026-09-11 米財務長官が9月14日に大手銀行を制裁すると予告（CNBC・ユーロニュース、…）

■ 出力形式
{"verify":[
 {"id":"...","verdict":"miss","url":"https://...","fact":"late","factNote":"10月2日に指定を発表（期限の2週間後）",
  "reason":"","sign":"sign","signOther":"","actual":"指定は2行"}
]}
- verdict：hit（当たり）／miss（外れ）／unverifiable（確かめられない）
- url：確かめに使ったページ。hit・miss では必須
- fact（hit のときは空）：late 期限の後に起きた／opposite 逆の動きがあった／none 動きが見当たらない／short 動いたが数字が届かなかった
- factNote：その事実を1行（いつ・何が）。80字まで
- reason（unverifiable のときだけ）：notyet まだ発表されていない／never そもそも公表されない数字だった
- sign：sign 当たりの印の調べ先で確かめた／other 別の出典で確かめた（signOther に名前）／none どこでも確かめられなかった
- actual：予告に数字があるとき、実際の数字を文字のまま（「14.8トン」）。無ければ空
```

- 元の推定・元の札を載せるのは、「何を確かめればよいか」を生成が取り違えないため（予告の what は40字まで、例：「9月14日に大手金融機関1行以上を…」だけでは、どの発表のことか分かりにくい）
- 元の札が端末に無いときは「（端末に無い）」

**字数（試作を本物のデータで組んで測った）：**

| | 字数 |
|---|---|
| 米財務省の1本 | **約1,440字** |
| 10本（期限の近い予告から10本） | **約3,440字** |
| 1本あたり | 175〜255字（元の推定・元の札の長さで変わる） |

実装したら、本物のボタンを押して米財務省の1本で測り直す（回答書の確かめ）。

**失うもの：** 元の推定・元の札を載せる分、1本あたり約130字長い。載せないと、what が短い予告で調べる対象を取り違える危険がある（測れない）。

### 1.4 fact と verdict の組み合わせ

| verdict | fact | url | reason |
|---|---|---|---|
| hit | 空 | **必須** | 空 |
| miss | late・opposite・short・none のどれか（**必須**） | **必須** | 空 |
| unverifiable | 空 か none | なくてよい | notyet・never のどれか（fact が none のときは空でよい） |

- 組み合わせが合わないものは取り込まない（2.2 で数を出す）
- **足1 の理由：** 「動きが見当たらない」は、無いことを示すページが普通は無い。発表一覧のページ（そこに載っていない）を url にできれば外れとして確かめられる。できなければ「確かめられない・動きが見当たらない」として、url なしで印つきで出す

## 2. 取り込む

### 2.1 予告に足す欄

v20.22 の欄（見立て・根拠1行・見立ての日時・地層の数字）はそのまま。次を足す。

| 欄 | 中身 | 上限 |
|---|---|---|
| 根拠の url | 確かめに使ったページ（http/https だけ） | — |
| 事実の種類 | late・opposite・none・short・空 | — |
| 事実の1行 | 生成の factNote | 80字（今の「根拠1行」の欄に入れる） |
| 確かめられなかった理由 | notyet・never・空 | — |
| 当たりの印 | sign・other・none・空 | — |
| 別の出典の名前 | signOther | 40字 |
| 実際の数字 | actual | 60字 |
| **読み違いか（人）** | yes（読み違い）・no（読みは合っていた）・unknown（分からない）・空 | — |
| 読み違いを選んだ日時 | — | — |

- 字数の上限に当たって切ったら、設定の「切り詰めた文」に残す（今の決まり）
- 足5：答え合わせでは地層の数字（evidence）を聞かない。今ある分（今は0本）は表示だけ残す

**失うもの：** 予告1本に欄が8つ増える。**v20.38 までの端末は、予告を整えるときにこの欄を落とす**（予告は決まった欄だけ残す作り）。両方の端末を v20.39 にするまで、答え合わせを取り込まない。

### 2.2 取り込みの決まり

- 貼るのは予告の画面の貼る欄。`{"verify":[...]}` の形
- 1本ずつ：
  - 番号が端末に無い → 取り込まない（「端末に無い予告 N本」）
  - もう押してある・畳んである → 取り込まない（「すでに押してある予告 N本は変えていません」）。**押した結果は機械が変えない**
  - verdict が3つのどれでもない → 取り込まない
  - hit・miss で url が無い（または http/https でない） → **取り込まない**（「※ url が無い当たり・外れ N本を取り込んでいません」）
  - 組み合わせが 1.4 に合わない → 取り込まない（「※ 事実の種類・理由が合わない N本」）
  - それ以外 → 見立てと欄を入れる。**結果（当たり・外れ・確かめられない）は変えない**
- すでに見立てがある予告に入れ直したら、「前の見立てを置き換えた N本」（足4）
- 取り込んだら「答え合わせの候補が N本つきました。見て、押して確定してください」

**失うもの：** 置き換えた前の見立ては残らない（生成の見立てで、人の結果ではない。置き換えた本数は出す）。

### 2.3 画面に出すもの（1本ごと）

押すボタンより上に、今の「生成の見立て」「根拠1行」に続けて出す。

```
9/14まで　米財務省が 9月14日に大手金融機関1行以上を制裁対象に指定
当たりの印：CNBC
生成の見立て：外れ　［URLなし］ ← url が無いときだけ（推定の印と同じ色）
事実：期限の後に起きた（10月2日に指定を発表）
根拠：www.cnbc.com/...（押すと開く）
当たりの印：印の調べ先で確かめた ／ 別の出典で確かめた（ロイター） ／ どこでも確かめられなかった
実際の数字：指定は2行
確かめられなかった理由：まだ発表されていない
［当たり］［外れ］［確かめられない］
```

- **url が無い見立てには「URLなし」の印**（推定の印と同じ色）を、見立ての行の横に付ける（回答書 5）
- url は、押すと別のタブで開く（アプリの外へ出る）
- 外れを押した予告には、ボタンの下に次を出す（回答書 3）：
  ```
  思惑の読み違いか：［読み違い］［読みは合っていた］［分からない］
  ```
  押した方が選ばれた形になる。もう一度押すと外す。当たり・確かめられないを押し直したら、この欄は消さずに残す（押し直しで戻れるように）が、表示は外れのときだけ

**失うもの：** 予告1本の表示が長くなる（最大で6行増える）。

## 6. 確かめ方

1. **米財務省の1本で、本当にボタンを押してプロンプトを作り、字数を測る**（回答書）。コピーした文と、1.3 の決まりが入っているかを見る
2. **期限が重なった日（10本）**：試しのページで期限切れの予告を12本にして、コピーに10本だけ載り、「ほか 2本」が出ること。見立てを10本取り込んだ後にもう一度コピーすると、残りの2本が載ること（足2）
3. **url の決まり**（回答書）：試しの JSON で
   - url の無い当たり・外れ → 取り込まれず、1行に数が出る
   - url の無い確かめられない → 取り込まれ、「URLなし」の印が付く
   - url のある当たり・外れ → 取り込まれ、印なし・根拠の url が出る
   - 組み合わせが合わない（外れで fact 空、確かめられないで reason も fact も空）→ 取り込まれず、数が出る
   - 押してある予告 → 変わらない
4. **人が押す**：取り込んだ後も結果は「まだ」のまま。外れを押すと「読み違いか」が出て、選べる・外せる。ページを開き直しても残る
5. **朝の取り込む回**：プロンプトに答え合わせの節が無いこと（期限切れ1本の状態で字数が約540字減る）。`verify` 入りの JSON を貼ると、札は入り、答え合わせは取り込まれず1行出る
6. **本物のデータ**：今の kotoba-data を整え直して v20.38 と比べ、違いは足した欄（空）だけ
7. **触る確かめ**：決まった8項目。予告の画面の貼る欄に2文字以上打って［答え合わせを取り込む］（読めない旨が出る）、［答え合わせのプロンプトをコピー］、［当たり］［外れ］［確かめられない］、読み違いの3つを本当に押す

## 7. 消えないため・嘘をつかないための決まり

| 危険 | 対策 |
|---|---|
| 機械が当たり外れを確定する | 取り込みは見立てと欄だけ。結果は押したときだけ変わる（今のまま） |
| url の無い見立てを事実と見間違える | 当たり・外れは url 必須。確かめられないの url なしには印（2.3） |
| 取り込めなかったものが黙って消える | 理由ごとに数を1行（2.2・3.2） |
| 思惑の読み違いを生成が決める | 聞かない。人が選ぶ欄（2.3） |
| 古い端末が欄を落とす | 両方の端末をそろえてから取り込む（5.） |
