# 一万日 v15 仕様書 — 世界：お金の流れを追う

v14.1 までの世界タブに足す。既存の言葉・引く・相談・問い・撮る・筋トレ・散歩には触らない。**API は使わない**。

## なぜ足すのか

本人の言葉：

> お金の流れがめっちゃ大切だと思う。なぜなら人の意思→行動→お金になるから。お金の動きからすべてが逆算できる。

いま `flow` は札1つに1つ。**金額が縦に並ぶのは主体の時系列だけ**で、主体をまたいで「誰から誰へ」を見る手段がない。

1日ぶんの札だけでも 財務省15兆円／欧州委員会35億ドル／IMF1.4億ドル／NATO100億ドル。**言葉は安いが金額は嘘をつきにくい。** 桁と方向が並ぶだけで、誰が本気かが分かる。

### 追える範囲（先に画面で認めておく）

| | 例 |
|---|---|
| よく追える | 中銀の資産・買い入れ、政府の予算・国債発行・介入実績、IMF/世銀の融資、軍事支援の割当、貿易収支・経常収支 |
| 部分的に追える | 企業の設備投資（決算ベース・遅い）、対外投資残高（四半期遅れ）、エネルギー貿易額 |
| ほぼ追えない | 誰がいつ何を売買したか、実需と投機の内訳、非公開の政治資金、迂回取引 |

**公のお金は追えるが、私のお金は追えない。** 逆算できる相手は公的主体に限られる。この表を画面に置き、**追えないものを追えるように見せない**。

## 1. 残高は地層へ

### 1.1 なぜ flow に入れないか

残高（外貨準備1兆2075億ドル、日銀の資産規模）を `flow` に入れると、**`from` も `to` も無い flow ができる。それは「流れ」ではない。**

そして**残高を置く器は既にある**——地層の `levels`。地層13件のうち5件（債務/GDP、外貨準備、日銀の資産、軍事費、中銀の金保有）はまさにお金の量。

これで**地層の最大の弱点が消える**。いま13件中12件が「値は未記入」で、四半期に一度手で入れる設計だった。**札を取り込むたびに勝手に埋まる**ようになる。

### 1.2 札が値を運ぶ

```
ev.levels = [{ stratumId: 'st_jp_fx_reserve',
               value: '1兆2075億ドル',      // 出典の書き方のまま
               at: '2026-09-07' }]           // 省略時は札の eventDate
```

**`source` と `url` は生成に書かせない。札のものを使う。**

- 生成の手間が減る（同じ出典を2回書かせない）
- **札の `url` は既に検証済み**（http(s) チェック・存在確認を通っている）。生成に別途書かせると、そこだけ未検証の URL が入る

保存される形：

```
stratum.levels = [{ value, at, note,
                    source: '財務省 外貨準備等の状況 2026-09-07',   // 札の source
                    url: 'https://...',                              // 札の url
                    via: 'card' | 'hand',
                    eventId: 'w_...' }]                              // via:'card' のとき
```

### 1.3 縛り（ここが一番の捏造の入り口）

生成が地層の値を作れる以上、**fact と同じ厳しさで縛る**。

1. **出典に数字が書かれているときだけ。** 推測・概算・「およそ」は入れない
2. **`source` と `url` が無い札からは入れない**（札に url が無いものは取り込み時点で落ちているので、実質いつも満たす）
3. **同じ日付の値は上書きしない。** `levels` は履歴なので**足すだけ**。同じ `at` が既にあれば**落とす**
4. **一覧に無い `stratumId` は落とす**（地層と同じ。生成に地層を作らせない）

**3 の例外：手で入れる分は上書きしてよい。** 地層の詳細から手で入れるのは本人の判断で、打ち間違いを直せないと困る。**`via: 'card'` のときだけ上書きしない。**

取り込み結果に出す：`地層の値 N件を入れました（同じ日付で重なった M件は落としました）`。

## 2. `flow` に足す2つ

```
ev.flow = { from, to, what, amount, value, unit,
            span: '',                       // v15: 累計のとき「2022年以降」など。1回の動きなら空
            strata: ['st_jp_fx_reserve'] }  // v15: この金が動かした地層。0〜2件
```

### 2.1 `span` — 累計と1回を分ける

「NATO → ウクライナ 100億ドル」が**1回の拠出**なのか**2022年以降の累計**なのかで意味がまるで違う。混ぜると、一覧で累計だけが大きく見える。

- 1回の動き → `span` は空
- 累計・期間合計 → `span` に期間（`2022年以降` `2026年度` `7月30日〜8月26日`）

一覧では **`span` のある行に期間を添え、1回の動きと視覚的に分ける**（薄い括弧）。

### 2.2 `strata` — お金が地層を動かす

「介入15兆円 → 外貨準備が減る」。札の `strata` と同じ形（一覧の id から選ぶ、無ければ空）。

繋げると、地層の詳細でこう見える：

```
日本の外貨準備
1兆2075億ドル（2026.9/7 ・ 3日前）
  出典：財務省 外貨準備等の状況 2026-09-07  [開く]

この地層を動かしたお金
  9/8   財務省 → 為替市場   15兆3993億円   円買い介入
  7/14  財務省 → 為替市場    5兆円         円買い介入

これまで
  1兆2075億ドル  2026.9/7   財務省 外貨準備等の状況
  1兆2800億ドル  2026.6/30  財務省 外貨準備等の状況
```

**「残高が減った」と「その分どこへ流れたか」が同じ画面に並ぶ。** これが「お金の動きから逆算する」の実物。

**ただし単位が違う**（外貨準備はドル、介入は円）。足し算をしないので壊れないが、**「15兆円出したから◯◯億ドル減った」とは言えない**——そこは自分で読む部分として残る。画面でも繋げて見せるだけで、引き算はしない。

## 3. お金の一覧

### 3.1 置き場所

**出来事タブの中に型の切替を置く。**

```
[主体] [出来事] [概念] [予測]
        └ [札] [お金]
```

v17 のタブ再編で出来事タブが「探す」に畳まれるとき、**お金の型もそのまま一緒に移る**。いま独立したタブを作ると、v17 で作り直すことになる。

### 3.2 形

```
お金の流れ                        追えるのは公のお金だけ ▸

円
  財務省 → 為替市場                                    2回
    9/8    15兆3993億円   円買い介入
    7/14    5兆円         円買い介入
  日本政府 → 復興基金
    8/2     3000億円      拠出

ドル
  NATO → ウクライナ
    8/2   100億ドル       軍事支援  （2022年以降）      ← span
  IMF → エルサルバドル
    9/3   1.4億ドル       EFF融資
  欧州委員会 → ウクライナ
    9/5    35億ドル       マクロ財政支援
```

- **通貨ごとに区切る**（換算しない）。`unit` が取れなかったものは末尾に「単位が読めないもの」として置く
- 通貨の中は **`from → to` の組でまとめ、組の中を日付の新しい順**
- **2回以上ある組を上に**（ゲートの代わり。繰り返しが自然に目立つ）。同数なら最新順
- **合計を出さない。** 「財務省 合計20兆円」を出した瞬間に、性質の違う金を足した数字が独り歩きする
- 行を押すとその札へ
- 検索あり（`from` / `to` / `what` / `amount`）

### 3.3 「追える範囲」の凡例

見出しの右に常時 `追えるのは公のお金だけ ▸`。押すと上の3行の表が開く。**畳めるが、消えない**（凡例は畳めるようにしたが、これは「見えていないものがある」という但し書きなので、常に出す）。

追えないものを追えるように見せないための、唯一の防具。

## 4. 生成プロンプトの差分

3か所。

### 4.1 `flow` に2つ足す

```
- flow：この出来事で動いたお金。無ければ null。無理に書かない。
  from／to は主体名（アクター名か、「為替市場」のような場所）。what は何をしたか。
  amount は出典の書き方のまま（「15兆円」「1.4億ドル」）。換算しない。合計しない。
  出典に金額が無ければ null。
  span：その金額が期間の累計・合計なら、その期間（「2022年以降」「2026年度」）。
        1回の動きなら空。累計と1回を混ぜると、一覧で累計だけが大きく見える。
  strata：この金が動かした「地層」の id を0〜2個。末尾の一覧にあるものだけ。
          例：介入 → st_jp_fx_reserve（外貨準備が動く）
  例：{"from":"財務省","to":"為替市場","what":"円買い介入","amount":"15兆円",
       "span":"","strata":["st_jp_fx_reserve"]}
```

### 4.2 `levels` を新設

```
- levels：末尾の地層の一覧にある量について、この時点の値が出典に書かれていたら。
  無ければ空の配列。0件でよい。
  - 出典に数字が書かれているときだけ。推測・概算・「およそ」は書かない。
  - value は出典の書き方のまま（「1兆2075億ドル」）。換算しない。
  - at は出典に書かれた基準日（YYYY-MM-DD）。書かれていなければ省略してよい。
  - stratumId は末尾の一覧にある id だけ。一覧に無い量は書かない。
  - 出典（source・url）は札のものを使うので、ここには書かない。
  例：[{"stratumId":"st_jp_fx_reserve","value":"1兆2075億ドル","at":"2026-09-07"}]
```

### 4.3 出力形式

```
  "flow":{"from":"...","to":"...","what":"...","amount":"...","span":"","strata":[]},
  "levels":[{"stratumId":"st_jp_fx_reserve","value":"...","at":"YYYY-MM-DD"}],
```

**地層の一覧は既に末尾に差し込まれている**（`strata` のために）ので、`levels` のための追加の差し込みは要らない。プロンプトは **+約400バイト**。

## 6. 守ること

- **換算しない・合計しない。** 為替レートを選んだ瞬間に推定が事実の顔をする
- **残高は `flow` に入れない**（from も to も無い flow は流れではない）
- **`via: 'card'` の値は同じ日付を上書きしない。** 手で入れる分は上書きしてよい
- **地層の値は出典に数字が書かれているときだけ。** 推測・概算を入れない
- `source` と `url` は札のものを使う（生成に書かせない。札の url は検証済み）
- **累計と1回の動きを混ぜない**（`span`）
- **「追えるのは公のお金だけ」を常に画面に出す**
- 一覧に無い `stratumId` は落とす（生成に地層を作らせない）
- 既存のデータは消さない。朝の流れは変えない

## 7. 実装後に見る数字

- **取り込み結果の「地層の値 N件」。** 0件が続くなら、生成が `levels` を書いていないか、一次ソースが残高を出していない
- **13件の地層のうち、何件の「値は未記入」が消えたか。** これが v15 の成否
- **お金の一覧で「2回以上ある組」がいくつあるか。** 0なら、まだ一覧はただのリスト
- `span` の付いた行の割合（累計ばかりなら、生成が1回の動きを拾えていない）
