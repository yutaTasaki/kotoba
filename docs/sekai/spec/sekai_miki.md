### 0.2 仕様にするとき解いたこと（確認の印つき。反対が無ければこのまま進める）

**確認1：割り当てに人が触らないなら、食い違いは機械の決まりで解く**
- 回答書5「132枚の割り当ては人が触らない」と、指示書3.5「食い違った札だけ人が見る」は両立しない。回答書を優先する
- 2回の割り当てで、**両方に共通する幹だけを付ける**。共通が無ければ、どの幹にも付けない
- 食い違いは1枚ずつ見せない。「どの幹とどの幹の間で揺れたか」の表にして、**切り方を直すかの判断**に使う（2.2）

**確認2：「最後に札で裏が取れた日」を持つため、答えは文ごとに持つ**
- 答え1つ＝文の並び（合計150字まで）。文ごとに「裏が取れた日」と根拠の札を持つ
- 「変えなかった」のときも、新しい札が今の答えのどの文の裏になったかを返させる（`backs`）
  - 返さないと、ずっと正しい文ほど「裏が取れた日」が古いまま残り、先に落ちる
- 失うもの：読む回の返事が1幹あたり十数字長くなる

**確認3：出発点と最初の答えは、別の依頼文にせず毎日の回に乗せる**
- 相談では「出発点は別のプロンプト」と勧めたが、回答書の「開かなくても育つ」「人に頼むのは立てるだけ」に合わせて変える
- 出発点：朝の取り込みに、**出発点がまだの幹を1回に1本だけ**載せて探させる（4.1）
- 最初の答え：読む回に、**答えがまだの幹を1回に3本まで**、出発点と枝の一覧つきで載せる（4.2）
- 失うもの

  - 10本の出発点が揃うまで、朝の取り込み10回かかる
  - 最初の答えが揃うまで、読む回4回ほどかかる

### 0.3 段3を始める条件（仕様書への回答で直した）

**段3は、出発点の札と各幹の中心の札に、切れた推定が0枚になったら始める。** 102枚全部は待たない。残りは段3を回しながら直す。

### 0.6 並行と直列（仕様書への回答 3-1）

**並行して進む。** 直列になるのは、次の順だけ。
1. 段0 公開 → 以後、読む回のたびに切れた推定が直る（段1〜段2 と並行）
2. 段1 公開 → 割り直し（1回、座って15回ほど押す） → **ここで幹が立つので、直す順が中心の札から先になる**
3. 段2 公開 → 朝の取り込みのたびに、枝が付き、**出発点を1本ずつ探す**（4.1 を段2に移した。取り込み1回に1本）
4. 段3 公開 → 条件（0.3）を満たした幹から最初の答え（読む回1回に3本まで）

- 直列になる所：割り直し（段1）の後でないと、直す順を幹で決められない・出発点を探せない。出発点が見つかった（または見つからないと返った）幹でないと、最初の答えを書かない
- 見込み（推測。朝の取り込み1日1〜2回、読む回 週2〜3回）
  - 出発点10本：取り込み10回 ＝ 5〜10日

  - 最初の答え10本：読む回4回 ＝ さらに1.5〜2週間
- **合計：段1の割り直しから、全部の幹に最初の答えが付くまで約3〜4週間**（直列の2か月にはならない）。各段の実装と公開の間隔は、本人の実機確認の速さで決まる

## 1. データ（段1で入れる。段2〜4で種類を足す）

### 1.1 置き場所

- **調べたことの月ファイル（`world/dig/YYYY-MM.json`）の `miki` に置く。** 月は記録を作った日の月
- 1件＝一度書いたら変えない記録
  - 直す・外す・閉じるは、新しい記録を足す形にする
  - 例外は、合わせるための `updatedAt` だけ（作った日時と同じ値）
- すべての記録に `id`（`mk_` の記録は `mkr_YYYYMMDD_乱数`）・`type`・`at`・`updatedAt`・`by`（`split`／`import`／`read`／`hito`）を持たせる
- v20.48 の端末は、知らない並び（id と日時を持つ記録）を落とさず書き戻す。2台で合わせるときは id ごとに足し合わせる
- **段1を入れる前に、両方の端末が v20.48 以上であることを確かめる**（v20.47 以前は `miki` を落とす。v20.48 以上の端末があれば、次の同期で書き戻る）

### 1.2 記録の種類

| type | いつ | 中身 | 段 |
|---|---|---|---|
| `open` | 幹を立てた | `miki`（`mk_…`）・`name`（24字まで）・`line`（1行、60字まで。「誰が得をし、誰が払う話か」）・`from`（`split`／`candidate`／`card`）・`fromId`（候補の記録か札の番号）・`strata`（見る地層0〜3）・`center`（中心の札0〜5枚。割り直しは段A の cards、候補は候補の cards、1枚から立てたときはその札） | 1 |
| `rename` | 名前か1行を直した（割り直しで切り方を直したときだけ） | `miki`・`name`・`line` | 1 |
| `attach` | 札を幹にぶら下げた（幹が0本という結果も記録する） | `card`・`eventDate`・`fact`（写し、40字まで）・`miki`（0〜2個、強い順）・`more`（3本目の幹の番号か null）・`src`（`split`／`import`／`read`） | 1 |
| `split` | 割り直し1回分 | `run`（1か2）・`order`（`asc`／`desc`）・`result`（札番号 → 幹の番号の並び）・`same`（同じ出来事の組）・`unknownIds`（知らない番号の件数） | 1 |
| `sameGroup` | 同じ出来事の組（2回とも同じ組のものだけ） | `cards`（2枚以上） | 1 |
| `candAsk` | 候補の節を載せた取り込みを取り込んだ | `cards`（渡した「幹に入らない札」）・`returned`（候補の件数。書かれていなければ null） | 2 |
| `cand` | 新しい幹の候補 | `name`・`line`・`cards`・`why` | 2 |
| `start` | 出発点が決まった／見つからなかった | `miki`・`card`（札番号か空）・`none`（見つからない理由） | 3 |
| `answer` | 読む回が答えを見た（書き直す・足す・変えなかった） | 4.3 | 3 |
| `unknown` | まだ分からないこと を開いた／閉じた | `miki`・`uid`・`text`（80字まで）・`cards`・`kind`（`gap`／`conflict`）・`close`（閉じた記録なら true） | 3 |
| `fcLink` | 予告がどの幹のどの答えを確かめるか | `forecast`・`miki`・`slot` | 4 |

**今の姿は、記録を日時の順にたどって端末で組み立てる**（保存しない）。
- 札 → 幹：その札の最後の `attach`（`src` に関わらず一番新しいもの）
- 幹 → 枝：同じ表の逆。札の中身を開くときは、札番号の日付から月を取る（読み込んでいない月は GitHub から）
- 同じ名前の幹が2本（2台で同時に立てた）：幹の一覧に「同じ名前の幹が2本あります」と出す。自動でまとめない

### 1.3 札・予告・索引には書かない

- 札の欄は増やさない。取り込みの JSON に書かれた幹は `attach` の記録にする
- 予告のファイル・世界の索引・主体のファイルにも足さない（知らない欄を落とすため）

### 1.4 大きさの見込み（推測）

- 週2〜3回の読む回、幹10本、答え1つ150字
  - 1万日で約70〜90MB
  - 1か月のファイルは約0.3MB
- 起動時に全部の月を持つ件は、データ量の相談で別に決める（回答書3）

## 2. 段1：幹を立てて、132枚を割る（v20.50）

### 2.1 段A：幹を立てる

**置き場所**：設定 → 世界 に「幹を立てる（割り直し）」の欄。幹が1本も無いあいだは、世界の画面の一番上にも「幹を立てる ▸」の1行を出す（押すと設定のその欄へ）。

**プロンプト（段A）**
- 渡すもの：非表示でない全部の札の「番号・日付・何が起きたか・なぜ」（実測で約17,900字）と、参考の幹10本（評価の A〜J、名前＋1行。「そのまま使わない」と書く）
- `cards` は1本5枚まで。**決めたとき `open` の `center` に残し、中心の札とする**（切れた推定を直す順と、段3の最初の答えに使う。0.3）
- 返させるもの
  ```
  {"miki":[{"name":"ホルムズ・紅海が詰まる","line":"…","why":"…","cards":["w_…"],"strata":["st_…"]}],
   "same":[["w_…","w_…"]]}
  ```
  - `cards` は、その幹の中心になる札（人が切り方を判断する材料で、割り当てには使わない）
- 規則
  - 8〜12本
  - 1本は「誰が得をし、誰が払うかが同じ話」
  - 1社・1国・1回きりは幹にしない
  - 地名や主体が同じというだけでまとめない
  - `line` は「誰が得をし、誰が払う話か」が分かる1行

**画面**
- 貼って［幹の案を読む］→ 案の並び。1本ごとに次を出す
  - 名前の欄・1行の欄（打てる）
  - 中心の札（押すと fact が開く）
  - ［採る／外す］の切り替え（既定は採る）
- ［この幹で決める］：採った幹が1本以上のときだけ押せる。押すと `open`（`from: split`）を書く
- 決める前なら、案を貼り直してよい（前の案は消える。記録にはまだ何も書いていない）

### 2.2 段B：2回割る

**プロンプト（段B）**
- 渡すもの
  - 決めた幹の一覧（番号・名前・1行）
  - 全部の札の「番号・日付・何が起きたか・なぜ・お金の動き（出し手→受け手）・主体の名前」（実測で約24,000字）
  - 規則（下の3.1 と同じ文）
- 返させるもの
  ```
  {"assign":{"w_…":["mk_a","mk_b"],"w_…":[]},"more":{"w_…":"mk_c"},"same":[["w_…","w_…"]]}
  ```
- 2回目は札の並びを逆にする。**1回目と2回目で、別のチャットに貼る**ことを画面に書く

**画面の順**
1. ［段B 1回目のプロンプトをコピー］→ 貼る → ［読む］
   - 「132枚中130枚に返事、2枚は返事なし」のように数を出す
   - 返事の無い札があれば［返事の無かった札だけもう一度］（その札だけのプロンプトをコピーし、貼ったら1回目に足す）
2. ［段B 2回目のプロンプトをコピー（並びを逆）］→ 貼る → ［読む］（同じ）
3. 比べた結果を出す
   ```
   2回とも同じ幹 96枚
   食い違い 36枚 → 共通の幹だけ付ける 22枚／共通が無く付けない 14枚
   揺れた幹の組：ホルムズ ⇔ エネルギーと利上げ 11枚 ／ 関税 ⇔（幹なし） 8枚 ／ …
   同じ出来事の組（2回とも同じ）9組
   知らない幹の番号：0件
   ```
   - 揺れた組を押すと、その札の fact が並ぶ（読むだけ。割り当ては変えられない）
4. ［この割り当てで入れる］→ 次を書く
   - 2回分の `split`
   - 全部の札の `attach`（`src: split`。共通の幹0本の札も `miki: []` で書く）
   - 2回とも同じ組になった `sameGroup`
5. ［切り方を直す］→ 段A の案の画面に戻る
   - 名前・1行を直す、幹を足す、外す
   - 直した幹は `rename`、足した幹は `open`、外した幹は `open` の取り消しとして `rename` に `closed: true` を書く
   - そのあと段B をやり直す（前の比べた結果は消える。`split` はまだ書いていない）

**決まり**
- 割り当ての1枚ごとの直しは作らない（回答書5）
- 3本目（`more`）は数えるだけ。結果に「3本目を付けたかった 4枚」
- 知らない幹の番号は付けず、数える
- 2回とも付けた幹の順が違うときは、1回目の順

### 2.3 幹の画面（段1の形）

世界の画面の一番上に「**幹 10本 ▸**」の1行を置く。押すと幹の一覧。

**幹の一覧（1本1行）**
```
ホルムズ・紅海が詰まる　枝 29　最後に枝 9/14　答えはまだ
```
- 並びは、最後に枝が付いた日の新しい順


### 4.3 答えの記録

`answer` 1件＝1つの幹の1つの答え（①②③）を1回見た記録。

| 欄 | 中身 |
|---|---|
| `miki` / `slot` | 幹・1〜3 |
| `exit` | `first`／`rewrite`／`add`／`keep` |
| `basis` | `gain`／`contradict`／`zure`／`turn`（rewrite のときだけ） |
| `sents` | 見たあとの答え全体：`[{sid, text, backedAt, cards}]` |
| `dropped` | 150字で落とした文：`[{sid, text, backedAt}]` |
| `why` | keep の理由 |
| `readBatch` | その読む回の番号 |

**文の「裏が取れた日」の決め方**
- `first`・`rewrite` の文、`add` で足した文：その読む回の日
- `keep` の `backs` に書かれた文：その読む回の日に更新
- 書かれなかった文は、前の日のまま
- `rewrite` で、前の文と一字一句同じ文は、前の `sid` と裏の日を引き継ぐ

### 4.4 150字の決まり（回答書ア）

- 足した結果が150字を超えたら、**「裏が取れた日」の古い文から**落とす。同じ日なら前にある文から。150字以下になるまで続ける
- `rewrite`・`first` の文だけで150字を超えたら、前から入るところまで入れ、残りを落とす
- 落とした文は `dropped` に残す（履歴で読める）
- 結果の1行に出す：「ホルムズ ①で1文落とした（裏 9/14）」
- 定数 `WORLD_MIKI_ANSWER_MAX = 150`

- **幹の無い札に幹を付ける**（`mikiCards`）

  - `attach`（`src: read`）を書く。すでに幹がある札には付けない
  - 見込み約700字（幹の一覧が段2と同じ624字＋規則）
