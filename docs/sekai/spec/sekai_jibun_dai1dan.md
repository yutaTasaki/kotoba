## 1. 場所の読み方の直し（6つ）

### 1.1 一般名の言葉を足す

「もう片方と同じ国にいる相手」とみなす言葉に、次の4つを足す。

| 足す言葉 | 救われる動き |
|---|---|
| 売り手 | Alphabet → データセンターの設備・用地の売り手 |
| 製造装置 | TSMC → 先端工程の製造装置・工場 |
| 業者 | ガーナ政府 → 小規模採掘業者 |
| 金融企業 | 中国政府 → 中央金融企業 |

**「工場」は足さない。** 足すと「TSMC → 先端工程と**海外**工場」が台湾の国内になり、GM の「**カナダ**・オンタリオ州の工場」も米国の国内になる。工場は国の外にあることが多い。

### 1.2 括弧つきの主体名を引く

札の名前が、主体の名前の**括弧の前**（または括弧の中）と丸ごと一致したら、その主体として扱う。

- 例：札の「GM」→ 主体「GM（ゼネラルモーターズ）」→ 米国
- 主体の表で括弧つきの名前は、いま2つ（GM（ゼネラルモーターズ）、データセンターの買い手（書類では匿名））
- 同じ名前の括弧なし主体ができたら、今までどおり起動時に括弧つきの方をまとめる（今の決まりのまま）

### 1.3 「・」の前の国・主体を読む

名前の「・」の前が、**国名か主体の名前と丸ごと一致**したら、その国とする（「〜の」「〜向け」の前を読む今の決まりに「・」を足す形）。

- 変わるのは今のデータで2つだけ：「カナダ・オンタリオ州の工場」→ カナダ、「PIF・シルバーレイク・アフィニティ」→ サウジ
- 「・」を含む名前13個を全部当てて確かめた。「ファースト・アブダビ銀行」「アル・ハラフィ建設」「中国の国有銀行・保険会社」などは変わらない
- 結果：GM の動きが**米国 → カナダの線**になる

### 1.4 国の呼び名を足す（試算の途中で見つかった誤り）

いま、次の2本が**間違って国内の動き**として描かれている。

| 動き | いまの描き方 | 原因 | 直した後 |
|---|---|---|---|
| アル・ハラフィ建設 → シリアの発電事業 | サウジの国内 | 国の表に「シリア」が無い（正式名「シリア・アラブ共和国」だけ）。「発電事業」が一般名なので、もう片方のサウジに寄せられた | サウジ → シリア |
| カナダの供給企業 → 米連邦政府の調達枠 | カナダの国内 | 「米連邦政府」が国として読めない。「調達枠」が一般名なので、カナダに寄せられた | カナダ → 米国 |

国の呼び名の表に「**シリア**」（シリア）と「**米連邦政府**」（米国）を足す。

**【実装時に追加】** 国の呼び名の表を作るスクリプトで、英国の呼び名（英国・イギリス）がコメントの中に入っていて表に入っていなかったので直した（「イギリス」は正式名として入っていたので、今のデータへの影響は無し）。また v20.20 で表にだけ足した地域の枠の「欧州」「アジア」が、スクリプトに入っていなかった（作り直すと消える状態だった）ので、スクリプトにも入れた。作り直した表と元の表の違いが「シリア・米連邦政府・英国」の3語だけであることを確かめた。

同じ種類の誤りを今後も見つけられるよう、2.2 の一覧を作る。

### 1.5 EA を主体の表に米国で入れる

**事実：** 主体の表には、手で主体を足す入口が無い。主体は札の「動かした側」からしか増えない。EA はどの札でも動かした側に出てこないので、今のままでは表に入らない。

**やり方：** 起動時に「**アプリが入れる主体**」として EA を1件足す。

| 項目 | 値 |
|---|---|
| 名前 | EA |
| 別名 | エレクトロニック・アーツ、Electronic Arts |
| 国 | 米国（国を決めた印つき。取り込みで上書きされない） |
| 決まった番号 | アプリが入れる主体だと分かる番号にする |

- **足すのは、その番号の主体が表に1件も無いときだけ。** 隠れている（まとめられた）ものも「ある」と数える。こうすると、まとめたり消したりした後に起動し直しても**勝手に戻ってこない**
- 足した結果：「EAの株主」の頭の「EA」が主体として読め、PIF の買収が**サウジ → 米国の線**になる（場所不明 4→3）

**推定の出し方（今の仕組みを使う）：** 主体の詳細の「国」の行に、今ある琥珀の「推定」の印を付け、「アメリカ合衆国　推定（アプリの表で入れた国）」と出す。見分けは決まった番号でするので、**主体のデータに新しい欄は足さない**。

- 手で国を直したら、推定の印は外す（手で決めた国として扱う）

**出さない所：** 地図の線そのものには推定の印を付けない（線に印を付ける仕組みは今無く、作らない）。

### 1.6 生成への指示を1文足す（回答書の c）

お金の動きの書き方の説明に、次の1文を足す。

```
  買い手・出し手が複数の会社のときは、主導する1社を from に書き、ほかの会社は detail に書く。
```

- **これからの札にしか効かない。** PIF の札は 1.3 で読む
- 毎朝のプロンプトが約50字増える。~~今の本当の長さは測っていません~~ **【実装時に測定】** 本物のデータ（今日の数字を除く）で 19,575字 → 19,631字（＋56字）。注意を出す線は今 23,000字（v20.8.1 で 20,000 から上げてあった。仕様書を書いたときの 20,000字は古い値だった）

## 2. 画面に出す（黙って決めない）

地図の下の「場所不明 N件」の並びに、次の2つを足す。**0件のときは押せない形で出す**（件数を必ず出す）。

### 2.1 「・」の前で場所を決めた相手 N件

- 1.3 で場所を決めた動きの一覧。今は2件（GM → カナダ・オンタリオ州の工場、PIF・シルバーレイク・アフィニティ → EAの株主）
- **「・」の後にも別の国名や主体があった名前**には、一覧の**見出し**に「うちN件は「・」の後にもほかの国・主体が並んでいる（先頭で描いた）：名前」と出す（**【実装時に変更】** 行ごとではなく見出しにした。開く一覧は札の一覧をそのまま使っていて、行に注を足すには札の一覧の作りを変える必要があるため）。今のデータには0件。回答書の「米国・日本の〜が来たら画面で分かる形」への答え
- PIF のように、後ろの会社（シルバーレイク・アフィニティ）が主体の表に無い場合は「並んでいる」とは出せない。一覧に載ることで確かめる

### 2.2 相手の国をもう片方から推し量った動き N件

- 一般名（金融機関・株主・取得先・売り手など）で、相手を**もう片方の国に寄せた**動きの一覧。今は19件
- 1.4 のシリア・米連邦政府は、この一覧を見れば気づけた種類の誤り

## 3. 消えないための決まり

| 危険 | 対策 |
|---|---|
| EA を足す処理が、消した・まとめた EA を毎回よみがえらせる | 決まった番号の主体が1件でもあれば（隠れていても）足さない |
| 取り込みで EA の国が上書きされる | 国を決めた印を付けて足す（今の決まりで上書きされない） |
| 別の端末で先に起動して、同じ EA が2つできる | 番号を決まったものにするので、同期で1つにまとまる |
| 場所の読み方を変えて、国をまたぐ線が国内に化ける | 実装後に本物のデータで全行を比べ、化けたものが0本かを確かめる（試算では0本） |
| 札のデータ | **変えない。** 場所は描くときに毎回決めるので、札には何も書き込まない |
