# kotoba v2.0 仕様書 — 自動関連づけ

## 目的
ノートを保存したとき、既存ノートの中から「似ている」「対立している」「補足している」ものを
Claude API で見つけて自動で紐づける。自分が気づけない言葉同士のつながり（知識の網）を作る。
v1 の手動リンクは残す。

## 前提
- 既存の C:\kotoba\index.html に追加する形で実装（構成・同期の仕組みは変えない）
- Claude API はブラウザから直接呼ぶ。リクエストヘッダに
  `anthropic-dangerous-direct-browser-access: true` が必要
- API キーは設定画面で入力し localStorage に保存（GitHub token と同じ扱い。data.json には含めない。端末ごとに入力）
- モデルは実装時点で使える中でコストと精度のバランスがよいもの（Sonnet 系）を使う。
  モデル名は https://docs.claude.com で最新を確認して決める。設定画面で変更できる入力欄も置く

## データ構造の変更
`links` を文字列配列からオブジェクト配列に変更する。
```json
"links": [
  { "id": "n_20260901_003", "kind": "manual", "createdAt": "..." },
  { "id": "n_20260902_001", "kind": "auto", "relation": "similar",
    "reason": "どちらも外からの評価を受け流す態度を説く", "createdAt": "..." }
]
```
- `kind`: `manual`（手動）または `auto`（自動）
- `relation`: `similar`（似ている）／`opposite`（対立）／`supplement`（補足）。手動リンクは省略可
- `reason`: 自動リンクの根拠を1文（30字程度）
- 既存の文字列だけの links は読み込み時に `{id, kind: "manual"}` に変換する（後方互換）
- リンクは引き続き双方向。片側に追加したら反対側にも同じ内容で追加。`reason` は共通
- ノートに `rejectedLinks: ["id", ...]` を追加。ユーザーが×で外した自動リンクの相手 id を記録し、
  以後の自動関連づけでその相手を再提案しない（手動で結び直すのは可）
- `version` を 2 に上げる。同期のマージ処理は links / rejectedLinks も含めてノート単位で扱う

## 自動関連づけの処理
### 保存時
1. ノートを保存（従来どおり）
2. API キーが設定されていれば、バックグラウンドで Claude API を1回呼ぶ。画面はブロックしない。
   カードや詳細に「関連を探しています…」を小さく出し、結果が来たら差し替える
3. 送る内容：
   - 対象ノートの text / source / myWords / tags
   - 既存ノート全件の圧縮版（id、text 先頭120字、source、myWords 先頭80字、tags）。
     対象自身、既にリンク済みの相手、rejectedLinks の相手は除く
   - 指示：「対象ノートと、同じ考えを別の言い方で述べている（similar）／反対の立場を取っている（opposite）／
     前提や具体例として補い合う（supplement）ノートを最大5件、関連の強い順に選び、JSON のみで返す。
     表面的な単語の一致ではなく、考え方・態度・問いの共通性で判断する。myWords（本人の解釈）を重視する。
     該当がなければ空配列」
   - 返答形式：`[{"id": "...", "relation": "similar", "reason": "..."}]`。JSON 以外を返さないよう指示し、
     ``` フェンスが付いていたら除去してパースする
4. 返ってきた id のうち存在するものだけを `kind: "auto"` で双方向に追加し、保存・同期する
5. 失敗（キー未設定、ネットワーク、パース失敗）は静かに無視し、設定画面の「最終エラー」に記録する
6. 編集で text / myWords が変わったときも同じ処理を走らせる（既存の auto リンクは残す）

### 一括関連づけ（設定画面のボタン）
- 「全ノートを一括で関連づけ」ボタン。押すと確認（概算コストと件数を表示）→ 実行
- 全ノートを createdAt 順に1件ずつ、保存時と同じ処理で回す。進捗を「12 / 87」で表示、途中で停止できる
- 途中で止めても、済んだ分は保存されている。再開時は「まだ一括処理していないノート」から続ける
  （ノートに `autoLinkedAt` を記録し、それを基準にする）
- 1件ごとに同期はせず、10件ごと＋最後にまとめて同期する
- 呼び出し間隔は 500ms 程度空ける。429 が返ったら待って1回だけ再試行

### ノート数が多い場合
- 既存ノートの圧縮版が 400 件を超える場合は、まず tags の重なりと簡易な文字一致で候補を 400 件に絞ってから送る。
  この閾値は設定画面で変更できる

## 画面の変更
### ホーム
- ランダム1枚の下に「つながり」欄を置き、関連ノート（手動・自動とも）を最大5件表示。
  各行に text の冒頭＋出典、右に関係ラベル（似ている／対立／補足、手動は「手動」）。タップで詳細へ
- 関連が0件なら欄ごと非表示

### 詳細
- 関連ノート一覧の各行に、関係ラベルと、自動の場合は `reason` を小さく1行表示
- 自動リンクの行には「自動」の印と × ボタン。×で外すと双方向で削除し、rejectedLinks に相手 id を記録
- 手動リンクの × は従来どおり（rejectedLinks には入れない）
- 「関連を探し直す」ボタン。このノートだけ自動関連づけを再実行

### 追加／編集
- 関連ノート欄はそのまま（手動リンク用）。説明文を
  「保存すると自動で関連ノートを探します。自分で結びたいものはここで追加」に変更

### 設定
- Claude API キー入力（text、autocomplete="off"）、モデル名入力（初期値はデフォルトモデル）
- 「全ノートを一括で関連づけ」ボタンと進捗表示
- 自動関連づけの ON/OFF スイッチ（OFF なら保存時に呼ばない）
- 統計：自動リンク数、手動リンク数、API 呼び出し回数（累計、端末ごと）、最終エラー

## 関係ラベルの表示色
- 似ている：アクセント色（既存のセージグリーン）
- 対立：控えめな赤系
- 補足：控えめな青系
- 手動：グレー

## v2.0 に含めないもの
- ノートとの対話（v2.1）
- 一括入力、網の可視化、X 投稿
