# kotoba v2.1 仕様書 — 相談画面・一覧の整理・修正

既存の index.html（v2.0）に追加する。同期・自動関連づけの仕組みは変えない。

## 1. 相談画面（ノートとの対話）

### 目的
自分の状態や考えていることを投げると、自分が集めた言葉と自分の一言の中から、
今の状態に近いものを探して返す。AI の一般論ではなく、過去の自分が用意した言葉が返ってくる場所。

### 画面
- ホームの下部ボタンを「一覧」「相談」「設定」の3つにする
- 相談画面：上に入力欄（複数行）と「聞く」ボタン。下に返答が積まれていく（同じ画面内で続けて聞ける）
- 返答は次の形で表示する
  1. 選ばれたノートのカード（2〜3枚）。text、source、myWords、関係の一言（「なぜ今のあなたに近いか」30字程度）。
     カードをタップすると詳細へ
  2. 最後に、選んだノート同士のつながりや、それらを踏まえた短い一言（3行以内）。
     一般的な助言や励ましは書かない。ノートの言葉に戻す役割だけ
- 該当するノートがない場合は「まだ、これに応える言葉はノートにありません」と返し、
  「この気持ちをノートに書く」ボタンで追加画面（出典＝自分、言葉欄に入力内容を転記）へ行けるようにする
- 会話は保存しない。画面を離れたら消える。localStorage にも data.json にも残さない
- 入力中と返答待ちは「言葉を探しています…」を表示

### API 呼び出し
- 送るもの：ユーザーの入力＋全ノートの圧縮版（id、text、source、myWords、tags。v2.0 と同じ圧縮ルール、400件超は同じ絞り込み）
- 指示の要点：
  - 「以下はこの人が本や名言集から集めた言葉と、本人の解釈である。入力された状態に対して、
    最も応える言葉を最大3件選び、それぞれになぜ近いかを30字程度で書く。
    最後に、選んだ言葉同士の関係やそこから見える一つの見方を3行以内で書く。
    一般論、慰め、アドバイス、ノートにない引用は書かない。本人の解釈（myWords）を重視する。
    該当がなければ空にする」
  - 返答形式は JSON のみ：`{"picks":[{"id":"...","why":"..."}],"closing":"..."}`
- 直近2往復（入力と picks の id）を次の呼び出しに含め、続けて聞いたときに文脈がつながるようにする
  （画面内でのみ保持）
- 自動関連づけと同じ API キー・モデルを使う

## 2. 一覧の整理

- 上部に表示切替：「すべて」「出典別」「タグ別」
  - 出典別：出典ごとの見出し＋件数、折りたたみ可。折りたたみ状態は localStorage に保持
  - タグ別：タグごとの見出し＋件数。複数タグのノートは各タグの下に重複して出てよい
  - 見出しの並びは件数の多い順
- 並び替え（「すべて」表示時）：「新しい順」「つながりが多い順」
- 絞り込みに「関連なし」（links が0件のノートだけ）を追加。既存のタグ絞り込み・検索と併用可
- 各行の右端に関連数を小さく表示（例：⇄ 4）。0 は表示しない
- 検索・絞り込み・表示切替の状態は画面を離れても保持し、戻ったときに同じ状態で開く

## 3. 修正

- 自動関連づけの JSON パース失敗対策
  - max_tokens を十分大きく取る（1024 以上）
  - reason に引用符や改行が入っても壊れないよう、モデルへの指示で「reason に引用符・改行を使わない」を明記
  - パースに失敗したら、`[` から最後の完全な `}` までを切り出して再パースを試みる。それでも失敗なら1回だけ再呼び出し
  - 失敗が記録されたノートは autoLinkedAt を付けず、一括処理の対象に残す
- 設定画面の「最終エラー」の隣に「エラーが出たノート」の件数と、そのノートへのリンクを表示

## 含めないもの
- 一括入力、網の可視化、X 投稿、会話の保存
