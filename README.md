# 一万日（kotoba） — 保守メモ

このファイルは、作った本人（と、手伝う人）が **あとから自分で直す・戻す** ためのメモです。前半は「困ったときにどうするか」、後半は「中身がどうなっているか」。急いでいるときは **第1章と第2章だけ** 読めば足ります。

- アプリの URL: https://yutatasaki.github.io/kotoba/
- アプリ本体: このリポジトリ（`yutaTasaki/kotoba`）の `index.html` 1 ファイル。`git push` すると 1 分ほどで反映される。
- データ（自分の言葉・記録など）: 別の非公開リポジトリ `yutaTasaki/kotoba-data` と `yutaTasaki/walk10000-data` に JSON で置く。**アプリを消してもデータはここに残る。**
- 端末（iPhone・PC のブラウザ）にも同じデータのコピーがあり（IndexedDB という保存領域）、起動時と操作のたびにリポジトリと同期する。

用語:
- **リポジトリ**: GitHub 上のフォルダのようなもの。履歴（いつ何を変えたか）が全部残る。
- **PAT（トークン）**: GitHub がアプリに読み書きを許可するための長い文字列。設定画面に入れる。有効期限がある。
- **同期**: 端末のデータとリポジトリのデータを突き合わせて、新しい方に揃えること。
- **IndexedDB**: ブラウザの中の保存領域。iPhone の「Web サイトデータ」を消すと消える（リポジトリから戻る）。

## 1. 困ったときの対処（症状から引く）

## 2. 戻し方（手順を省略せずに）

### 2.1 トークン（PAT）を作り直す

1. PC で GitHub にログイン → 右上のアイコン → **Settings** → 左の一番下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. Token name は何でもよい（例 `kotoba`）。Expiration は最長（1 年）にする。
3. **Repository access** → **Only select repositories** → `kotoba-data` と `walk10000-data` の 2 つを選ぶ。
4. **Permissions** → **Repository permissions** → **Contents** を **Read and write** にする。他は触らない。
5. **Generate token** → 表示された `github_pat_…` をコピー（この画面を閉じると二度と見られない）。
6. アプリの設定 → 1. 同期 → 入力欄に貼って **保存** → 「今すぐ同期」。同期バーが「同期済み」になれば完了。
7. iPhone と PC の両方で 6 を行う（トークンは端末ごとに入れる）。

### 2.2 まずバックアップ（何かを戻す前に必ず）

PC で（Git が入っていれば）:
```
git clone https://github.com/yutaTasaki/kotoba-data.git   backup-kotoba-data-YYYYMMDD
git clone https://github.com/yutaTasaki/walk10000-data.git backup-walk10000-data-YYYYMMDD
```
Git が無ければ、ブラウザで GitHub の各リポジトリを開き **Code（緑のボタン）→ Download ZIP**。
加えてアプリの設定 → 5. データ →「言葉のデータをエクスポート」で、端末上のデータも 1 部保存しておく。

### 2.3 ある日の状態にデータを戻す（リポジトリの履歴から）

リポジトリには変更のたびの履歴が残っている。例えば「昨日の朝の状態の `data.json`」に戻すには:
```
cd backup-kotoba-data-YYYYMMDD
git log --oneline -- data.json            # 履歴一覧。左の 7 文字が「コミット」
git show <コミット>:data.json > data.json  # その時点の内容を取り出す
git add data.json
git commit -m "restore data.json"
git push
```
年ファイル・月ファイルも同じ（`notes/2026.json`, `journal/2026-09.json` など。ファイル名を変えるだけ）。
Git を使わない場合: GitHub でファイルを開く → **History** → 戻したい日時を選ぶ → 右上の **…** → **View file** → 内容をコピーして、現在のファイルを **Edit** で貼り替えて **Commit changes**。

そのあと、アプリ側:
- 端末はまだ新しい内容を持っているので、そのまま同期すると「端末の方が新しい」項目は端末が勝つ。
- 完全に戻したいときは、**端末側を空にしてから**起動する（iPhone: 設定 → Safari → 詳細 → Web サイトデータ → yutatasaki.github.io を削除。PC Chrome: アドレスバー左の鍵アイコン → サイトの設定 → データを削除）。空の端末はリポジトリの内容をそのまま取り込む。
- トークンと API キーも消えるので、2.1 の 6 と設定の API キーを入れ直す。

### 2.4 保存方式を戻す（月ファイルをやめる）

「言葉」と「記録」は、それぞれ **旧方式（data.json に全部入り）** と **新方式（月ごとのファイル）** を設定画面のボタンで行き来できる。どちらも片道切符ではない。

- 設定 → 1. 同期 →「**言葉を data.json 方式に戻す**」: 全月のファイルを読み込み、`data.json` に書き戻す。月ファイルは残るが使われない。
- 設定 → 1. 同期 →「**記録を data.json 方式に戻す**」: 全月のファイルを読み込み、`data.json` に書き戻す。
- 逆（新方式へ）は同じ場所の「…方式に移行」。移行は最後に `data.json` を書き換えるので、途中で失敗しても旧方式のまま使える。
- 実行前に 2.2 のバックアップ。実行中は画面を閉じない。1 台で実行すれば、もう 1 台は次の同期で自動的に同じ方式に切り替わる。

### 2.5 アプリ（index.html）を前のバージョンに戻す

```
cd kotoba                      # このリポジトリ
git log --oneline              # 履歴。左の 7 文字がコミット
git checkout <コミット> -- index.html
git commit -m "revert index.html"
git push
```
1 分ほどで反映。主な節目（新しい順）:

| コミット | 内容 |
|---|---|
| `a77c11e` | v7.4 言葉を月ファイルに（年ファイルから自動切替）、言葉タブ 200 枚ずつ表示 |
| `e447aa2` | v7.3 タブバーが浮く不具合の修正（ページ固定 + `#shell` スクロール） |
| `521a963` | v7.2 言葉の年ファイル、引くの★、30 秒タイムアウト |
| `7bff371` | v7.1 読書メモ |
| `17f53d6` | v7.0 種類（名言/本/自分）、候補の言葉の選び方 |
| `1773083` | v6.0 IndexedDB 保存、記録の月ファイル |
| `bd77edb` | v6 の直前（localStorage 保存、data.json 全部入り） |

この表は保存方式が変わった節目だけ。そのあとの変更（v8〜v20 の瞑想・撮る・世界など）は `git log --oneline` で見る。いまの版は 設定 → 世界 の一番下に出る。

**注意**: 言葉が月ファイル方式のまま v7.4 より前へ（`e447aa2` 以前は年ファイル、`521a963` より前は data.json しか読めない）、記録が月ファイル方式のまま `1773083` より前へ戻すと、そのアプリはファイルを読めず言葉・記録が見えなくなる。**先に 2.4 で旧方式に戻してから**アプリを戻すこと。

### 2.6 端末のデータを消して入れ直す

iPhone: 設定 → Safari → 詳細 → Web サイトデータ → yutatasaki.github.io を削除 → アプリを開く → トークンと API キーを入れる → 同期で全部戻る。
（「端末が空でリポジトリにデータがある」ときは、端末の空データで上書きしないよう、取り込みだけ行う。）

## 3. 中身の説明

### 3.1 データがどこに、どんな形であるか

| データ | 端末（IndexedDB `kotoba` / store `kv`） | リポジトリ | 備考 |
|---|---|---|---|
| 言葉（ノート） | `notes:YYYY-MM`（作成月ごと。全月を端末に持つ）、未同期の月 `notesDirty`、最後に見た索引 `notesStamps` | `kotoba-data` の `notes/YYYY-MM.json` と `notes/index.json` | 月ファイル方式のとき。旧方式では `data.json` の `notes`。v7.2〜7.3 の年ファイル `notes/YYYY.json` は v7.4 で自動的に月ファイルへ移され、残骸として残る |
| ゴミ箱・下書き・API使用量・方式フラグ | `data`（予備 `dataBackup`） | `kotoba-data` の `data.json` | |
| 記録（朝・相談・引く・問い） | `journal:YYYY-MM`（月ごと）、索引 `journalIndex`、未同期の月 `journalDirty` | `kotoba-data` の `journal/YYYY-MM.json` と `journal/index.json` | 月ファイル方式のとき。旧方式では `data.json` の `journal` |
| 筋トレ | `training` | `kotoba-data` の `training.json` | |
| 瞑想 | `meditation:YYYY`（年ごと。全年を端末に持つ）、未同期の年 `meditationDirty`、最後に見た索引 `meditationStamps` | `kotoba-data` の `meditation/YYYY.json` と `meditation/index.json` | v8.0。最初から年ファイル |
| 世界（出来事） | `world:YYYY-MM`（eventDate の月ごと。**全月は持たない**）、索引 `worldIndex`、未同期の月 `worldDirty`、最後に見た索引 `worldStamps` | `kotoba-data` の `world/YYYY-MM.json` と `world/index.json` | v10。端末に読むのは「今月・先月」＋「索引が未読ありと言う月」。地図と国の網を開いたときは直近90日（最大6か月）を読む |
| 世界（概念・用語・地層・アクター・問い・ソース） | `worldConcepts` / `worldTerms` / `worldStrata` / `worldActors` / `worldAsks` / `worldSources`（どれも全件） | `kotoba-data` の `world/concepts.json`・`world/terms.json`・`world/strata.json`・`world/actors.json`・`world/asks.json`・`world/sources.json` | 署名が変わったときだけ書く。用語（v10.5）は概念と**別ファイル**（混ぜると概念一覧が固有名詞で埋まる）。地層（v11）は閉じた一覧（既定16件＋内訳4件）で、生成には作らせない。アクター（v12）は種21件を撒いた開いたリスト |
| 世界の数字（v20.6） | `worldFigures`（「world:」で始めないので、世界のデータを捨てても残る） | `kotoba-data` の `world/figures/YYYY-MM.json` と `world/figures/index.json` | 米財務省の API の数字（入出金・口座残高・政府債務）を日ごとに貯める。項目名を1か所にまとめて詰めた形で約44KB/月。確認先の URL は種類ごとに1つ持つ |
| 散歩 | `walk`（予備 `walkBackup`） | `walk10000-data` の `data.json` | walk10000 と同じ形 |
| 設定（トークン・APIキー・モデル名・各種フラグ） | localStorage `kotoba_*` | 置かない | 端末ごと |

世界のデータを捨てる操作（設定 → 世界）は、捨てる前に全部を `world/_backup_YYYYMMDD.json` に書き出す。世界の端末ごとの控え：`kotoba_worldRates`（ドル換算に使ったレート）、`kotoba_worldPullPending`（コピーしたプロンプトに入れた必ず見るもの・決算の書類。取り込めたら消える）。

IndexedDB が使えない環境では同じキーが localStorage（`kotoba_kv_` 接頭辞）に入る。v6 より前の localStorage のコピー（`kotoba_data` など）は初回起動で取り込んだあと残してある（旧バージョンへ戻すときの保険。設定の「古い保存形式のコピーを消す」で消せる）。

**data.json**
```
{ version: 2, updatedAt,
  notes: [...]（旧方式のみ）, deletedIds: [{id, deletedAt}]（旧方式のみ）, trash: [ノート + deletedAt],
  journal: [...]（旧方式のみ）, deletedJournalIds: []（旧方式のみ）,
  drafts: [], deletedDraftIds: [], dismissedDuplicatePairs: [],
  usage: { 端末id: { label, months: { 'YYYY-MM': { 機能: {calls, input, output, cacheWrite, cacheRead} } } } },
  journalMode: 'legacy'|'monthly', journalModeAt, notesMode: 'legacy'|'monthly'（'yearly' は v7.2 の名残。起動時に 'monthly' へ自動変換）, notesModeAt }
```

**ノート 1 枚**
```
{ id: 'n_YYYYMMDD_連番', text, source, myWords, tags: [], kind: 'quote'|'book'|'self', book?: {title, author},
  keep?: 1（「残したい」の印。普通は項目なし）, lastViewedAt?（一覧の「眠っている順」から詳細を開いた最終日時。眠り順の計算にだけ使う）,
  context?: [{text, at}]（周辺のメモ。AI には渡さない）,

**流れの説明（v9.4）**：撮る前に一度読んで全体の転がり方を頭に入れるための 300〜500 字。プロンプトをコピーしてチャットに貼り、返ってきた文をそのまま欄に貼る（JSON ではないので取り込みボタンは無い）。プロンプトは「カードの事実を繰り返さない・数字や固有名詞を書かない・カードからカードへの動きと落差だけ・喋る言い回しや指示を書かない」で縛ってある。**撮影表示には出さない**（読める文が手元にあると台本になる）。撮影表示を開くと、この文だけが先に全画面で出て、「読んだ」でカードに変わる。同じデッキではその起動中は一度だけ。

**撮影表示（v9.2）**：カンペなので 1 枚 1 行。番号・★（壊すの枠）・`label`・出典の略だけを出す。`breaks` は出さない。タップでその 1 枚だけ詳細が開き（`fact` → `detail` → 出典・種別・信じ度 → 出典を開く）、長押し（0.5 秒）で話し終えた印として薄くなる。`flow`（展開）はカードの中ではなく**カードとカードの間**に細い 1 行で出る（前から次への移り方なので行の間が自然）。`label` が空のカードは `fact` の先頭 15 字を暫定表示し、開くときに未記入の枚数を知らせる。ラベルは生成の JSON に含めさせて取り込み、編集画面で直す（空から 10 枚書くより速い）。編集画面の「ラベルだけ書く」で、番号と色と 1 行入力だけを並べて直せる。

**編集画面の並び（v9.4）**：上から順に埋めれば完成する順。1 問い → 2 仮の答え → 3 タイトル → 4 相談 → 5 カード → 6 答えを壊す → 7 展開 → 8 入り → 9 流れの説明。まだ使えないブロックはボタンを薄くして理由を 1 行だけ出す（`shootGate`。「カードが3枚そろうと使えます。（いま 1枚）」など）。「答えを壊す」の結果の下に仮の答えをもう一度置いてあり、上の欄と同じ内容を書き直せる（両方向に同期）。

**話の型**：入り → 先出し（仮の答え） → 支え → 寄り道 → 壊す → 言葉 → 言い直し の 7 枠で固定。答えを先に言い、支えて、壊して、言い直す形。カードは枠（`slot`）に割り当てられ、撮影表示は作成順ではなく枠の順に出す。枠の定義は `TALK_SLOTS` の配列 1 か所（名前・説明・受け入れる種類・並び）。枠 1・2・7 はカードを持たない。`slot` はカードに保存されるので、既存の番号の意味を変えないこと（追加は末尾）。第1段のデッキ（`slot` なし）は読み込み時に種類ごとの既定（研究・記録 3／わくわく 4／言葉 6）が入る。

カードは材料であって台本ではない。言葉カードはデッキの中の相談（v8.7）と問いの材料から、記録カードはその日の朝の記録から作る。研究・わくわくは、撮る画面のプロンプトをチャットに貼って作るか（v9.0）、手で書く。

**値は札が運んでくる（v15）**：生成は札ごとに `levels`（`{stratumId, value, at}`）を返し、取り込みが地層に足す。当時の13件のうち12件が「値は未記入」で、四半期に一度手で入れる設計が止まっていた——札を取り込むたびに埋まるようにした。縛りは4つ：(1) **出典に数字が書かれているときだけ**（推測・概算は書かせない）、(2) `source`・`url` は**札のものを使う**（生成に書かせると、そこだけ未検証の URL が入る。札の url は取り込み時点で検証済み）、(3) **同じ日付が既にあれば落とす**（履歴なので足すだけ。`via:'card'` のときだけ。手で入れるぶんは打ち間違いを直せないと困るので上書きしてよい）、(4) 一覧に無い `stratumId` は落とす。取り込み結果に「地層の値 N件を入れました／同じ日付で重なった M件は落としました」を出す。札から入った値は `value` が出典の書き方のまま（「1兆2075億ドル」）なので**地層の `unit` を後ろに足さない**（「1兆2075億ドル 億ドル」になる）。
**専用プロンプトで残りを埋める（v16 B）**：札から埋まるのは当時の13件のうちせいぜい5件で、週のニュースに出てこない量（長期金利・人口・実質実効為替レート・エネルギー自給率）は未記入のまま残る。地層の一覧に「現在値を調べる」を置き、全件の `name`・`line`・`unit`・`where`（確認先URL）・**前回の値**を差し込んだプロンプト（`worldProbePromptText`。約3100字）を1本で回す。分野で分けないのは、月1回の作業を3回に割ると回らなくなるため——返答が途中で切れても配列に入っているものだけ入るので、足りなければもう一度回せば済む。**値・基準日・出典URL の3点が揃わなければ返せない形**にしてある：`url` が無い値は落とす（`via:'probe'` の url は生成が新しく書くので未検証。札の url と混ぜないよう via を分けてある）、`at` が無い値も落とす（**札と違い eventDate で代用しない**。基準日の無い残高は意味が違う）、推測・概算は書かせない、一覧に無い id は落とす。前回の値を差し込むのは**桁を1つ間違えた返答をこちらで気づくため**なので、「前回の値をそのまま書き写さない」を規則に入れてある。
取り込み結果は「N件を入れました／落とした内訳／**古いまま残っている地層 N件**」。最後の一行が要で、7件入っても赤が残っていることが同じ場所で分かる。`value` が前回の100倍以上・1/100以下なら**落とさずに警告**を出す（本当に桁が変わることがある。機械は気づかせるだけで、判断は人がする）。`probe` の値は素の数字なので地層の `unit` を後ろに足す（`card` の値だけ足さない）。

このアプリの本当の目的は「すべての物事は人間の思惑で動いている。その思惑はお金の動きや行動に現れる」を見えるようにすること。概念の網は「何の話か」で繋ぐが、見たいのは「**誰が動かしているか**」で繋ぐ軸。用語は「読むための注」、アクターは「動かした主語」——IMF は両方でありうるので、重ねたまま役割で分ける（注は用語側にあり、アクターの詳細はそれを**借りる**。複製しない）。種は21件（「市場参加者」は入れない。市場は思惑を持つ主体ではなく、思惑が現れる場所）。原則は組織を主体にし、個人は組織と立場が違うときだけ `kind:'person'`。
**思惑は必ず捏造される**ので、札ごとの記録は3層（行動／述べた理由／読んだ思惑）に分け、「**述べた理由と同じなら読んだ思惑は空**」を規則にも取り込みにも入れてある（`normalizeWorldActorRec`：`did` が空の主体は落とす＝行動が出典に書かれていない主体をアクターにしない、`read` を正規化して `said` と同じなら空に）。**統計・論文・報告書の公表そのものは行動としない**（公表機関を主語にすると時系列が「内閣府：7月公表→8月公表」で埋まる）。推定は琥珀色（`--guess`）のバッジ＋左の破線で、事実の行と見間違えない形にしてある。空が多いのは正常で、取り込み結果に「推定を書いた札 N件／全 M件」を出す——高すぎたら生成が推定を作りすぎている。
`flow` は**換算しない**（円をドルに直した瞬間に生成が為替レートを選ぶ）。`amount` は出典の文字列が正、`value/unit` は端末で解析するだけ。合計もしない。**残高は `flow` に入れない**——外貨準備や中銀の資産を入れると `from` も `to` も無い「流れ」ができる。器は地層の `levels` のほうにもともとある。
v15 で2つ足した。`span`：その金額が**累計か1回の動きか**（「NATO → ウクライナ 100億ドル」が1回の拠出か2022年以降の累計かで意味がまるで違う。混ぜると一覧で累計だけが大きく見える）。`strata`：**その金が動かした地層**——地層の詳細に「この地層を動かしたお金」が出て、「残高が減った」と「その分どこへ流れたか」が同じ画面に並ぶ。ただし単位が違う（外貨準備はドル、介入は円）ので、並べるだけで引き算はしない。
表示：札の展開の why の直下に「動かした側」（name+did の1行が既定、押すと述べた／推定）。段数を増やさないよう用語と地層を1行にまとめた。出典の立場（v11 C）は、その出典が札のアクターに含まれるときは出さない。アクターの詳細は**時系列**（`eventIds` から月を割り出して必要な月だけ読む）で、`flow` の金額が右端に縦に並ぶ——「7月 介入 5兆円 → 9月 介入 15兆円」がこの層で一番見たい絵。同じ単位だけが並ぶ。
**遡及**：概念のときと逆に作った（主語の軸は履歴が無いと開く意味がない）。取り込み画面の「既存の札に付け直す」でプロンプト（`worldRetroPromptText`。出典を開き直さないぶん縛りが厳しい：did は fact・detail の行動だけ、said は「述べた」と分かる形があるときだけ、read は必ず推定、`levels` は detail に数字が書かれているときだけ）をコピーし、返った JSON を足す。**置き換えない**——主語は `ev.actors` が空の札にだけ、`flow` は無い札に、既にある `flow` には空いている `span`・`strata` だけ。v15 で対象を「端末にある札（新しい順に最大40件）」に広げた（地層の値は主語がもう付いている札からも拾えるため）。主語が付いている札にはプロンプト側で「※ 主語は付いています」の印が付き、`actors` は空で返る。

**読む（v20.17。第1段）**：集める（探す・書き写す）と読む（思惑・分かれ目）を別の回に分けた。未読＝**`readAt` が無く `actors` が1つ以上ある札**（`read` が空かどうかでは見ない——述べた理由と同じなら `read` は正直に空になるので、空を未読にすると永久に出続ける）。取り込み画面の「読む」でプロンプト（`worldReadPromptText`。新しい出来事を探させず、出典も開けない前提。同じ主体には違う読みを書く／said と did のずれ（`zure`）／損を承知の犠牲を書く／すでに答えが出ている分かれ目は立てない）をコピーし、返った JSON を `worldImportReadJson` で足す。**足すだけ**——空いている `read`・`zure`・`fork`・`reason` だけを埋め、既にある値は上書きしない。`said` のなぞりは入れない。`confidence` は**下げるときだけ**通し（`confidenceWhy` 必須）、**上げる値は捨てる**（出典を開いていない側が確かさを上げる根拠がないため）。読んだ札には `readAt` を押す（材料が足りず空振りした札にも押す）。朝の1行は8枚（`WORLD_READ_NUDGE`）以上溜まってから出る。20枚のプロンプトは実測9,634字。

**第2段（v20.18）**：朝のプロンプトから `read`・`fork`・`reason` を外した（`confidence`・`premise`・`concepts`・`did`・`said` は朝に残す）。プロンプトから消すだけでなく、朝の取り込みの入口でも落とす（`worldStripMorningRead` が `read` をキーごと捨て、`fork`・`reason` は `normalizeWorldEvent` に渡さない）。朝のプロンプトは実測16,310字。すでに入っている浅い読みは、**印の無い `read` ＝ 朝が書いたもの**として見分ける（読む回が書いた読みにだけ `readBy:'yomu'` を刻むので、移行処理が要らない）。読む枠20枚は未読を優先し、余った枠だけ `worldRereadCards()`（`readAt` があり `rereadAt` が無く、印の無い読みを持つ札）で埋める。書き直しは `rewrite: true` を明示したときだけ通り、**元の文は `readWas` に必ず残す**。一度当てた札には `rereadAt` を刻む。札を開いたとき `read` が空の主体には「まだ読んでいません」と「いま読む ▸」を出し、空欄が放置に見えないようにした。

**ソース（`world/sources.json`）**: `{ version:1, updatedAt, sources: [{id, name, url, field:'finance'|'geo'|'both', role:'primary'|'analysis', stance（v11: この発信者が欲しいもの）, note（プロンプトの「取るもの」）, cadence:''|'day'|'week'|'dekad'|'month'|'quarter'（v19.4。周期があるものが「必ず見るもの」）, cadenceSetAt, updatedAt}] }`
`role` の `primary`（中銀・政府・国際機関・統計）は出来事・日付・数字の出所。`analysis`（シンクタンク）は why を書くための補助で、**それだけを根拠に出来事を立てさせない**。プロンプトでは2つの一覧を分けて差し込み、使い分けを明記してある。一度も保存されていないときだけ初期リスト22件が入る。

**差分だけを見ない仕掛け（v11）**：出来事は「変化したもの」しか映さないので、動かないもの・溜まるものが見えなくなる。**地層**を少しだけ持ち、(1) 出来事の行には `short` のタグを1つ（行は増やさない）、(2) 今日の3件の上と朝の畳んだ行の下に**日替わりで巡回する1行**を出す（`WORLD_STRATUM_ON_COLLAPSED` で朝の分は消せる）。巡回にしてあるのは、変わらないものを毎日同じ形で見せると2週間で見えなくなるため——「今日はどれか」という小さな差を残す。値には「前回更新から N 日」を必ず出す（古いまま放置されているのが見えないと数字が嘘になる）。**「古い」の日数は地層ごと（v16 B）**：長期金利は日次、外貨準備は月次、SIPRI の軍事費と国連の人口は年次。一律90日にすると軍事費が1年中赤くなり、**赤が情報でなくなる**。`cadence` を1件ずつ手で振り、`month` 45日／`quarter` 120日／`year` 400日で判定する（`worldStratumStale`）。値が無いものは常に古い。地層の一覧の見出しに「古い N件 / 全件数」を出すので、**押す前に押す必要があるかが分かる**。
**発信者の立場**：ソースの `stance`（この発信者が欲しいもの）。出来事の url のドメインから引いて「詳しく」に出す。コピーは**「反対の見方は」にだけ**渡す（反論は前提を突くので効く。他に渡すとノイズ）。
**非表示（v11）**：出来事・概念・用語に `hidden`。本文は残る。出来事は読み出し口を `worldLiveEvents()` に一本化してある——生の `worldEvents` を使ってよいのは**保存・重複判定・マージ**の3か所だけ。重複判定が非表示のものを見ないと、消した札が次の取り込みで戻ってきて非表示の意味が消える。
**用語が沈む（v11。v19.5 で用語の一覧を画面から外し、v20.9 で沈める処理も外した）**：`lastUsedAt` が90日より古い用語は一覧の下段に畳まれ、生成の既知一覧からも外れる。**`seenAt` は使わない**——注を開くのは「その語を知らなかったとき」なので、`seenAt` で沈めると IMF のように身についた語から先に沈む（意図と逆）。
**つながり（v11.5）**：生成の `related` は**構造的に育たない**——`makeIfMissing=false` で既に存在する概念しかリンクせず、プロンプトも「既知の一覧から」と縛っているので、1回目は既知が空でリンク0、2回目の概念どうしは絶対に繋がらない。バグではなく仕様の帰結。そこで**同じ札に一緒に出た概念どうしを自動で繋ぐ**（共起）。「なぜ繋がっているか」が「同じ札に出たから」という検証可能な理由になる。
`concept.related`（id の配列）は `concept.links = [{id, by:'cooc'|'model', count, eventIds, at}]` に置き換わる（古いデータは読み込み時に `by:'model'` として読み替わる。消えない）。`count` は**共起の回数だけ**を数え、`by` は作られたときの出所で後から変えない（`by:'model'` で `count>0` のリンク＝「生成が指定し、実際に同じ札にも出た」）。歯止めは4つ：回数を数える／`WORLD_COOC_MIN` は**表示にだけ**効かせる（`count` は常に数えるので上げ下げに数え直しが要らない）／手で外せて `rejected` に入り二度と繋がない／**1つの札で繋ぐ概念は `WORLD_COOC_MAX_PER_EVENT` 件まで**（`ev.concepts` は8件あるので、上限が無いと1札から36本出る）。
設定の**「概念のつながりを作り直す」**は全月を読み直し、`by:'cooc'` だけを捨てて数え直す（`by:'model'` と `rejected` は残る）。**冪等**で、何度押しても同じ本数になる。同時に `concept.eventIds` も数え直す——リンクが育たないのと同じ理由で**再会の回数も過少**になっているため（`ev.concepts` も `makeIfMissing=false` なので、まだ存在しない概念の名前は取り込み時に捨てられる）。`eventIds` は**減らさない**（読めなかった月の分を消さないため）。

**concepts の指示（v11.6）**：段階2.5 を実機で回したら15件から共起が1本しかできなかった。網の作りではなく、`concepts` の指示が空欄同然で、生成が「その札に出てくる語」（`石油在庫`・`設備投資`——札限りで二度と出ない語）を並べていた。**2〜4個・premise を含む・末尾の既知一覧から必ず探す・札限りの語を禁じる**に変え、既知一覧の見出しを「concepts はここから探す」にした（「説明しなくてよい」だけだと避けるもののリストになる）。`related` は落とした（同じ質問を違う縛りで2回聞くことになる。取り込みは今でも読む）。まだ存在しない概念名は今も捨てる（概念が生まれる場所は premise だけ）が、**何件捨てたかを取り込み結果に出す**。

**問いモード（v14）**：主体そのものは固定でないが、**入口が固定**だった——「ニュースが先、主体は後」で、札を読んで初めて主体が見える。逆向きの入口を足した：**知りたいことを打つ → プロンプトをコピー → チャット → JSON を貼り戻す**（API は使わない）。返るのは 見立て（view）／分かれ目（fork）／**その問いを動かしている主体と、その望み**／一次ソースの出典が付く行動／既にある札の id。
**主体は二層**。札の主語（`ev.actors`）は「出典に行動が書かれた主体」に厳しく縛ってあるので広げられない。問いの主体は `runs[].actors` の中に持ち、既存の主体に当たれば `actorId` を持って盤面・時系列と繋がり、当たらなければ名前だけ（投機筋・輸出企業・年金基金）。**昇格の条件は1つだけ——その行動が札になったとき**。だから「投機筋」は盤面を汚さない。
**捏造対策**：問いは「答えを出せ」と迫るので、札の取り込みより捏造しやすい。プロンプトに「**材料が一次ソースに無ければ無いと書く／主体を無理に挙げない／行動は出典が付くものだけ／思惑はすべて推定**」を明記。`want` は放っておくと「経済の安定を望む」のような一般論になるので、**他の主体と食い違う点が分かるように書く**を規則にした（思惑が見えるとは、誰と誰の望みがぶつかっているかが見えること）。`want` 必須・`fear`/`bound` 任意（3つ書かせると必ず3つ埋めて薄くなる）。表示は望みのブロックごと琥珀の縦線で囲う（1行ずつバッジを付けると琥珀だらけになる）。
**同じ問いは `runs[]` に積む**（別レコードにすると「同じ問い×違う時期」が並ばない）。1日1 run で、同じ日に貼り直すと上書き（同期のマージも `at` で束ねるため）。同じ問いかどうかは**本人にしか分からない**ので、投げるとき近い問い（バイグラム 0.60）を出して人に選ばせる。
**プロンプトに差し込む札**は、既知の語（概念・用語・アクターの名前と別名）を辞書代わりに使って絞り、新しい順に20件まで。日本語の分かち書きを持っていないので、問いの文をそのまま部分一致にかけても当たらない。0件なら絞り込みの語を1つ入れてもらう。長さは約 3.8KB〜（札が100件に育っても20件で切るのでこのまま。通常の生成プロンプト（最大で約22,000字。注意の線は `WORLD_PROMPT_WARN_LEN` の 23,000字）の数分の1）。
**問いの画面には行動（札）を出さない**（`runs[].added` から「出来事タブで見る」で辿る）。過去の問いもこの画面の中だけ——既定に出すと「問いの在庫」ができる。札には `viaAsk` が付き、どの問いが掘り当てたかが引ける。

**まとめて貼る（v17.1）**：ソースの `stance` は22件とも空、地層の `where.url` は当時13件中7件が「数字の載っていないページ」（CSV・PDF・JS描画・DB形式）を指していた。**手で22回・13回入力するのは現実的でない**ので放置されていた。設定 → 世界 に貼り付け欄を1つ置き、「コピー → 貼る → 取り込む」の形で一度に入れる。
**行き先は先頭の列で決まる**（`worldApplyBulk`）——地層の id は `st_` で始まる閉じたリストなので、ソース名と衝突しない。ソースは `名前［タブかコロン］立場`（立場の文中のコロンでは割らない。最初のコロンだけ）、地層は3列（id・確認先名・URL）か5列（id・名前・説明・確認先名・URL）。5列があるのは、**単一の公表値が存在しない量を id はそのままに別の量へ置き換える**ため（世界貿易/GDP → 世界の商品貿易量）。
ソースは `aka` を持たないので、当たらなければ**アクター・用語の別名を通して寄せる**（MOF → 財務省）。`stance` は**空欄だけ埋める**が既定でチェックで上書き、地層の確認先は差し替えが目的なので常に上書き。**新しいソースも地層も作らない**。当たらなかった行は件数と名前を出し、**その行だけ欄に残す**ので直して貼り直せる。`st_` で始まるのに一覧に無い行は「新しいソース」ではなく「一覧に無い地層の id」として報告する（打ち間違いをソースの話として説明しない）。
概念・用語・アクターの注は**入れていない**——同じ名前が複数のストアにあるとき、黙って違うものに入るため。行き先を足すなら分類の分岐に1行足すだけで済む形にしてある。

**予測と答え合わせ（v17 C）**：生成は分かれ目（fork）だけを書き、押すのは自分だった。予測タブは空のままで、判定する経路がどこにも無かった。生成にも `lean`（up/down/flat）と `because`（60字・推定）を書かせ、期限が来たら**一次ソースで答え合わせ**する。副産物として「**AI の予測は当たるのか**」が測れる——同じ分かれ目・同じ期限に両方が答えるので、`worldJudgeStats` の2つの的中率だけが比較可能な数字になる。
**判定は「どちらが当たったか」ではなく「何が起きたか」を聞く**（`worldJudgePromptText`）。返させるのは `{eventId, outcome, evidence, url}` だけで、**当たり外れは端末が引き算する**（`leanResult = lean === outcome`、`result = pick === outcome`）。理由は3つ：生成に採点させると採点が甘くなる方向に力がかかる、pick と lean をプロンプトから外せるので忖度の余地が消える、両方の的中率が同じ `outcome` から機械的に出る。プロンプトには「前に誰が何を予測したかは書いていない。予測に合わせて事実を選ばない」と明記してある——**載せていない事実を明示する**ことで、生成が推測で埋めるのを防ぐ。
`type` が level と event で up の意味が違うので、**「up とは何か」を端末で文言に展開してから渡す**（`worldOutcomeWords`）。ここは実物を出して見つけた穴で、3択のボタン文言をそのまま借りると「1億バレルを割るか → up とは：上」になり、何を聞かれているのか伝わらない。同じ理由で答え合わせの画面も `WORLD_OUTCOME_LABEL`／`WORLD_SIDE_LABEL`（届いた／起きなかった）を使う。
**url が無い・`evidence` が空・`outcome` が unknown はすべて保留**（判定を捏造させない）。保留は `nextCheck = 14日後` で戻り、**2回で打ち切る**——永久に戻り続けると答え合わせが詰まるし、2回調べて決着しない分かれ目は fork の書き方が悪かったという情報になる。
入口で絞るのが要で、**`WORLD_FORK_PER_BATCH = 3`**。実データで fork は約半分の札に付き、毎日7件取り込むと90日後に300件が待つ（答え合わせは12件/回）。プロンプトに書いたうえで**取り込みでも切る**（`order` の若い3件だけ fork を残す）。`worldPredictionWritten` は `Mine`／`Lean`／`Any` の3つに割った。**due 索引は `result` ではなく `judgedAt` で外す**——pick を押していない札は判定しても `result` が空のままなので、`result` で見ていると永久に索引に残る。期限は90日固定で、`writtenDate` は札の `eventDate`（自分があとで押しても期限が動かないので、生成と同じ期限で比べられる）。
札の中では**見立て（方向）は出し、`because` は自分が押すまで畳む**——理由を先に読むと自分の考えではなく理由の追認になり、方向まで隠すと「AI はこう思っている」が予測タブでしか見られなくなる。`WORLD_LEAN_HIDDEN`（既定 false）で方向ごと隠せる。

**お金の流れ（v15）**：「人の意思→行動→お金」なので、お金の動きから逆算できる。ただし逆算できる相手は**公的主体に限られる**（中銀の資産・政府の予算・国際機関の融資は追えるが、誰がいつ何を売買したか・非公開の政治資金は追えない）。一覧の見出しに常時「追えるのは公のお金だけ ▸」を置き、押すと 追える／部分的／ほぼ追えない の3行が開く——**追えないものを追えるように見せない**ための唯一の防具。
v18 A-2 でタブを無くし、いまは既定の画面の「お金の一覧」と、探すの型「お金」から開く。**通貨ごとに区切り**（換算しないので足せない）、`from → to` の組でまとめ、**2回以上ある組を上に出す**——繰り返しがゲートの代わりで、同じ相手に何度も出している金が自然に目立つ。**合計は出さない**（「財務省 合計20兆円」を出した瞬間に、性質の違う金を足した数字が独り歩きする）。
`worldParseAmount` は v15 で**複合の書き方**（「15兆3993億円」）を読むようにした。実データでは普通に来る形で、ここで読めないと同じ通貨の同じ組が「円」と「単位が読めないもの」に二手に分かれ、2回以上の仕掛けが働かない。桁を読み違えるくらいなら読めないことにする（`value` は並べ替えにしか使わない）。

**日付と問いの見え方（v14.1）**：一覧の日付は当年なら M/D、それ以外は YYYY.M/D（去年の札が今年に混ざって見えていた）。`worldShortDate` 1か所を通るので、出来事・盤面・時系列・問い・つながる札のすべてに効く。盤面の「知りたいことから引く」の下に**最近の問いを2件**（`WORLD_BOARD_ASKS`）出す——問いは在庫ではなく自分が立てた立場なので、問いの画面の中だけに置くと戻ったとき消えたように見える。押すとその問いを開いた状態で問いの画面へ。

**主体の盤面（v13）**：世界タブの**既定を入れ替えた**。（当時はタブが [主体][出来事][概念][予測] の4つで、既定を「主体」にした。v18 A-2 でタブは無くなり、既定の画面1枚になった。）この機能は「情報を集める」から作り始めて「思惑を見る」を後付けしたので、土台が札の一覧のままだった。最初に見るべきは「今日どんな出来事があったか」ではなく「**いま誰が何を動かそうとしているか**」。
盤面は1行 = 名前／直近の行動（did）／最終日／回数／印。**期間で切らない**——「静かになったこと自体が情報」で、あれだけ介入していた主体が2か月動いていない、が消えるのは危ない。最終行動の新しい順に並べ、古い主体は自然に下がる。**金額は出さない**（出すと金を動かさない主体が沈む。金額が縦に並ぶ絵はアクター詳細の時系列にある）。行動が1件も無い主体は出さない。既定5件、「もっと見る」で20件まで。
右端の印がこの画面の核心：`述`＝述べた理由がある／`推`＝推定がある／**`・推`＝述べた理由が1件も無く推定だけ**。3つ目が一番重要（何も言わずに動いている主体）なので、琥珀色に加えて**中黒で位置もずらす**——色だけだと「述推」と並んだとき走査で拾えない。
**回数と最終日は id から出す**ので、月ファイルを読み込んでいなくても正確（id の日付部分が eventDate）。読み込み済みの月については実物で判定して非表示・削除された札を除く。行動の文と述べた／推定は読んだ月からしか取れないので、裏で月を読んで埋まったら描き直す。
アクター詳細からの「戻る」は**来た場所へ返す**（`worldState.entryFrom`）。盤面から入ったのに一覧に落ちる、を防ぐ。

**つながりを勝手に見せる（v11.7）**：共起も再会も裏で動いていたが、見る方法が「概念タブ→概念→つながる概念」しかなく、探しに行かないと見えなかった。3つ足した。(1) **取り込みの最後に自動で数え直す**——端末にある札を全部 `worldScanEventLinks()` に通す（足すだけ・冪等）。この回で生まれた概念が前の札の `concepts` に名前だけ出ていて捨てられていた分を、ここで拾う。端末に無い月は対象外で、それが設定の「作り直す」の残った役目（降格）。(2) **取り込み結果に「過去の札と N本つながりました」と「入れた札を見る」**——出来事タブがその回の札＋つながった相手の札だけの一覧になる（「全部を見る」で戻る）。(3) **展開に「つながる札」**——同じ概念に触れている端末上の他の札を、新しい順に `WORLD_LINKED_MAX`（3）件、**どの概念で繋がっているか**を添えて出す。押すとその札が開く。概念どうしではなく札どうし（読んでいるのは札なので、隣に出るのも札）。**繋がっていない札には何も出さない**。

**再会（v11.5）**：体系ができるのは**新しい札を読む瞬間**で、一覧を見に行く行為にはその瞬間がない。だから一覧は見られない。概念タグの中に回数を足し（`[イールドカーブ 3]`。**行は増やさない**）、展開したら premise カードの中に1行だけ足す（`3回目 ・ 前は 9/9「…」`）。初出は何も出さない。`relation` の premise は2つあるので数字を出さない。

**今日の共通点（v11.5）**：2件以上が同じ**地層**に乗っていたら1行出す。概念で判定すると premise が1件1つで薄く空振りするので、数の少ない地層で見る。**共通点が無い日は何も言わない**（毎日出る飾りにしない）。展開の中だけで、朝の畳んだ行には出さない。

**概念タブの位置づけ（v11.5）**：「日々開く場所」ではなく**「たまに整理する場所」**。羅列のままで正しい。消すべきは一覧ではなく、一覧を毎日見るつもりだった前提のほう。一覧を残す理由は「探すため」ではなく、**統合・名前変更・上位概念・非表示の操作口が一覧しかないから**。検索は3つのタブそれぞれに置き、横断検索は作らない。

**上位概念（v11）**：`parent` を1つ、**2段まで**。手で付ける（生成には選ばせない）。統合のとき、消える側を親にしていた子は残る側へ付け替える。循環は祖先を辿って弾く。並び替えの4つ目「親でまとめる」でだけ効き、他はフラットのまま。

**世界の作り**：生成はアプリの中でやらない（撮る v9.0 と同じ）。1本のプロンプト（v19 から金融・経済と地政学・政治を1本で見る。米財務省の数字・5社の決算の書類・必ず見るものも入る）をコピーしてチャットに貼り、返ってきた JSON を貼り戻す。**取り込みは追記のみ**で、置き換えを一切しないので、読んだ出来事と書いた予測が取り込みで消える経路が無い。重複は `eventDate ±3日` の窓で `fact` のバイグラム類似（0.70）と URL 一致を見る（窓が月境を越えるので隣接月も読む）。`url` が空・日付が不正・未来の日付は落として、理由ごとに件数を出す。
一覧は **fact の1行だけ**で、`why` と `premise` はタップの向こう、数字・出典・URL はさらにその奥。**朝のステップを押すまで1件も消費されない**（1日の件数の上限 `WORLD_PER_DAY` は v18 A-1 で外した）。読まない日があってよく、14日を過ぎた未読は「古い」印が付いてまとめて捨てられる（自動では消さない）。
概念の表記ゆれは、(1) 正規化（中黒・長音・空白・全角半角）して完全一致するものを取り込み時に自動で吸収、(2) 近い名前を候補として出して1タップで統合、(3) 概念一覧から手で名前を直す（**既にある名前にすると統合になる**。タグの名前変更と同じ）。**バイグラムは「イールドカーブ」と「利回り曲線」のように文字が重ならない言い換えを拾えない**ので、本命は生成に `aka`（別名・訳語・英語名）を書かせて突き合わせることと、手での統合。引き当て・候補・統合・名前変更は概念と用語で1本のコード（`WORLD_STORES` にストアを渡す）。違うのは、統合のとき出来事側のどこを寄せるかだけ。用語の「片方が片方を含む」規則は最短4文字（概念は3）——`IMF` が `IMFC`（別組織）を拾う事故を避けるため。

**用語の注の出し方（v10.5）**：`fact` には注を入れない（一覧の1行はタップ＝展開なので、語に指が当たったときだけ展開しない操作になる）。注が開くのは展開後の `why` と `detail` の中、および premise の下の「用語」のチップ行だけ。本文の照合は**その出来事の `terms` に載っている語だけ**を見て、最長一致・重なりなし／英数字の略語は前後が英数字でないときだけ／日本語で2文字以下は本文では当てない（チップ行からは開ける）／1語につき最初の1回だけ、で事故を避ける。既知の用語も生成に `name` だけは書かせる（書かせないと、覚えさせた語ほど下線が消える）。

**「Claude に聞く」（v10.5）**：押すと4つの定型（やさしく説明／なぜ今なのか／日本にどう効くか／反対の見方は）が開き、素材を差し込んだ完成形がコピーされる。文面は `WORLD_ASK_PROMPTS` と `WORLD_ASK_COMMON`。**「反対の見方は」だけ既知の用語を渡す**（反論は前提を突くので、渡さないと既知の説明から始まる）。**「やさしく説明」は渡さない**（注を読んでも分からなかったときに押すボタンなので、既知として渡すと分からなかったものを飛ばされる）。概念・用語の詳細にも同じ仕組みで `WORLD_CONCEPT_ASK_PROMPTS` を置いてある。

**長さと形（v10.5.1）**：最初の版は見出し・箇条書きを禁じただけで長さを言わず、返ってきた文章が長すぎて読む気が失せた。この機能は隙間時間に読んで積み上げるためのものなので、6つとも `max` を持つ（出来事の4つは300字、「反対の見方は」だけ400字。概念は300／400）。数字は定数から出て、`worldAskTail()` が `- N字以内で書く。` の1行を差し込む。共通の縛りに「太字を使わない」「前置きを書かない、要約を繰り返さない」「最初から全部書かない、続きは自分で聞く」を足した。「なぜ今なのか」から「次にどこを見ていれば分かるか」を外したのは、その役割を `fork` が持っているため。「やさしく説明」の一言注は**5〜10字にとどめ、注も含めて字数に収める**ことにしてある（注だけで300字を使い切らないように）。

**用語の注と fork の書かせ方（v10.5.1）**：注は 20〜40字だと全部が上限に張り付き、1文に節が2つ入った（「〜が集まり、〜を作る」）。**20〜35字・1つの節で言い切る**に変え、それまでの良い例自身が二段構えだったので差し替えた（規則と例が食い違えばモデルは例に従う）。`fork` は3件とも「次の統計の数字がこの線を超えるか」になったので、**その出来事が言っていること自体が本当かを問う**形に変えた（出典が予想を述べていればその予想の当否、述べていなければ狙った効果が出るか、それも立たなければ null）。数字当ては当たっても外れても世界の見方が変わらない。

### 3.2 同期のしくみ

- 何かを変えると 0.8 秒後に同期。起動時・画面に戻ったとき・オンラインに戻ったときも同期。
- GitHub の Contents API をトークンで直接呼ぶ。読むときは `object` 形式で sha（版の印）を取り、1 MB を超えるファイルは `raw` 形式で本文を取る。書くときは sha 付きで送り、409（別の端末が先に書いた）なら取り直してマージしてもう一度。
- 全部の呼び出しは 30 秒でタイムアウト（`ghFetch`）。
- **言葉（月ファイル）**: `notes/index.json` を読む → 対象の月（端末で変えた月・他端末が変えた月・端末に無い月）を 1 つずつ読む → `mergeNoteSets`（id ごとに `updatedAt` の新しい方。削除は墓標の時刻と比べる）→ 変わっていれば書く → 索引を書く。端末側は保存のたびに月ごとの JSON を前回と比べ、変わった月だけ IndexedDB に書いて「未同期」にする。起動時は `notes:` で始まる全キーを 1 回のカーソル読みで取り込む。
- **記録（月ファイル）**: `journal/index.json` を読む → 今月・先月・端末で変えた月・他端末が変えた月を読む → `mergeJournalSets` → 書く → 索引を書く。端末のメモリには今月・先月と、記録タブや詳細で開いた月だけを載せる。
- **data.json**: ゴミ箱・下書き・使用量・方式フラグ。`mergeData`。
- **筋トレ**: 日ごとに `updatedAt` 新しい方＋墓標。種目カタログと筋肉対応は和集合。
- **瞑想（年ファイル）**: 言葉の月ファイルと同じ作り。`meditation/index.json` を読む → 端末で変えた年・他端末が変えた年・端末に無い年を読む → `mergeMedSets`（1 回ごとに `updatedAt` の新しい方＋墓標）→ 変わっていれば書く → 索引を書く。
- **散歩**: walk10000 と同じ「歩いた日数が多い方が勝つ」（ファイル単位）。
- **引くの順番（v8.2）**: 引くたびに端末のカウンタ（`kotoba_drawExploreN`）が 1 増える。6 の倍数の回は「眠っている言葉」（最後に見た日が古い方から 10%、最低 10 枚、★の有無は問わない）から。それ以外で 3 の倍数の回は「今月」モードで未★の言葉から。残りは重み付き（「今月」）か一様ランダム（「全部」）。相談の候補選びに「残したい」と眠りは入れない。朝の候補にだけ、眠っている言葉を 5 枚足す（選ぶのは AI）。
- 同期バーの文言は `renderSyncBar`。エラーは localStorage の `kotoba_lastSyncError` などに残り、設定の「最終同期エラー」に出る。

### 3.3 AI（Claude API）の使い方

- API キーは端末の localStorage にだけ置く（`kotoba_claudeApiKey`）。data.json には入れない。
- 機能ごとに呼び分け: 朝の言葉・相談（`callChatApi`）、自動関連づけ（`callClaudeApi`、Haiku）、一括入力（`callBulkDecomposeApi`）、問い（`callQuestionApi`：v8.4 から2回呼ぶ。1回目は材料から「種と場面」、2回目は場面と a/b だけから問い `callQuestionAskApi`。材料は2回目に渡さない）、筋肉対応（`generateMuscleMaps`）、読書メモ（`callReadingDecomposeApi`）。
- **撮るはアプリから AI を呼ばない**（v9.0）。カード・答えを壊す・展開・入りの候補は、撮る画面で「プロンプトをコピー」→ Claude のチャットに貼る → 返ってきた JSON をアプリに貼り戻す、という形。1 本の生成に 3 分かかって時間切れになり課金だけ残ったのが理由。週 2 回しか使わないので、チャットの方が確実で安い。
- 貼り戻しの検査はアプリ側にある。JSON として読めなければ入れない。URL は http/https 以外を空にする。枠は `stance`（support / break）から決め、モデルには枠を決めさせない。
- 検索料の算入（`WEB_SEARCH_USD`）はそのまま残してある。撮るからは呼ばなくなったが、他の機能が web 検索を使い始めたときに月上限へ乗る。
- 読書メモは「口述」と「本文の書き写し」のどちらでも受ける。書き写しなら AI が引く価値のある箇所を 1〜3 か所（各 200 字まで）選び、残りを周辺のメモにする。応答はコードフェンスや文字列内の改行があっても読めるように直してから JSON 解析する（`parseReadingReply`）。
- 相談・関連づけに渡す言葉: 言葉が上限（既定 200 枚、設定で変更）以下なら全件を渡してキャッシュ。超えたら「入力に近い言葉」を端末で選んで渡す（`selectCandidateNotes`）。
- 使用量は機能別に月ごと集計し、設定の月上限（USD）を超えると自動関連づけと朝の言葉が止まる。
